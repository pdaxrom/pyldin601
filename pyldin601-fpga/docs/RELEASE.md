# Кандидат первого релиза — 2026.10.17-rc1

Комплект объединяет текущие FPGA, два системных BIOS, UniDOS, NC/NCEDIT,
PAINT, UART, игры и инструменты UniCC/UniAS/UniLD/UniAR. Он готовится из
двух чистых копий исходников; бинарники и SD-образы сравниваются побайтно.
Автоматические проверки пройдены. 18 октября 2026 года пользователь
подтвердил успешное прохождение проверок на физической плате после
запуска набора BOARDCHK. Сценарии и порядок повторения приведены ниже.

## Состав

| Каталог/файл | Назначение |
|---|---|
| `sd.img` | Начальный образ для новой карты, 36 МиБ |
| `sd.json` | Разделы и хеши каждого файла внутри образа |
| `boot/` | LOADER.BIN, P601.ROM, P601A.ROM и начальные настройки |
| `fpga/` | Проверенный JED, отчёты MAP/TRACE и хеши входов трассировки |
| `fpga/source/` | Все зафиксированные входы Diamond, исходники RTL и происхождение CPU |
| `hg/` | Программы и ресурсы для HG; инструменты C находятся в CVM |
| `docs/` | Руководства по аппаратуре и программам |
| `host/hg`, `tools/`, `tests/` | Переносимые исходники HG, XMODEM, конвертера HAM8 и проверки хостовых утилит |
| `release.json` | Версия, ревизии исходников и контрольные суммы |
| `SHA256SUMS` | Проверка всего комплекта |

Образ содержит boot FAT16, исходный системный том A, программы на B и
распакованное старое ПО на C. `C:\CVM` содержит инструменты C и обе VM.
В B находятся все три файла NC и четыре файла PAINT; обновлять каждый
набор целиком. Настройки по умолчанию: 601, HD6303, 1 МГц, AUTO.

Хостовые инструменты собирать под свою ОС: `make -C host/hg` (libftdi1)
и `make -C tools` (libjpeg/libpng, результат tools/ham8conv). Проверки:
`make -C host/hg test` и `python3 tests/test_uart_xmodem_host.py`.
Для передачи файлов: `python3 tools/uart_xmodem.py --help`.

## Воспроизводимая сборка

Зафиксировать Git-ревизии основного репозитория и `hd6303-toolchain`.
Распаковать `git archive` каждого в новый каталог, сохраняя структуру
основного репозитория: `native`, `native-src`, `pyldin601/src` и
`pyldin601-fpga` должны оставаться соседями. Не копировать прежний build.
Пути ниже — примеры; заменить `/path/to/...` своими каталогами.

```sh
make -C /path/to/clean-toolchain all pyldin test
cd /path/to/clean-machine/pyldin601-fpga
export CVM_TOOLCHAIN=/path/to/clean-toolchain
export UNIAS="$CVM_TOOLCHAIN/unias"
make -f firmware/Makefile all extension
make fixtures cvm-apps image hg-host ham8conv game-objects
make test
python3 tests/run_native_firmware.py --toolchain "$CVM_TOOLCHAIN" --jobs 2
make test-native-assembly test-object-tools test-hg-object-tools
make test-c-modules test-unicc-selfhost
make test-ham-layers test-xonix test-turbo test-memory-bus
```

Цели тестов используют общие временные файлы: запускать один Make без
`-j`. Нативная сборка firmware использует собственные подкаталоги и
допускает `--jobs 2`. Подробности — [BUILD.md](BUILD.md).

Второй раз собрать firmware и toolchain в других новых каталогах.
Сравнить ROM, PGM, CMD, OBJ, LIB, сгенерированные FPGA ROM-таблицы и
итоговый образ; журнал ассемблера и абсолютные пути не являются бинарниками.

Упаковка использует уже собранный `build/sd.img` и обновляет его B/C.
`sources.json` содержит объекты `machine` и `toolchain`, каждый с полем
`commit`. Каталог evidence должен содержать JED/MAP/TRACE,
`routed-inputs.json` и `validated-build.json` соответствующей FPGA.

```sh
python3 tools/package_release.py --project /path/to/clean-machine/pyldin601-fpga \
  --sources /path/to/sources.json --fpga-evidence /path/to/evidence \
  --output /path/to/new-release
python3 tools/package_release.py --verify --output /path/to/new-release
P601_RELEASE_DIR=/path/to/new-release python3 -m unittest discover -s tests -p test_release.py -v
python3 tests/run_release_media.py --release /path/to/new-release
cd /path/to/new-release
shasum -a 256 -c SHA256SUMS
```

Если хотя бы один RTL/constraint/ROM-вход отличается от трассированного,
упаковщик отказывается использовать JED. Нужна новая сборка Diamond с
тем же контролем setup/hold и SRAM, описанным в BUILD.md.

Проверка готового носителя включает 8 сохранённых конфигураций загрузки
(модель × CPU × 1/8 МГц) и 12 функциональных запусков NC в разных
видеорежимах. Ещё четыре сценария проверяют совместную работу:
UniDOS → выбранная VM → NC → HELLO/CVMTEST → NC → оболочка,
с сохранением стека, памяти и намеренно резидентной VM.
Сам функциональный эмулятор приложений имеет фиксированное
расписание тактов; реальные частоты и SRAM-тайминги проверяются HDL.

## Проверка на плате

Матрица: 601/601А × MC6800/HD6303 × 1/8 МГц. Проверить текстовые и
поддерживаемые графические режимы; NC/PAINT — с доступным RAMMAN и при
исчерпании свободных банков. Игры, использующие инструкции HD6303,
проверять в HD6303; MC6800 проверяет корректный отказ таких программ.

1. Холодная загрузка, Setup, сохранение модели/CPU, warm/cold Reset.
2. DIR A/B/C, чтение/запись и повторное открытие тестового файла.
3. NC: стрелки через границы кэша, Ctrl+F1/F2, F-клавиши, запуск PGM,
   Ctrl+O → EXIT, фокус ввода и мышь.
4. F4: длинный файл, выделение/буфер, Undo/Redo, поиск/замена, сохранение
   и восстановление сессии после прерывания.
5. PAINT: пять форматов, кисть/геометрия/заливка, текст, палитра,
   выделение/масштаб, PCX/IFF, Undo/Redo и возврат видеорежима.
6. UART: ANSI, клавиатура, XMODEM туда/обратно с побайтной сверкой.
   115200 проверять отдельно при 8 МГц.
7. UniCC/UniAS/UniLD/UniAR: HELLO, объектные модули и библиотека,
   нативная сборка XONIX/ARKANOID; результаты сравнить с кроссовыми.
8. Игры и YPLAY: мышь не оставляет следов, звук/таймер работают,
   после выхода снова доступны диски и NC.

Для последовательной проверки подготовлен отдельный каталог `BOARDCHK`:
`CHECK.JOB` запускает проверки памяти/DMA/VM, сборку C и ASM из объектов
и библиотек, смешанные вызовы, затем NC/PAINT/UART. Между этапами есть
PAUSE; `AUTO.JOB` запускает только основные тесты, `HDCHECK.JOB` — игры
и звук для HD6303. В наборе 128 файлов для прокрутки и текст >200 КиБ.
Это отдельное дополнение в HG; исходный RC-образ не изменяется.

Подготовка набора: `python3 tools/prepare_board_check.py --output /new/BOARDCHK`
(нужны собранный `build/cvm` и `hd6303-toolchain`). Создаётся только новый
каталог. Для запуска через HG, заменив E: фактической буквой:

```text
E:
CD \BOARDCHK
HANDLES 16
E:\REL1017\CVM\RAMLOAD /CVM
CHECK E:\REL1017 E:\REL1017\CVM E:
```

Последний аргумент задаёт рабочий диск: после приложений JOB возвращается
в его `\BOARDCHK`. HANDLES и первую установку VM выполнять из основной
UniDOS до JOB. Для программ с SD: `CHECK B: C:\CVM E:`. Для проверки
записи на SD скопировать весь набор в новый `B:\BOARDCHK` и запускать
оттуда с последним аргументом `B:`. Ожидаемые результаты и ручные действия
описаны в `CHECK.TXT`. UniDOS JOB не имеет IF/ERRORLEVEL; END не означает
общий PASS. Вывод BIOS не перехватывается обычным `>`.

Проверка самого сценария на нативной UniDOS с резидентом HG и побайтным
сравнением результатов сборки:

```sh
python3 tests/run_board_job.py --release /path/to/release \
  --toolchain /path/to/hd6303-toolchain
```

Тест не заменяет визуальную и электрическую проверку платы.

## Установка

Для новой карты: проверить SHA256, записать `sd.img` на выбранное
устройство и прочитать назад для побайтного сравнения. Указания и
формат образа — [SD-CARD.md](SD-CARD.md) и [BUILD.md](BUILD.md).

Для общей используемой карты нужен её полный backup и обновление
именованных файлов с сохранением MBR/EBR, настроек и других разделов.
Начальный `sd.img` не является обновлением пользовательской карты.

При обновлении HG сохранять пользовательские рисунки, исходники,
XONIX.CFG и файлы рекордов; заменять только файлы этого комплекта,
предварительно сохранив их старые версии. После замены CVM выгрузить VM
через `RAMLOAD /U ZCODEVM` и загрузить `RAMLOAD /CVM` снова.

Первый запуск инструментов из основной UniDOS:

```text
C:
CD \CVM
HANDLES 16
RAMLOAD /CVM
HELLO
CVMTEST
```

## Ограничения кандидата

- Базовые 64 цвета HAM8 аппаратно RGB222. PAINT редактирует набор
  RGB666 цветов рисования в текущей сессии, а не эту аппаратную базу.
- Игры и часть графических/звуковых демонстраций требуют HD6303.
- Для большого нативного ассемблирования необходимы HANDLES 16 до
  загрузки VM. Длины строк Small-C — до 79 символов.
- Бинарный комплект воспроизводим; размещение Diamond не заявляется
  побайтно воспроизводимым. Используется JED с проверенным происхождением.

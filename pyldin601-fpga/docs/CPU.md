# Выбор набора команд MC6800 / HD6303

Первичный BIOS всегда работает на HD6303 ISA. В BIOS Setup (DEL) пункт
CPU HD6303 EXTENSION выбирает Y/N для работы компьютера после lock;
P601.SET сохраняет этот выбор вместе с моделью и частотой. Сводка настроек
ожидает DEL 10 секунд, без действительной конфигурации открывается меню.
[Запуск, сохранение и Reset](BOOT.md).

Выбор модели определяет видеоконтроллер и P601.ROM/P601A.ROM. Выбор CPU
определяет только набор команд; доступны все четыре сочетания. Новый
HD6303-компьютер с другой картой памяти, внутренними портами, таймерами
и SCI здесь не добавляется. Boot clock остаётся 4 МГц, runtime выбирается 1/2/4/8 МГц,
слоты CPU/видео и электрические тайминги SRAM прежние. Число микроциклов
этого ядра не воспроизводит таблицу тактов физического HD6303.

## Внешний сигнал и регистр

Новый вход `cpu6800.hd6303_en` по умолчанию равен 0. При 0 действует
MC6800, расширенные opcode не исполняются; прежнее поведение неизвестного
opcode как однобайтового NOP сохранено. При 1 разрешён документированный
набор HD6303R. Режим фиксируется при fetch каждой инструкции, поэтому
изменение входа между её opcode и операндами не меняет эту инструкцию.
До lock вход равен 1; после lock его источник — retained-триггер
`classic_boot_ports.hd6303_en`.

До первого байта конфигурации E6A3 запись E6A0 принимает 00–0F; bits 3–2 выбирают 1/2/4/8 МГц.
Нижние два бита сохраняют прежнее значение:

| E6A0 | Модель | CPU |
|---|---|---|
| 00 | 601 | MC6800 |
| 01 | 601A | MC6800 |
| 02 | 601 | HD6303 |
| 03 | 601A | HD6303 |

Статус E6A0: bit 7 locked, bit 6 error, bits 3–2 код начальной частоты,
bit 1 выбранная рабочая ISA, bit 0 model_a.
После начала конфигурации выбор изменить нельзя; A5 фиксирует ROM lock.
Обычный Reset сохраняет модель, ISA, ROM lock и содержимое SRAM. Cold
reset устанавливает начальные значения 601/MC6800, затем первичный BIOS
читает P601.SET и применяет конфигурацию. Байт 25 ROM-заголовка по-прежнему кодирует
только модель; ISA хранится отдельно в P601.SET/E6A0.
Редактор находится в первичных 8 КиБ EBR. SAVE AND BOOT создаёт
P601.SET на первом FAT16; формат текущего контейнера — P601BOOT v2.

## Команды и флаги

Поддержаны дополнения 6801: LSRD, ASLD, BRN, PULX, ABX, PSHX, MUL,
SUBD, ADDD, LDD, STD, direct JSR. Добавлены Hitachi XGDX, SLP, AIM,
OIM, EIM, TIM. Масочные команды имеют три байта: opcode, immediate mask,
unsigned direct address или indexed offset. AIM/OIM/EIM выполняют RMW;
TIM меняет только NZV, записи памяти нет. C/H/I сохраняются.

XGDX обменивает D и X без изменения CCR. MUL умножает беззнаковые A и B
в D; только C получает bit 7 результата, остальные флаги сохраняются.
Промежуточные сложения MUL больше не меняют CCR. В HD-режиме CPX использует
полное 16-битное вычитание с NZVC; классический режим сохраняет побайтный
CPX и прежний C. LSRD/ASLD меняют NZVC по 16-битному результату.

SLP сохраняет регистры, не создаёт стековый кадр и освобождает CPU bus.
Видео и периферия продолжают работать. Masked IRQ пробуждает к следующей
инструкции; unmasked IRQ или NMI создаёт обычный семибайтовый кадр и входит
в соответствующий обработчик. Reset также выводит из сна.

26 неопределённых opcode HD6303 вызывают TRAP через FFEE/FFEF, приоритет
выше NMI/IRQ. Сохраняются адрес ошибочного opcode и исходный CCR; затем
устанавливается I. Порядок стека совпадает с SWI/IRQ. Недокументированные
12/13 остаются неопределёнными. Address-error для внутренних регистров
реального чипа не применяется к карте памяти классического Пълдина.

Основание: оригинальная [Hitachi HD6303R data sheet](https://datasheets.chipdb.org/Hitachi/6303/hitachi-HD6303R.pdf),
таблицы команд/флагов 8–11, печатные страницы 65–68; SLP и error processing,
страницы 74–76. Арифметика дополнительно сверена с существующим HD6303
режимом `pyldin601/src/core/mc6800.c`. Этот эталон не реализует TRAP,
а его SLP/IRQ/reset имеют ограничения; для них применены проверки по
спецификации, без изменения исходного эмулятора.

## Предвыборка при IRQ/NMI

При принятии IRQ/NMI ядро может уже считать следующий opcode, не исполняя
его. Перед первым fetch обработчика `vect_lo_state` сбрасывает этот opcode
в NOP: иначе `fetch_state` применяет отложенный ALU/writeback от инструкции,
операнды которой не читались. В частности, предвыбранный LDX портил X на
входе в обработчик; LDS мог изменить SP уже после сохранения кадра.
Сбой проявился при нативной сборке Arkanoid в UniAS с работающим PAL IRQ.

`test-cpu-interrupts` проверяет регистры и все семь байтов сохранённого кадра
до первой инструкции обработчика, перебирая предвыбранные opcode для IRQ
и NMI. Тот же набор запускается с `tests/run_cpu_interrupts.py --hd`.
Неопределённые HD6303 opcode исключены из этого перебора, поскольку они
должны принять TRAP раньше IRQ/NMI; отдельные проверки TRAP сохранены.

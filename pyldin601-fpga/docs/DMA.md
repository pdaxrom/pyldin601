# Общий DMA и блиттер

Один аппаратный движок обслуживает прежние графические команды E651 и
новый интерфейс физического DMA E6E0–E6E3. Второго конкурирующего блиттера
нет. CPU сохраняет свои слоты SRAM на 1/2/4/8 МГц, HOLD остаётся нулём.
Выборка строк native/indexed/HAM8 имеет приоритет; DMA использует оставшуюся
полосу. Время переноса зависит от частоты CPU и режима вывода.

## Регистры

| Адрес | Чтение | Запись |
|---|---|---|
| E6E0 | bit7 BUSY, bit4 ERROR, bits3:0 ABI=1; bits6:5=0 | Нет действия |
| E6E1 | 44h (`D`) | Команда: 1 FILL, 2 COPY, 6 KEYED COPY |
| E6E2 | Индекс параметра, 0..31 | Индекс параметра, младшие пять бит |
| E6E3 | Текущий параметр, FF для индексов 19..31 | Параметр; индекс +1, после 18 → 0 |

Чтение DATA не меняет индекс. Это позволяет использовать инструкции CLR
и другие RMW без скрытого пропуска параметров. Индексы 19..31 не содержат
параметров. Запись COMMAND принимается только при общем BUSY=0; параметры
также заморожены до завершения. INDEX доступен всегда. Пока BUSY=1, новые
команды и записи параметров игнорируются, очереди нет.

BUSY устанавливается в CPU-домене при записи команды, до перехода в 96 МГц.
Он снимается после последней подтверждённой записи SRAM/палитры и обратной
синхронизации. E650.bit7 также включает новый DMA; E6E0.bit7 включает
старые задания и ожидание FLIP. ERROR каждого интерфейса относится к его
последней принятой команде: E650 для E651, E6E0 для E6E1. Следующая команда
того же интерфейса обновляет результат; запись режима E650 ошибок не стирает.

## Параметры

Все многобайтные поля передаются **младшим байтом первым**.

| Индекс | Размер | Поле |
|---|---:|---|
| 0..2 | 3 | SRC, физический byte address |
| 3..5 | 3 | DST, физический byte address |
| 6..8 | 3 | WIDTH, байт в строке, 0..200000h |
| 9..10 | 2 | HEIGHT, строк, 0..65535 |
| 11..13 | 3 | SRC STRIDE, расстояние между началами строк |
| 14..16 | 3 | DST STRIDE, расстояние между началами строк |
| 17 | 1 | MODE: bit0 source=порт, bit1 destination=порт, bit2 SRC fixed, bit3 DST fixed |
| 18 | 1 | VALUE: байт заливки либо прозрачный ключ |

Неиспользуемые старшие биты адресов/stride и MODE.bits7:4 должны быть нулём.
Адреса и stride — 0..1FFFFFh. При HEIGHT>1 шаг обычного увеличиваемого
адреса обязан быть не меньше WIDTH. Fixed означает один адрес для всего
задания; stride этого endpoint не используется. Порт подразумевает fixed.
Два периферийных endpoint одновременно не поддерживаются.

Линейный перенос: HEIGHT=1, WIDTH=длина, оба stride=0. Он пересекает границы
8-КиБ банков и 64-КиБ GPU-страниц без остановки. Прямоугольник задаётся
WIDTH/HEIGHT и двумя положительными stride. FILL не читает источник;
KEYED COPY не записывает байты, совпадающие с VALUE.

RAM→RAM автоматически выбирает обратный обход, если DST>SRC. Линейное
копирование и перекрывающиеся прямоугольники с одинаковым stride работают
как memmove. Для пересекающихся прямоугольников с разными stride общий
снимок источника не гарантируется: приложение должно использовать временный
буфер. Это байтовый движок; маски краевых битов упакованных пикселей
формирует программа.

## Физическая память и проверки

SRC/DST не проходят CPU MMU и не зависят от E6F0/E6F1. Карта всех 2 МиБ
приведена в [MEMORY.md](MEMORY.md). Чтение ROM/font допускается, записи в
010000..0217FF блокируются проверкой задания. DMA не выделяет банки:
приложение использует только принадлежащие ему RAMMAN/GPU/обычные буферы.

Каждая строка проверяется **до первого переноса**, включая последний адрес,
переполнение и защищённые области. Ошибка поздней строки не изменяет даже
первую строку. Проверка идёт небольшим конвейером без аппаратного умножителя.
WIDTH=0 или HEIGHT=0 не выполняет переносов; общие недопустимые поля и
код команды всё равно могут дать ERROR. Значения не оборачиваются через
конец SRAM. Адрес E6xx в режиме RAM означает SRAM под портами.

Конфигурация нескольких регистров и запуск должны быть атомарны относительно
других пользователей DMA. IRQ продолжают обслуживаться во время переноса,
но обработчики и основной код должны согласовывать владение общим движком.
Пока BUSY=1, нельзя менять/освобождать исходный буфер или читать/переписывать
результат. Живые стек, код, PCB и системные данные не являются буферами DMA.

## Палитра

Единственный периферийный endpoint ABI1 — CPU-порт E65E. В MODE=2 DMA
читает SRAM и записывает шестибитные отсчёты палитры; MODE=1 читает палитру
и пишет SRAM. Для FILL порт тоже может быть назначением. Неверный порт
даёт ERROR до любых записей. Другие устройства могут позднее добавить
свои готовность и подтверждение, не меняя модель SRC/DST.

Перед запуском CPU задаёт адрес палитры через E652/E65D. DMA сам продвигает
13-битный адрес по модулю 8192 при чтении и записи. CPU-семантика чтения
E65E сохранена: само CPU-чтение адрес не увеличивает. DMA-чтение не меняет
текущий режим readback E65F.bit0. Верхние два бита SRAM при записи палитры
отбрасываются; при чтении возвращаются нулём.

Каждый байт подтверждается портом на 24 МГц; данные не теряются на переходе
частоты. Пока задание использует палитру, CPU-записи E652/E65D/E65E/E65F
игнорируются, защищая её общий адрес. Режим графики E650 остаётся доступен.
Видимое изменение палитры может приходиться на середину поля; для атомарной
визуальной смены приложение выбирает подходящий момент или отключает показ.

## BIOS

Постоянный BIOS обеих моделей регистрирует INT E8 до сканирования ROM:
обычная RAM/банки, memmove и полный PAL save/restore выполняются общим DMA.
Код помещается по F640 в основном BIOS; отдельная обёртка SDPARTS не нужна.
Обработчик написан на MC6800, поэтому работает на обеих ISA. Дескриптор
копируется на стек, регистры настраиваются под коротким SEI, ожидание
завершения — с исходной маской прерываний. Постоянной рабочей RAM нет.
Код E8 с INFO и частным входом занимает 451 байт основного BIOS; до фиксированного INT20 остаётся 119 байт.

Резервного CPU-копирования и совместимости с FPGA без DMA нет: BIOS и FPGA
обновляются комплектом. Частная FAT-операция 4 пока сохраняет штатный
фиксированный gateway ядра через INT2D; это отдельная операция для его
512-байтовых системных буферов, а не fallback публичного DMA.

## Проверки

- `make test-dma`: физические границы, memmove/stride/fixed/key/fill, отсутствие
  частичных записей, полный PAL roundtrip и его владение, CPU/видео/reset.
- `make test-dma-skew`: тот же сценарий с другой фазой PLL и перекосом SRAM.
- `make test-dma-bios`: собранные ROM/UniDOS, E8 и жизненный цикл GAMEBIOS
  с независимой моделью DMA, обе модели и обе ISA; полную графическую
  регрессию проверяет `make test-gamebios` с той же моделью.
- `make test-dma-bios-rtl`: production VHDL CPU, реальные BIOS/ROM, общий
  движок и SRAM-10, обе модели/ISA и четыре частоты; вложенное копирование
  из музыкального IRQ, сохранение/восстановление PAL и маска SEI во время
  автономного переноса (проверяется CCR реального CPU-ядра).
- `make test-gfx test-ham-layers`: прежние команды, keyed overlap и HAM8
  с одновременными CPU/блиттером и проверкой пикселей.

Физическая плата требует новый JED и соответствующие BIOS для DMA.
HDL и timing отчёты не заменяют проверку платы.

После установки согласованного JED и P601.ROM/P601A.ROM запустить
`DMATEST.PGM` из HG. Утилита выделяет два собственных банка RAMMAN,
проверяет 8-КиБ FILL/COPY и PAL, восстанавливает палитру и освобождает банки.
Ожидаемая строка: `PASS: DMA 8K copy/fill, PAL restored.` Проверку повторить
на 1/2/4/8 МГц, затем проверить игры и возврат в UniDOS.

# Регистры FPGA-Пълдина 601/601А

Справочник текущей реализации: graphics v6, raw PS/2 v2, P601BOOT v2.
Адреса приведены в пространстве CPU, числа с `$` шестнадцатеричные.
Все обращения к MMIO **байтовые**; последовательность отдельных байтов
важна. Источник семантики — RTL, а не историческая схема Пълдина.

| `$E629/$E62B` | Штатное видео/Кир–Лат, PAL-тик/бипер | Чтение/запись |
| `$E644..E647` | UART FTDI B: ID, скорость, control/status, data | Чтение/запись |

| `$E6B0..E6B7` | Raw PS/2 FIFO, захват и IRQ | Чтение/управление |

Параметры блиттера, физический адрес bootstrap и регистры AY используют
младший байт первым. Музыкальный период и Q16 divider — старший первым.
ROM-дескрипторы INT E0/E6 используют BE16, контейнер P601BOOT — LE32.
Не переносить порядок байтов между этими интерфейсами по аналогии.
Адреса вне описанных блоков не являются свободными регистрами расширения.

## Конфигурация и загрузочный порт `$E6A0..E6AF`

Блок управляет выбором модели/ISA/начальной частоты, режимом адресации SD,
выбором загрузочного FAT12 и записью ROM в физическую SRAM. После успешного
commit `LOCKED=1`. В runtime декодируются только **чтения E6A0, E6A2, E6AE**;
остальные адреса больше не являются bootstrap-портами. Через них нельзя
менять компьютер или дописывать ROM после загрузки.

| Адрес | Чтение | Запись до lock | Начальное значение после cold reset |
|---|---|---|---|
| E6A0 | bit7 LOCKED, bit6 ERROR, bits3:2 начальная частота, bit1 ISA, bit0 модель; bits5:4=0 | 00..0F выбирает конфигурацию до начала E6A3; A5 выполняет commit | 00 |
| E6A1 | Последний debug/STEP | Любой байт этапа/диагностики | 00 |
| E6A2 | bit0 SD block addressing; остальные 0 | **bit6** задаёт SDHC/block addressing | 00 |
| E6A3 | FF | Следующий байт 64-байтовой конфигурации из ROM-заголовка | Индекс загрузки заголовка 0 |
| E6A4 | FF | Физический адрес SRAM bits7:0 | Адрес 000000 |
| E6A5 | FF | Адрес bits15:8 | — |
| E6A6 | FF | Адрес bits23:16 | — |
| E6A7 | FF | Начать запись байта SRAM по текущему адресу | Нет запроса |
| E6A8 | bit7 ERROR, bit0 BUSY/pending; остальные 0 | Нет действия | 00 |
| E6A9 | FF | Добавить байт в CRC32 | Аккумулятор FFFFFFFF |
| E6AA | FF | Любое значение сбрасывает CRC32 в FFFFFFFF | — |
| E6AB | Последний законченный байт физического чтения | Любое значение начинает одно чтение SRAM | Read data=00 |
| E6AC | Финальный CRC32 bits7:0 | Нет действия | 00 |
| E6AD | Финальный CRC32 bits15:8 | Нет действия | 00 |
| E6AE | До lock CRC32 bits23:16; после lock выбор BOOT PARTITION | AUTO=0 либо номер 1..36 **до первого E6A3** | AUTO=0 |
| E6AF | Финальный CRC32 bits31:24 | Нет действия | 00 |

E6A0: модель 0=601, 1=601А; ISA 0=MC6800, 1=HD6303; код частоты
0/1/2/3=1/2/4/8 МГц. Например, `$0F` выбирает 601А/HD6303/8 МГц.
Это настройка **рабочего** CPU. Пока bootstrap активен, CPU всегда имеет
HD6303 ISA и работает на 4 МГц. E6A0 сообщает сохранённую начальную
частоту; короткое нажатие Reset меняет текущую скорость, но этот код
не обновляет. Текущая скорость видна на двухразрядном индикаторе.

Выбор E6A0 допустим лишь при индексе E6A3=0 и отсутствии pending SRAM.
E6AE дополнительно требует значение <=36. Заголовок поступает ровно
64 записями E6A3; чтение порта не перемещает индекс. После 64 байтов
лишняя запись выставляет ERROR. Проверяются сигнатура `P601BOOT`,
версия 2, фиксированные ROM base/size, резервные байты 0..63 и модель.
Несовпадение этих байтов запоминается как header_bad; commit отвергает
его. Expected payload CRC берётся из байтов 20..23 заголовка.

### Запись, чтение и автоинкремент SRAM

1. Дождаться E6A8.bit0=0, проверить bit7=0.
2. Записать E6A4/E6A5/E6A6, low/middle/high.
3. Для записи отправить байт в E6A7; для чтения **записать** любой байт
   в E6AB. Операция становится pending.
4. Дождаться BUSY=0 и проверить ERROR. При чтении прочитать E6AB.
5. Адрес увеличивается на 1 **при завершении** физического запроса.

Чтение E6AB само по себе ничего не запускает и не увеличивает адрес.
Попытка менять адрес или отправить следующий запрос при pending ставит
ERROR. Начальный адрес должен быть меньше `$200000`; адрес `$200000`
не оборачивается в начало SRAM, следующий запрос отвергается.
Ожидания в собственном загрузчике должны иметь конечный таймаут.

CRC32: отражённый polynomial `$EDB88320`, initial `$FFFFFFFF`, итог
`accumulator XOR $FFFFFFFF`. E6A9 обрабатывает только переданный байт:
ни E6A7, ни E6AB автоматически не добавляют данные к CRC. E6AC..E6AF
читаются low first; E6AE меняет смысл после lock.

### Commit и защита ROM

Запись A5 в E6A0 успешна только одновременно при:

- ERROR=0 и отсутствии pending SRAM;
- SPI завершён и SD CS высокий;
- полученных 64 байтах E6A3, header_bad=0;
- текущем итоговом CRC32, равном expected payload CRC.

При успехе LOCKED=1; bootstrap-ROM перестаёт перекрывать D000/F000,
применяются выбранные модель и ISA. Код commit должен исполняться вне
исчезающего ROM, поэтому штатный handoff использует RAM-трамплин E000.
При отказе LOCKED остаётся 0 и выставляется ERROR. Специального регистра
очистки ERROR нет; штатный путь восстановления — Reset/новая загрузка.
Cold reset обнуляет конфигурацию/lock; warm reset сохраняет уже закрытый
lock и выбранный компьютер. Полный порядок — [BOOT.md](BOOT.md).

После lock контроллер физической памяти защищает `$010000..$0217FF`
(ROM-страницы, BIOS, шрифт). CPU-запись под виртуальным ROM по-прежнему
идёт в базовую RAM; это не запись в защищённый физический ROM.

## Графика и палитра `$E650..E65F`

| Адрес | Чтение | Запись |
|---|---|---|
| E650 | bit7 BUSY, bit5 UNDERRUN, bit4 ERROR, bits3:0 режим | bit0 ENABLE; bits2:1 FORMAT=3 HAM8, остальные indexed; bit3 слой только при HAM8 |
| E651 | Последняя команда | 1 FILL, 2 COPY, 3 FLIP, 4 WRITE BYTE, 5 READ BYTE, 6 keyed COPY |
| E652 | Текущая front page, 0..15 | PAL-адрес bits7:0, **не front page** |
| E653 | Цвет/ключ/данные | Цвет FILL, байт WRITE, прозрачный ключ команды 6 |
| E654 | Source page | 0..15, источник COPY/READ; фиксируется как фон при E650=15 |
| E655 | Destination page | 0..15, назначение FILL/COPY/WRITE либо новая front page для FLIP |
| E656/E657 | Source offset low/high | Смещение источника LE16 |
| E658/E659 | Destination offset low/high | Смещение назначения LE16 |
| E65A/E65B | Width low / high bit0 | Ширина 1..320; E65B использует только bit0 |
| E65C | Height | Высота 1..200 |
| E65D | Последний READ BYTE | PAL-адрес bits12:8 |
| E65E | 47h (`G`), либо текущий PAL-отсчёт при readback | PAL-отсчёт bits5:0, затем адрес +1 |
| E65F | Hardware revision=6 | bit0 readback, bit1 PAL-адрес +1 |

После CPU reset: графика выключена, FORMAT/layer=0, front page=0,
параметры и read byte=0. SRAM-картинки не очищаются reset самого блока.
PAL readback/address сбрасываются; **палитра сохраняется** при CPU reset.
Её начальные RGB332 отсчёты загружаются при конфигурации FPGA.

Режимы: E650=0 — native, 1 — indexed, 7 — обычный HAM8, 15 — HAM8-фон
с RGB222 передним планом. При E650=15 текущий E654 фиксируется отдельно;
дальнейшие COPY-параметры не меняют источник показа. Чтобы сменить фон,
снова записать E654, затем E650=15. GB_MODE/INT E0 принимают только 0/1/7.

Сначала ждать BUSY=0, затем записать параметры и E651. Принятая команда
асинхронна; проверить завершение и ERROR. Пока BUSY=1, параметры/новая
команда игнорируются; E650 и порт палитры работают независимо. ERROR
относится к последней команде, UNDERRUN сохраняется до выключения графики
или reset. Не пытаться очищать эти биты записью в E650.

Страница — 65536 байт; кадр — первые 64000, stride=320. FILL/COPY/keyed
COPY проверяют размеры и последний адрес <64000; границу x+width<=320
проверяет программа. COPY с перекрытием одной страницы выбирает направление.
WRITE/READ BYTE используют страницу и смещение, игнорируя width/height.
FLIP завершается на следующем PAL VBL, без переключения посреди поля.

PAL-порт адресует 8192 шестибитных отсчёта: `index*32+phase`.
E652/E65D задают 13-битный адрес, увеличение по модулю 8192.
Для readback записать E65F=1, прочитать E65E; для следующего адреса
записать E65F=3. Чтение E65E адрес **не** увеличивает. Запись E65E
увеличивает его автоматически. E65F=0 возвращает чтение идентификатора.
После смены адреса требуется один 24-МГц такт синхронного чтения EBR;
обычные байтовые циклы CPU 1..8 МГц дают этот интервал.
HAM-таблица занимает индексы 0..191; меню может использовать 240..245.
[Форматы и композиция](HAM.md), [программирование](PROGRAMMING.md).

## AY-регистры `$E610..E61F`

| Регистры | Значение и используемые биты |
|---|---|
| R0/R1, R2/R3, R4/R5 | Tone A/B/C: младшие 8 + старшие 4 бита периода |
| R6 | Noise period, bits4:0 |
| R7 | bit0..2 disable tone A/B/C, bit3..5 disable noise; bit6/7 GPIO direction |
| R8/R9/R10 | Volume A/B/C bits3:0, bit4 envelope |
| R11/R12 | Envelope period LE16 |
| R13 | Shape bits3:0; **каждая** запись повторно запускает envelope |
| R14/R15 | GPIO latch; неподключённый input читается FF |

Период tone=0 трактуется как 1; `frequency=master/(16*period)`.
Reset отключает звук и очищает регистры/счётчики AY. Оба аудиовыхода
несут одинаковую моно-сумму AY и штатного бипера. Значение R13=FF
означает «не записывать» только для ROM FRAME API: прямой MMIO
записью FF запустит shape 0F. [Подробности генераторов](AY.md).

## Аудиотаймер и делитель `$E690..E69F`

| Адрес | Чтение | Запись |
|---|---|---|
| E690 | bit7 pending, bit6 overrun, bit5 divider busy, bit4 bad config, bit0 enable | bit0 enable, bit1 ACK, bit2 restart, bit3 clear bad config |
| E691 | 59h (`Y`) | Нет действия |
| E692..E695 | Committed period BE32 | Period shadow BE32 |
| E696 | 00 | bit0 commit периода |
| E697 | Текущий counter bits31:24; чтение фиксирует snapshot | Нет действия |
| E698..E69A | Остальные байты snapshot, high first | Нет действия |
| E69B..E69E | Committed Q16 divider BE32 | Divider shadow BE32 |
| E69F | bit0 divider busy | bit0 commit делителя |

Reset: enable/pending/overrun/bad config/busy=0; counter/snapshot=0;
period/shadow=480000; divider/shadow=$01800000. Все 32-битные записи
сначала идут в shadow; частичная запись не применяется до commit.
Перед commit записать все четыре байта, а не полагаться на прежний shadow.

Таймер работает на **24 МГц**, считает 0..period−1, повторяется и
выставляет pending. IRQ=`enable && pending`; он держится до ACK.
Новое событие при уже pending ставит overrun. ACK, совпавший с compare,
сохраняет **новое** pending; ACK одновременно очищает старый overrun.
Stop (`enable=0`), restart и успешный period commit обнуляют counter,
pending/overrun. Нулевой period отвергается с bad config без замены периода.
Сам аппаратный период — любой ненулевой uint32; GAMEBIOS ограничивает
его 240000..24000000, то есть 100..1 Гц.

Управление не является отдельными SET/CLEAR битами: при ACK надо также
передать enable=1, иначе запись 02 остановит таймер. Для ACK работающего
таймера использовать 03; для старта с restart — 05. Запись 00 останавливает.
Снимок читать E697→E698→E699→E69A, чтобы получить согласованное BE32.

`masterHz=768000000*65536/divider`, интервал шага AY:
`divider/65536` тактов 96 МГц. Дробный накопитель чередует целое и целое+1;
применение происходит на границе звукового шага через toggle/ACK.
После E69F=1 ждать busy=0; проверять bad config в E690.
Commit при busy или вне диапазона `$01800000..$FFFEFFFF` отвергается,
сохраняя прежний делитель и выставляя bad config.

| AY master | Divider Q16 |
|---|---|
| 2000000 Гц | 01800000h |
| 1000000 Гц | 03000000h |
| 1773400 Гц | 01B11101h |
| 1789773 Гц | 01AD1ACDh |

Музыкальный источник BIOS вызывает INT E4 и подтверждает его отдельно
от PAL. При GAMEBIOS E4 принадлежит ему; приложение пополняет очередь
в основном цикле. При ручном управлении сохранить/восстановить вектор,
period/divider и AY. [Очередь и эффекты](GAMEBIOS.md).

## SPI SD `$E660..E664`

| Адрес | Чтение | Запись |
|---|---|---|
| E660 | RX high | TX high, отмечает high_pending |
| E661 | RX low/последний байт | TX low и запуск передачи |
| E662 | bit7 READY; bits5:4 и1:0 control; остальные 0 | Control, маска 33h |
| E663 | Divider | Prescaler 0..255 |
| E664 | POUT latch | bits1:0 latch, без подключённого внешнего GPIO |

Reset: control=23h (CS high, байтовый режим), divider=29,
POUT=03h, RX/TX high/low=FFh. READY означает enabled и отсутствие
активной передачи; reset удерживается до готовности блока.
Control.bit1 — физический SD CS: 0 выбран, 1 отпущен. Bit4 включает
16-битный режим: сначала E660, потом E661; high передаётся первым,
затем low, READY после обоих. Без подготовленного high передача в word
mode не начинается. В byte mode запись E661 запускает один байт.
Bits0/5 сохраняются как совместимые control-биты; SPI mode 0 фиксирован.

Все записи принимаются только когда блок enabled и не busy. Чтение
RX не запускает передачу и не выбирает карту. Для получения байта
отправить FF в E661, дождаться READY и прочитать E661. CS принадлежит
программе и не переключается автоматически между байтами.
MSB передаётся первым, sample на rising SCK, MOSI меняется на falling SCK.
`SCK=24000000/(2*(divider+1))`: 29→400 кГц, 1→6 МГц.
Пока SD инициализируется, использовать 400 кГц; штатный BIOS после
инициализации выбирает 6 МГц. [Протокол загрузки](BOOT.md).

## HG `$E670..E673`

| Адрес | Чтение | Запись |
|---|---|---|
| E670 | Старший по очереди RX-байт; извлекает его, FF при пустом RX | Добавить байт в TX, если есть место |
| E671 | bit0 RX ready, bit1 TX room, bit2 SELECT, bit3 TX empty, bit4 v2 capable=1, bit6 RX overflow, bit7 TX underflow | Нет действия |
| E672 | Control bits5:0 | bit0 request/TDO enable, bit1 RX enable, bit2 TX enable, bit3 packet mode, bit4 credit inhibit, bit5 final TX, bit7 flush |
| E673 | 48h (`H`) | Нет действия |

Reset обнуляет FIFO/ошибки/control, освобождает TDO. RX/TX по 64 байта;
HG не обращается к SRAM сам — копирует CPU. Flush принимается только
при прежних request=0 и SELECT=0. Поэтому сначала записать 00 и дождаться
SELECT=0, затем 80; одной записью 80 из активного request очищение не
гарантируется. Чтение STATUS не очищает overflow/underflow.

FTDI/MPSSE использует mode 0, **LSB first**, TCK<=1 МГц; порядок битов
отличается от SD. Packet mode выдаёт кредиты до 32 байт. RX credit есть
при RX count<=32; TX credit при TX count>=32, либо для непустого
короткого хвоста при final TX. Credit inhibit блокирует выдачу кредита
в фазе статуса. При смене направления дождаться TX empty.
В v2 при SELECT=0 можно тактировать статус без изменения FIFO:
bit7 request, bit6 ошибка RX/TX, bit5 final TX, bit4 inhibit,
bit3 packet, bit2 TX enable, bit1 RX enable, bit0 request/credit.
[Использование сервера](HOSTLINK.md).

## Raw PS/2 `$E6B0..E6B7`

| Адрес | Чтение | Запись |
|---|---|---|
| E6B0 | 52h (`R`) | Нет действия |
| E6B1 | bit7 overflow, bit6 capture, bit5 full, bit3 parser reset, bit2 native consumed, bit0 available; bits4/1=0 | Нет действия |
| E6B2 | Прочитать и удалить один raw Set 2 байт; FF если пусто | Нет действия |
| E6B3 | Количество raw байтов, 0..64 | Импульсные команды, таблица ниже |
| E6B4 | Interface revision=2 | Нет действия |
| E6B5..E6B7 | FF | Нет действия |

| E6B3 bit | Команда |
|---:|---|
| 0 | Очистить FIFO |
| 1 | Очистить overflow |
| 2 | Включить эксклюзивный capture |
| 3 | Освободить capture |
| 4 | Включить raw IRQ |
| 5 | Подтвердить parser reset |
| 6 | Выключить raw IRQ |

Reset: FIFO пуст, capture/overflow/IRQ enable/parser reset=0;
native consumed=1 после сброса старого клавиатурного latch.
IRQ level активен, если IRQ enabled, capture=0 и есть байты, overflow
или parser reset. Чтение DATA уменьшает FIFO; одного чтения STATUS
недостаточно для снятия IRQ. Overflow очищается командой; parser reset
передаётся программе для сброса E0/F0/модификаторов после смены владельца.
Его надо подтверждать bit5, иначе IRQ остаётся активен.

Capture подавляет raw IRQ и старые клавиатурные IRQ/автоповтор/клики,
но приёмник/FIFO продолжают работать; игра читает DATA сама. PAL и музыка
не подавляются. E650 с bits2:0=0 автоматически освобождает capture,
как и reset. Освобождение/захват выставляет parser reset при смене
владельца. Новое переполнение имеет приоритет над одновременной очисткой.
Одновременное чтение освобождает место даже в полном FIFO.
SDK использует capture+flush+clear=07 и release+flush+clear=0B.
Приложениям предпочтительны sdk_input_reset/input/close, а не свой парсер.
[Программный мост в BIOS](KEYBOARD.md).

## Мышь, указатель и UART

Полное описание `$E6B8..E6BF` и `$E644..E647`, формата указателя,

## Общий DMA `$E6E0..E6E3`

E6E0: bit7 BUSY, bit4 ERROR, младшие четыре бита ABI=1.
E6E1: чтение 44h (`D`), запись 1 FILL / 2 COPY / 6 KEYED COPY.
E6E2: индекс параметра; E6E3: данные, индекс увеличивается только при записи.
Физические SRC/DST и WIDTH — LE24, HEIGHT — LE16, два stride — LE24,
затем MODE и VALUE: всего 19 байт. MODE: bit0 source port, bit1 destination
port, bit2 source fixed, bit3 destination fixed. Единственный порт ABI1 —
E65E, с автоматическим продвижением палитры и подтверждением каждого байта.

Движок общий с E651; BUSY обоих интерфейсов учитывает задания другого.
Старые графические команды/палитра сохраняют прежнюю адресацию и ABI.
[Поля, ограничения перекрытия, владение, reset и BIOS](DMA.md).

## Страничное окно `$E6F0..E6F3`

| Адрес | Чтение | Запись / reset |
|---|---|---|
| E6F0 | Полный записанный байт страницы | Reset=00, адресацию определяют bits3:0 |
| E6F1 | Группа 0..18 | Записи 0..18, остальные игнорируются; reset=0 |
| E6F2 | 52h (`R`) | Read-only |
| E6F3 | 111, количество 8-КиБ RAM-банков | Read-only |

Окно C000..DFFF: страницы 0/7 — базовая RAM, 1..6 — расширенная RAM,
8..F — ROM overlay. E6F1 действует только на RAM 1..6 в runtime;
в bootstrap это окно не активировано. Для физического банка n=0..110:
`group=n/6`, `page=1+n%6`, адрес `$022000+n*$2000+(CPU-$C000)`.
В группе 18 только страницы 1..3 валидны; 4..6 читаются FF, записи
блокируются и не попадают в видеопамять. RAM содержимое reset регистров
не стирает. BIOS IRQ/NMI/SWI сохраняет оба регистра на своём стеке.
Новые программы выделяют банки через RAMMAN, а не захватывают их сами.
[Карта и соглашение вызовов](MEMORY.md).

## Изменённые порты совместимости

E628 — код клавиши: запись загружает software latch; чтение снимает
pending/строб и отмечает consumed. E62A и E62E — алиасы статуса/управления:
bit7 читает строб, запись bit7 выставляет его только для свежего
непрочитанного кода !=FF; bit3 управляет Caps indication. Остальные
постоянные status-биты сохраняют ожидаемую BIOS маску 37h. Чтение статуса
может переключать строб свежей клавиши согласно старому handshake.
FPGABIOS пишет E628, затем строб E62A, и BIOS вызывает старый INT09.
При capture DATA=FF, строб/IRQ подавлены.

E629 сохраняет штатные видео/LAT–CYR биты, reset=01; модель компьютера
выбирается E6A0, а не E629. E62B: чтение возвращает 37h, bit7 PAL pending,
bit3 beeper; **чтение подтверждает PAL тик**. Запись меняет только bit3
beeper. PAL событие на том же такте, что ACK, сохраняется новым pending.
Музыкальный ACK E690 и raw ACK/FIFO независимы от PAL.

E680..E683 остаются заглушками прежнего RAM-диска: чтение 0, запись
ничего не выполняет. E632 читает 80h, E634/E635 — 0. Контроллер i8272
и ROM/RAM-диски не реализованы. Штатные MC6845-порты E600/E601 и их
алиасы E604/E605 сохраняются; они не заменяют новый графический блок.

E6D0 после удаления i8272 отображается в обычную SRAM. После монтирования
SD системный BIOS записывает туда 80h как признак наличия дисков для
старой дисковой оболочки. Без этого она обнуляет заголовки A/B. Аппаратного
регистра статуса, FIFO команд или дискетного протокола за этим байтом нет.
INT17 не выполняет ввод-вывод; для дисков используются INT40 и INT E1/E2.

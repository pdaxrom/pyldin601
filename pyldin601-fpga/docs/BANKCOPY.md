# INT E8: копирование памяти из постоянного BIOS

Оба BIOS, 601 и 601А, содержат сервис по F640, собранный UniAS из
`firmware/memory/BANKCOPY.INC`. Системный BIOS сам регистрирует INT E8
со страницей 0 при каждом Reset, до сканирования ROM-расширений.
Регистрация использует метку `bank_copy` в `BIOSBOOT.INC`;
DIRECTSD/FPGABIOS, RAMMAN и GAMEBIOS для неё не нужны.
Код всегда доступен в F000–FFFF, включая момент переключения
окна C000–DFFF. Процедуры в RAM и постоянных рабочих переменных нет.

Перед использованием проверить вектор через INT2E: A=E8, X≠0 означает
присутствие. B=0 здесь означает постоянное ПЗУ, поэтому проверять только
B нельзя. Затем INT E8 A=0 возвращает ABI 1, B=7 и X=8192.
INFO доступен на MC6800; копирование требует HD6303.
Приватная операция 4 используется только системными FAT/файловыми кэшами: фиксированный дескриптор
EAD0 задаёт перенос 512 байт E700/E000↔банковое окно через штатный INT2D.
Она работает на MC6800/HD6303 после проверки аппаратуры и lease ядром;
публичные операции 0–3 и их проверки ISA/диапазонов сохранены.

## Интерфейс

| A | Операция | Параметры |
|---:|---|---|
| 0 | INFO | A=1, B=7 (RAM copy, PAL read, PAL write), X=8192 |
| 1 | MEMMOVE | X=дескриптор 8 байт в обычной RAM |
| 2 | Сохранить PAL | B=физический номер банка E5, 0..110 |
| 3 | Восстановить PAL | B=физический номер банка E5, 0..110 |

Для операций 1..3 результат A=0 при успехе, 1 при неправильных аргументах,
2 при отсутствии нужного оборудования, 3 при выключенном HD6303 ISA.
B/X, CCR, E6F0 и E6F1 возвращаются с исходными значениями.
Сервис не выделяет и не освобождает банки, не проверяет cookie/PCB:
приложение обязано получить их через [RAMMAN INT E5](RAM-MANAGER.md).

Дескриптор MEMMOVE, слова big endian:

| Смещение | Поле |
|---:|---|
| 0 | Банк источника 0..110; FF — обычная RAM |
| 1 | Банк назначения 0..110; FF — обычная RAM |
| 2..3 | Адрес источника |
| 4..5 | Адрес назначения |
| 6..7 | Количество байт 0..8192 |

Для банка адрес — смещение 0000..1FFF, для обычной RAM — абсолютный
адрес 0100..BDFF. Весь диапазон обязан помещаться в одном банке либо
обычной RAM; конец обычного диапазона не выше BE00. Дескриптор также
должен целиком находиться в 0100..BDFF. ROM, MMIO и банковое окно как
«обычная RAM» не принимаются. Входные диапазоны проверяются до первой
записи; нулевая длина ничего не переносит, но аргументы проверяются.

Перекрывающиеся диапазоны одной области поддерживаются как memmove:
если назначение выше источника, копирование идёт с конца. Между разными
банками направление прямое. Дескриптор копируется на стек до записи,
поэтому изменение его памяти самим переносом не меняет операцию.
Для диапазона нескольких банков приложение делает отдельный вызов на
каждый банк своего дескриптора E5; физическая непрерывность не требуется.

```asm
; lease ранее получен: INT E5 A=1, B=1, X=lease.
    ldaa #$ff
    staa move
    ldaa lease+3
    staa move+1
    ldd #buffer
    std move+2
    ldd #0
    std move+4
    ldd #512
    std move+6
    ldx #move
    ldaa #1
    int $e8
    tsta
    bne failed
; move ds 8, lease ds 4, buffer ds 512 — обычные метки BSS UniAS.
```

## PAL и прерывания

Операции 2/3 переносят все 8192 отсчёта аппаратной waveform-палитры
через E65E/E65F. Они устанавливают адрес PAL=0 и заканчивают с readback=0.
RGB-компоненты/число цветов не пересчитываются. GAMEBIOS использует их
для точного восстановления предыдущей палитры после HAM8 и indexed.

Для RAM copy используются 16 байт временного стека, для PAL — четыре,
плюс адреса возврата/кадр SWI. Вызывающий код и стек должны быть вне
C000–DFFF. Переносимая область не должна перекрывать живой стек, код,
PCB или системные данные: проверка адресного диапазона этого не определяет.

Сервис не выполняет SEI и не отключает музыкальный таймер. IRQ/NMI/SWI
обоих BIOS сохраняют оба селектора, поэтому музыкальные и системные
прерывания могут обслуживаться между байтами переноса. Это синхронный
CPU-сервис: основной цикл занят до возврата и не пополняет очередь музыки.
Для длительных переносов пополнять очередь заранее или разбивать работу.
RAM↔банк/банк↔банк копируются побайтно с переключением селекторов;
PAL↔банк выбирает банк один раз и работает последовательным циклом.

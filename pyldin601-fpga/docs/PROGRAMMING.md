# Программирование графики и музыки Пълдина

Интерфейсы на 12 октября 2026: FPGA graphics v6, ROM GAMEBIOS ABI 1,
RAMMAN ABI 1. Для нового приложения на HD6303 основной интерфейс —
**INT E6**. Он управляет графикой и AY, сохраняет устройства и возвращает
штатный экран при завершении. Старые вызовы UniBIOS продолжают работать
с прежними видеорежимами и бипером; новые функции вызываются явно.

Это руководство относится к FPGA Пълдину 601/601А. Название латиницей —
PYLDIN. Исходники и примеры собираются настоящим UniAS.

## С чего начать

- [GAMEBIOS.INC](../firmware/game/GAMEBIOS.INC) — номера функций,
  ошибки, флаги и форматы параметров INT E6.
- [GAMESDK.ASM](../firmware/game/GAMESDK.ASM) и
  [GAMESDTA.INC](../firmware/game/GAMESDTA.INC) — открытие/закрытие,
  raw-клавиатура, тайлы и прокрутка.
- [GFXAY.ASM](examples/GFXAY.ASM) — небольшой полный пример:
  графический текст, прямоугольник, нота по SPACE, выход по ESC.
- [GAMEBIOS.md](../audit/GAMEBIOS.md) — полная таблица ABI;
  [GRAPHICS.md](../audit/GRAPHICS.md) и [AY.md](../audit/AY.md) — MMIO.

`INT E0` остаётся нижним ROM-интерфейсом: режим, FLIP, блиттер, обрезанный
спрайт, кадр AY и выключение звука. Он не открывает контекст, не сохраняет
палитру и не ведёт музыкальную очередь. При прямом использовании E0/MMIO
сохранение и восстановление устройств выполняет приложение.

## Открытие, память и завершение

GAMEBIOS INFO (`A=GB_INFO`) возвращает `A=1`, `B=63` и `X=8608`.
В B находятся feature bits: video, text, audio, clipping, HAM8, BATCH.
Для BATCH проверять `B & GB_FEATURE_BATCH`, а не равенство всего B числу 63.
Старые ROM ABI 1 могут возвращать 31 без BATCH. INFO разрешён на MC6800;
остальные операции GAMEBIOS требуют HD6303. `sdk_open` проверяет CPU,
наличие INT E6, ABI и размер контекста.

Перед `GB_OPEN` приложение выделяет **8608 байт обычной RAM**:

| Смещение | Данные |
|---:|---|
| 0..1 | Размер 8608, big endian |
| 2 | ABI 1 |
| 3 | `GB_VIDEO=1`, `GB_AUDIO=2` или их сумма |
| 4..31 | Резерв |
| 32..8223 | Резервная копия 8192 отсчётов PAL-палитры |
| 8224..8607 | Частное состояние, очередь AY, обработчик |

Размещать весь контекст и параметры в `$0100..$BDFF`, вне окна
`$C000..$DFFF`. Контекст должен жить до CLOSE; его частные байты нельзя
использовать как рабочую память. Одновременно допускается один владелец
PCB. Уже работающие чужие графика или аудиотаймер приводят к отказу OPEN.
Видеопамять при закрытии не восстанавливается, поэтому страницы кадра
нужно распределять внутри приложения.

UniDOS резервирует PGM BSS без обнуления. Перед инициализацией очистить
собственный BSS, особенно после другого PGM или повторного запуска.
`sdk_open` принимает флаги в B, `sdk_close` закрывает GAMEBIOS и освобождает
raw-захват клавиатуры. После успешного OPEN все выходы, включая ошибки,
должны пройти через CLOSE. Штатное завершение `INT $38` дополнительно
закрывает контекст владельца и освобождает его банки RAMMAN.

CLOSE восстанавливает PAL-палитру, страницу показа, штатное видео,
AY-регистры, делитель, период аудиотаймера и прежний INT E4.
Внутренние IRQ/NMI/SWI обоих BIOS сохраняют E6F0/E6F1. В основном коде
при ручном переключении банков всё равно сохранить и восстановить оба
регистра. Код, стек, контекст и очередь не переносить в страничное окно.

Для обычных функций E6 результат `A=0` означает успех. B/X сохраняются,
кроме INFO, READPIX и STATUS. BIOS восстанавливает CCR и регистры страниц.
Слова дескрипторов — big endian, в отличие от low/high регистров блиттера.
После каждого вызова проверять A; ошибка не означает откат ранее
выполненных графических команд.

| A | Ошибка |
|---:|---|
| 1 | Неверный аргумент |
| 2 | Оборудование, ERROR/UNDERRUN или таймаут |
| 3 | Требуется HD6303 |
| 4 | Нет доступного контекста/сервиса |
| 5 | Занято или вложенный вызов |
| 6 | Чужой владелец |
| 7 | Очередь кадров AY заполнена |
| 8 | Операция недоступна в этом режиме/контексте |

После ошибки закрыть контекст и вернуть управление UniDOS. OPEN/SDK
восстанавливают завершённую ошибку блиттера только при выключенной,
незанятой графике. Активную ошибку не скрывать бесконечным повтором.

## Кадры, палитра и рисование

Физическая SRAM `$100000..$1FFFFF` — 16 графических страниц по 64 КиБ.
Адрес страницы n: `$100000 + n*$10000`. Смещение пикселя:
`y*320+x`; видимая область — 64000 байт, `x=0..319`, `y=0..199`.
Последние 1536 байт не входят в кадр и недоступны командам блиттера.
Это GPU-память: CPU загружает её через команды WRITE BYTE/COPY/FILL,
а не через банковое окно E6F0/E6F1.

Типичная раскладка: 0/1 — два кадра, 2 — атлас, 3 — неизменный фон,
5 — меню. Это соглашение приложения, а не резервирование ROM.
Расширенная RAM музыки занимает отдельный пул и с этими страницами
не пересекается.

| Вызов | Параметры |
|---|---|
| MODE | B=0 штатный экран, 1 indexed, 7 HAM8 |
| TARGET | B=0..15, страница для примитивов, чтения и текста |
| FLIP | B=0..15, страница показа; вызов ждёт PAL VBL |
| PALETTE | X=`index,R8,G8,B8`, 4 байта |
| PIXEL / RAWPIX | X=`xBE,yBE,value`, 5 байт |
| READPIX | X=`xBE,yBE`, возвращает B=байт из TARGET |
| RECT | X=`xBE,yBE,widthBE,height,value`, 8 байт |
| LINE | X=`x0BE,y0BE,x1BE,y1BE,value`, 9 байт |
| COPY | X=11-байтовый дескриптор, см. ниже |
| SPRITE | X=12-байтовый дескриптор, см. ниже |

Indexed хранит индекс 0..255. Начальная палитра RGB332 может быть заменена
через PALETTE на RGB888 цвет: ROM вычисляет 32 PAL-отсчёта. Это не запись
трёх RGB-байтов в FPGA. Весь экран, включая меню, использует одну палитру.
Изменение видимого цвета действует сразу; подготовку большого набора
цветов лучше завершить до начала музыки/показа.

PIXEL/RECT/LINE обрезают изображение по экрану. Отрицательные координаты —
signed16. RECT требует width=1..320, height=1..200; полностью невидимый
прямоугольник ничего не рисует. LINE допускает концы x=-320..639,
y=-200..399. READPIX вне экрана возвращает ошибку.

### COPY и прозрачный спрайт

Дескриптор COPY:

| Смещение | Значение |
|---:|---|
| 0 | Команда 1 FILL, 2 COPY или 6 keyed COPY |
| 1 | Цвет для FILL / прозрачный ключ для команды 6 |
| 2, 3 | Страница источника, страница назначения |
| 4..5, 6..7 | Смещения источника и назначения, BE16 |
| 8..9 | Ширина BE16, 1..320 |
| 10 | Высота, 1..200 |

Шаг обеих строк всегда **320 байт**, включая атласы. COPY/SPRITE имеют
собственную страницу назначения и не используют TARGET. COPY не обрезает
координаты: вызывающий проверяет x+width<=320 и конец области <64000.
Блиттер допускает перекрытие в одной странице и выбирает направление.
Keyed COPY пропускает байт источника, равный ключу; остальные копируются
без изменения. Ключ может быть любым байтом, в indexed и HAM8 это именно
сравнение кода, а не итогового RGB-цвета.

Дескриптор SPRITE: `xBE,yBE,srcOffsetBE,widthBE,height,srcPage,dstPage,key`
(12 байт). Он обрезает signed x/y по всем краям и корректирует source
offset. Исходный прямоугольник должен целиком помещаться в кадр страницы.
Полностью невидимый спрайт — успешная пустая операция. Упакованный массив
16×16 с шагом 16 нужно сначала разложить в атласе с шагом 320.

Для движения без следов на каждой из двух страниц помнить её собственные
прошлые позиции. Сначала восстановить **все** старые прямоугольники этой
страницы из фона, затем нарисовать все новые спрайты и выполнить FLIP.
Одна общая история на два кадра оставит следы через кадр.

### Текст, тайлы и пакет команд

Новый текст рисуется в indexed framebuffer штатным шрифтом 8×8: 40×25
знакомест на обеих моделях. Он не переключает 601А в её native 80 колонок.
PUTC принимает символ в B, PUTS — строку с NUL в X. CURSOR принимает
`column,row`; ATTR — `foreground,background`; WINDOW —
`left,top,width,height` в символах. CURSOR использует координаты полного
экрана, которые должны лежать внутри окна. CR/LF, Backspace, перенос и
прокрутка поддерживаются. Backspace сдвигает курсор влево без стирания;
для удаления символа вывести пробел и снова Backspace. CLEAR заполняет
окно цветом background. SCROLL B=1..высота окна прокручивает его вверх.

`sdk_tile` использует атлас 8×8 тайлов по 8×8 пикселей: ID=0..63,
X=`srcPage,dstPage,ID,column,row`. `sdk_map` принимает 12 байт:
`mapBE,mapWidth,mapHeight,cameraX,cameraY,viewWidth,viewHeight,left,top,
atlasPage,destPage`. Карта — byte ID в обычной RAM; размеры в тайлах,
окно не больше 40×25. `sdk_scroll` с тем же X и B=0/1/2/3
(left/right/up/down) сдвигает изображение COPY на тайл и рисует открывшийся
ряд/колонку. На границе карты возвращает успех без изменения.

BATCH принимает B=0..32, X=список записей `operation,B,pointerBE`
по 4 байта. Разрешены TARGET, PIXEL, RECT, LINE, COPY, SPRITE, PUTC, PUTS,
CURSOR, ATTR, WINDOW, SCROLL, CLEAR, RAWPIX. MODE/FLIP/PALETTE, аудио и
вложенный BATCH запрещены. Пакет снижает число SWI; при первой ошибке
останавливается без отката уже нарисованного. На ROM без feature BATCH
вызвать те же операции отдельно. Пример списка — `refresh_batch`
в [ARKANOID.ASM](../firmware/game/ARKANOID.ASM).

## HAM8 и наложение без полос

Один байт HAM8: bits7:6=00 задаёт абсолютный RGB222 (R5:4/G3:2/B1:0),
01 меняет B6, 10 меняет R6, 11 меняет G6. Компоненты RGB222 расширяются
в 0/21/42/63. Строка начинается с чёрного; цвет зависит от всех предыдущих
команд этой строки. 262144 RGB-состояния не означают 18-битный физический
DAC: вывод остаётся composite PAL. HAM6 отсутствует.

`GB_MODE B=7` строит компонентную таблицу PAL и включает обычный HAM8.
PIXEL/READPIX/RECT/LINE/текст в этом логическом режиме недоступны;
RAWPIX/COPY/SPRITE работают с encoded байтами. Прямой `INT E0 A=1,B=7`
только включает режим, не строит таблицу. Для стандартного HAM8 IFF ILBM
использовать HVIEW/HIMAGE: 320×200, 8 плоскостей, без mask, uncompressed
или ByteRun1; подробности в [HAM-VIEWER.md](../audit/HAM-VIEWER.md).

В обычном HAM8 вставленный спрайт меняет накопленный цвет справа от себя.
Один keyed COPY не устраняет этот эффект. Для произвольного изображения
с движущимися объектами использовать **аппаратное наложение v6**:

1. В открытом видеоконтексте один раз вызвать `GB_MODE B=7` для подготовки
   компонентной таблицы. Делать это до музыки: вычисление длительное.
2. Сохранить исходные 64000 encoded байт в отдельной странице фона.
3. Вызвать `GB_MODE B=1`: логический режим GAMEBIOS остаётся indexed,
   поэтому доступны примитивы и текст. Компонентная таблица сохраняется.
4. В скрытой странице переднего плана кодами 00..3F нарисовать собственные
   RGB222 цвета, кодами 40..FF — участки, открывающие фон. Значения младших
   шести бит открывающего кода не используются.
5. Выбрать готовую страницу показа через GB_FLIP. Записать номер полного
   фона в E654, затем E650=15. Эта запись фиксирует источник фона.

```asm
    ; After preparing the HAM table, foreground and front page:
    ldaa #8             ; complete original background in page 8
    staa $e654
    ldaa #15            ; hardware HAM8 + RGB222 overlay
    staa $e650
```

INT E0 и GB_MODE принимают только 0/1/7; значение 15 задаётся MMIO.
Перед ним проверить E65F>=6 и дождаться завершения своих команд.
Последующие E654 для COPY не меняют зафиксированный фон. При переходе
на другую картинку снова записать E654/E650; обычный FLIP меняет только
передний план. При возвращении в меню `GB_MODE B=1` выключает аппаратное
наложение. `GB_MODE B=7` внутри игрового цикла снова пересчитает таблицу.

FPGA декодирует весь исходный фон, включая скрытые пиксели. Для открытия
пикселя можно использовать, например, код $40: в этом месте будет точный
цвет полного фона. Простое копирование исходного участка тоже сохраняет
картинку, но его абсолютные коды 00..3F трактуются как RGB222 переднего
плана и должны совпадать с исходником. Оверлей не использует indexed
палитру; цвета предметов/текста ограничить кодами 00..3F.

Компонентная таблица занимает PAL-индексы 0..191. Для indexed-меню,
сохраняющего эту таблицу, использовать, например, 240..245. Нельзя менять
PAL-индексы 0..191 через PALETTE и затем ожидать правильный HAM8.
В Xonix холодная загрузка всех фонов и шаблона заканчивается до таблицы
и начала музыки. Новый раунд/уровень только выбирает готовые данные.
[XONIX.CFG и распределение страниц](../audit/ARCADE.md).

## AY: ноты, кадры, частота и таймер

Частота генератора **AY master** и частота отправки музыкальных кадров —
разные настройки. CLOCK выбирает master: B=0 — 2 МГц, 1 — 1 МГц,
2 — 1773400 Гц (Spectrum), 3 — 1789773 Гц (MSX). RATE получает BE32
период в тактах 24 МГц: `round(24000000/rateHz)`, диапазон
240000..24000000 (100..1 Гц). Для 50/60/100 Гц: 480000/400000/240000.
CPU 1/2/4/8 МГц и PAL 50 Гц не изменяют эти настройки. OPEN по умолчанию
задаёт 2 МГц и 50 Гц; CLOCK/RATE разрешены только при PLAY=0.

| Вызов | Использование |
|---|---|
| NOTE | X=`channel,note,ticksBE,volume`, 5 байт |
| FRAME | X=14 готовых регистров R0..R13; копируются в очередь |
| PLAY | B=1 включить/продолжить IRQ, B=0 пауза |
| STOP | Выключить таймер/звук, очистить очередь и эффекты |
| STATUS | B=кадров в очереди 0..16, X=16-битный счётчик IRQ |
| RESERVE | B=маска каналов 0..7 (A/B/C = bits0/1/2) |
| AYREG | X=`register,value`, R0..R13, только без кадрового потока |

NOTE: channel=0..2, note=1 (C1)..72 (B6), volume=0..15. ticks=0 удерживает
ноту, положительное число задаёт длительность в музыкальных IRQ.
`note=0,ticks=0` отпускает канал; `note=0,ticks>0` даёт паузу.
Нота звучит при вызове, но для истечения ticks включить PLAY=1.
CLOCK установить до NOTE: уже активная нота не пересчитывается.

NOTE временно заменяет соответствующий канал музыкального кадра, затем
возвращает его музыке. RESERVE удерживает канал даже после окончания
NOTE; без активного эффекта такой канал молчит. Если нужно автоматическое
возвращение к песне после эффекта, постоянную маску RESERVE не задавать.
NOTE использует tone и фиксированную громкость; noise/envelope задаются
AYREG или музыкальными кадрами. Envelope общий у всех трёх каналов.

PLAY=0 сохраняет очередь, позицию и длительности, выключая звук и IRQ.
Для изменения CLOCK/RATE достаточно паузы. Для AYREG после FRAME
требуется STOP: пауза не снимает признак кадрового потока. STOP удаляет
его вместе с очередью/эффектами. CLOSE восстанавливает состояние до OPEN.

### Музыкальная очередь и основной цикл

FRAME помещает копию 14 байт в кольцевую очередь на **16 кадров**.
R13=$FF означает не записывать envelope shape; другая запись R13 повторно
запускает envelope. IRQ снимает один кадр, накладывает NOTE/RESERVE и
передаёт R0..R13 в AY. Пустая очередь удерживает последний кадр без
повторного запуска envelope: при этом музыка перестаёт продвигаться.

Последовательность: CLOCK, RATE, заполнить очередь, PLAY=1. В основном
цикле регулярно читать STATUS, готовить и добавлять недостающие кадры.
Количество свободных мест — `16-B`; при единственном производителе IRQ
может только увеличить этот запас. Если FRAME вернул GB_FULL, сохранить
кадр и повторить позже, не перепрыгивая позицию песни.

Запас полной очереди: 320 мс при 50 Гц, 160 мс при 100 Гц. В эти интервалы
должны укладываться участки без пополнения. FLIP привязан к PAL 50 Гц;
при 100-Гц песне нужно подавать несколько аудиокадров на графический кадр.
Длительный GB_MODE=7, дисковый OPEN/READ или пересчёт всего экрана могут
исчерпать очередь даже при работающих IRQ. Делить большой объём работы
на части и пополнять между ними; загрузку/распаковку крупных ресурсов
предпочтительно завершить до PLAY=1.

Для готовых YM3/3b/5/6, PSG, AY VTX, LHA LH0/LH5 используются
[GAMEMUS.ASM](../firmware/game/GAMEMUS.ASM),
[MUSAPI.ASM](../firmware/game/MUSAPI.ASM),
[MUSDATA.INC](../firmware/game/MUSDATA.INC). Это исходники библиотеки
приложения, не новые функции ROM ABI. Поддерживаемые clocks и ограничения
форматов перечислены в [AUDIO-PLAYER.md](../audit/AUDIO-PLAYER.md).

- `mus_load`: X=полный путь, A=0 загружено/проверено, 1 отказ.
  Выполнить **до sdk_open**: LH5-словарь и таблицы используют память
  будущего контекста при сборке с `-D GAME_MUSIC`.
- `mus_start`: после OPEN настроить clock/rate по файлу, заполнить очередь
  и начать песню с начала. Это не функция паузы/продолжения.
- `mus_fill`: часто вызывать из основного цикла; он читает выделенные RAM
  банки, декодирует кадры и пополняет GAMEBIOS. Файл уже закрыт.
- `mus_release`: освободить банки при окончательном выходе/отказе.

Включить MUSAPI/GAMEMUS после кода приложения, MUSDATA в BSS один раз;
GAMESDTA при GAME_MUSIC содержит общую область LH5/контекста. В играх
MUSDATA уже включён из HISDATA — повторять его нельзя. Пример порядка
включения и обработки отказов — ARKANOID.ASM.
При смене меню на игру не вызывать mus_start заново, если песня должна
продолжаться. В Xonix музыка запускается после холодной подготовки и
идёт через таблицу, раунды и смену уровня.

RAMMAN INT E5 выделяет до 111 банков по 8 КиБ (888 КиБ):
`ceil(распакованный_размер/8192)`, включая заголовки. Банки могут быть
разрозненными. Физический номер n из дескриптора отображается в окно
`E6F1=n/6`, `E6F0=1+n%6`; код/стек/очередь остаются в обычной RAM.
[Дескриптор и владение](../audit/RAM-MANAGER.md).
IRQ GAMEBIOS не читает SD/HG, не распаковывает и не переключает банки.
Он обслуживается штатным BIOS через INT E4, независимо от системного
INT05. При использовании GAMEBIOS свой обработчик E4 не устанавливать.

### Прямое управление AY

MMIO E610..E61F адресует регистры AY напрямую: tone R0/1, R2/3, R4/5;
noise R6; mixer R7; levels R8..10; envelope R11/12 и shape R13.
Периоды AY — **little endian**, в отличие от дескрипторов NOTE/RATE.
Частота тона `master/(16*period)`, период 0 аппаратно равен 1.
В R7 установленный bit0..2 выключает tone A/B/C, bit3..5 — noise.
Volume=0..15, bit4 включает envelope. INT E0 A=5 передаёт 14 байт
немедленно; A=6 выключает AY, сохраняя штатный бипер.

Аудиотаймер и делитель находятся в E690..E69F; оба имеют shadow/commit.
Q16 divisor для master: `round(768000000*65536/masterHz)`.
Для 2 МГц — $01800000, для 1 МГц — $03000000;
интервал звукового шага равен divisor/65536 тактам 96 МГц.
При ручной настройке ждать ACK/busy с конечным таймаутом и проверять
bad config. Полная карта, снимок счётчика и IRQ ACK — в AY.md.
Не смешивать MMIO/E0 запись AY со своим потоком GAMEBIOS: следующий
музыкальный кадр перезапишет её. Для эффекта внутри песни использовать NOTE.

## Ввод и порядок игрового кадра

После открытия вызвать `sdk_input_reset`: raw PS/2 захватывается, штатные
клавиатурные IRQ/автоповтор/клики подавляются, PAL и музыкальные IRQ работают.
`sdk_input` возвращает A=код, B=удерживаемые клавиши; `sdk_pressed` содержит
нажатия с прошлого опроса, включая короткое make/break между кадрами.
Маски — GB_KEY_LEFT/RIGHT/UP/DOWN/SPACE/ESC/CTRL/SHIFT. Стрелки и WASD
имеют отдельное физическое состояние. Переполнение очищает состояние
и FIFO, возвращая GB_HARDWARE, чтобы не оставлять залипшую клавишу.

Движение считать по B каждый кадр, запуск/паузы — по sdk_pressed.
Для ввода имени в графическом меню отпустить raw-захват
(`GB_PS2_FLUSH+GB_PS2_CLEAR+GB_PS2_RELEASE` в GB_PS2_CONTROL), использовать
неблокирующий INT10 и рисовать полученные символы через GB_PUTC/PUTS.
Контекст и графику сохранять открытыми. Перед возвратом в игру снова
sdk_input_reset. `INT $23` рисует штатный текст, поэтому использовать
его только после окончательного CLOSE.

Обычный кадр: пополнить музыку → опросить клавиши → обновить логику →
восстановить старые области скрытой страницы → нарисовать новые объекты
и изменившиеся цифры → пополнить музыку → FLIP. При длительных фазах
логики/рисования добавлять пополнение между частями. При паузе не двигать
объекты и вызвать PLAY=0; для продолжения PLAY=1 без перезагрузки файла.

## Сборка примера

Из корня `pyldin601-fpga`; подставить путь к настоящему UniAS:

```sh
make -f firmware/Makefile build/firmware-data
mkdir -p build/programming
cp docs/examples/GFXAY.ASM firmware/game/GAMEBIOS.INC \
   firmware/game/GAMESDK.ASM firmware/game/GAMESDTA.INC build/programming/
(cd build/programming && sh ../../tools/run-unias.sh GFXAY.log \
  /Users/sash/Work/FPGA/hd6303-toolchain/unias \
  -l GFXAY.LST -o GFXAY.raw.PGM GFXAY.ASM)
build/firmware-data pgm build/programming/GFXAY.raw.PGM \
  build/programming/GFXAY.PGM build/programming/GFXAY.LST \
  build/programming/GFXAY.json auto
```

C-инструмент формирует PGM из результата UniAS, удаляет сохранённый хвост
BSS и проверяет relocation/размеры; машинные инструкции создаёт UniAS.
В конце исходника нужны `bss_start`, `bss_end`, `end start`. Адреса данных
задавать настоящими метками для relocation, не числовыми EQU-адресами.
Итоговый GFXAY.PGM можно скопировать на SD или HG. Требуются HD6303,
GAMEBIOS, raw PS/2 capture и согласованная FPGA; SPACE играет C5 на канале C
в течение 25 музыкальных тиков, ESC возвращает UniDOS.

12 октября пример собран UniAS: PGM 1856 байт, код/данные 1432,
BSS 8667, основная RAM 10099 байт, 204 relocation. В эмуляторе с
настоящими BIOS/UniDOS обеих моделей проверены два запуска, пиксели
шрифта, обрезка RECT, нота по SPACE и её завершение через 25 тиков,
повторное нажатие, ESC, восстановление палитры/AY/таймера/вектора/стека
и последующие DIR A/B/C. Логи — `build/programming/601.log` и `601a.log`.
Физическая проверка этого отдельного примера не проводилась.

Производственные примеры: SDKTEST (тайлы/прокрутка), ARKANOID (indexed,
двойной буфер, эффекты и музыка), XONIX (HAM8 v6, кэш фонов, меню),
HVIEW (ILBM), YPLAY (файлы AY), GFXMUSIC (свой E4 и обычный HAM8).
Последний использует выравнивание фона/спрайтов по четырём пикселям;
это ограничение композиции этого демо, не общее правило COPY/SPRITE.

Проверки интерфейсов: `make test-gamebios`, `make test-gamebios-rtl`,
`make test-gfx`, `make test-ham-layers`, `make test-ay`,
`make test-audio-irq`, `make test-xonix` с `UNIAS=/path/to/unias`.
Их матрицы и результаты — в связанных audit-документах;
сборка примера сама по себе не является подтверждением работы на плате.

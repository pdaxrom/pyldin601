# UART: терминал и передача файлов

`UART.PGM` — нативная программа MC6800 для 601/601А, обоих CPU.
Запуск: `UART` либо `UART 115200`. По умолчанию 19200, 8N1.
Используется канал **B** FTDI; резидент HG продолжает работать на канале A.
Файлы CVM и RAMMAN не требуются. `make input-apps` собирает программу
нашим UniAS из `UART.ASM`, `UARTVT.INC`, `UARTUI.INC`, `UARTX.INC`.
Эти же исходники собираются нативным UniAS без обработки на хосте.

## Терминал

24 строки терминала и нижняя строка управления. Ширина сохраняется:
40 колонок на 601, 40/80 на 601А. Из графики программа временно переходит
в текст, при выходе возвращает прежний режим. На удалённом Unix задавать
`stty rows 24 cols 40` или `cols 80` в соответствии с экраном Пълдин.
Поддерживается подмножество ANSI/VT100; полноценную эмуляцию xterm не заявляем.

| Клавиша | Действие |
|---|---|
| F1 | Справка |
| F2 | Local echo; состояние видно в нижней строке |
| F3 | Приём файла XMODEM-CRC |
| F4 | Отправка файла XMODEM-CRC |
| F10 | Выход в UniDOS/NC |
| Esc, Ctrl+буква | Передача соответствующего управляющего байта хосту |
| Стрелки | CSI A/B/C/D; при DECCKM — SS3 A/B/C/D |
| Home/End, Delete, PgUp/PgDn | ANSI H/F, CSI 3~/5~/6~ |

Реализованы CR/LF/BS/TAB, отложенный перенос строки, CUP/HVP, CUU/CUD/CUF/CUB,
CHA/VPA, ED/EL, DECSTBM, IND/RI/NEL, DECSC/DECRC, CSI s/u, DECCKM,
DECOM, DECAWM, DECTCEM, LNM, RIS, DA и DSR 5/6. Есть G0/G1 DEC Special
Graphics и SO/SI; рамки выводятся штатными символами знакогенератора.
OSC/DCS пропускаются до BEL/ST. Число параметров CSI ограничено восемью,
значения — 0..255; некорректная последовательность не пишет вне буфера.

SGR: сброс, обычные восемь цветов, reverse и blink. Цвета видны только
в цветном тексте 40 колонок на 601А; монохромные режимы сохраняют текст.
Bold принимается и запоминается, но не меняет яркость: у аппаратуры
только три бита цвета переднего плана, а bit7 атрибута задаёт мигание.
Кодировка — байты штатного шрифта, без декодирования UTF-8.

Терминал использует XON/XOFF, FIFO UART и программное кольцо приёма на 255 байт.
Очередь передачи на 127 байт сохраняет ввод во время XOFF; F10 и окна
остаются доступны. Начало передачи файла при непустой очереди отклоняется.
На хосте включить software flow control. Для CPU 1 МГц использовать
`UART 9600`; для CPU 8 МГц проверен `UART 115200`. Значение по умолчанию
19200 оставлено прежним. В цветном/80-колоночном тексте при 1 МГц
19200 может переполнить 16-байтный FIFO во время длинного вызова BIOS,
даже с XON/XOFF; это воспроизведено в проверке. При выключенном flow
control непрерывный поток может обогнать CPU; аппаратные и программные
переполнения включаются в итоговую строку ошибок при выходе.
Прокрутка и снимки окон используют BIOS DMA, при недоступности DMA есть
CPU-перенос. Отдельный читаемый текстовый framebuffer находится в BSS:
стандартная область F000 перекрыта системным ROM для чтения CPU.

## XMODEM-CRC

Передача выполняется блоками **128 байт**, CRC-16/XMODEM (1021, init=0).
Checksum XMODEM, XMODEM-1K, YMODEM и ZMODEM не включены. XON/XOFF во время
пакета не интерпретируются: значения 00..FF, включая CAN/EOT, передаются
как обычные данные. Повтор пакета после потери ACK не дублирует запись.
Есть десять попыток, тайм-ауты по часам BIOS, double CAN и отмена Esc/F10.

В диалоге указать имя с диском/каталогом. Приём в существующий файл
отклоняется. Данные записываются в свободный `UTxxxx.TMP` рядом с целью;
после успешного EOT, закрытия и переименования отправляется финальный ACK.
Отмена/сбой удаляет временный файл. При ошибке самого носителя окно
предлагает проверить TMP, если очистка не удалась. Завершённый приём
повторно подтверждает EOT, пока открыто окно результата.

Отправка показывает заполнение шкалы по размеру файла; приём показывает
индикатор активности, поскольку XMODEM не сообщает длину. Счётчик байтов
в hex учитывает полные переданные блоки; отдельно выводятся повторы.
Последний блок дополняется 1A. **Приём сохраняет дополнение**: невозможно
отличить его от настоящих последних байтов бинарного файла. Для точной
длины нужен известный размер либо протокол с передачей длины.

## Обмен с хостом

Скрипт не требует pyserial и не открывает FTDI A. На sashz-ubuntu:

```sh
# На Пълдин F3: приём; ввести E:\IN.BIN, затем на хосте:
python3 tools/uart_xmodem.py send /path/source.bin --baud 19200

# На Пълдин F4: отправка; выбрать исходник, затем на хосте:
python3 tools/uart_xmodem.py receive /path/received.bin --baud 19200
```

При необходимости указать `--port /dev/serial/by-id/...if01-port0`.
Хостовый приём также использует временный файл и защищает существующее
имя; файл публикуется до финального ACK. После ACK скрипт ещё 12 секунд
отвечает на повтор EOT. Ctrl+C отменяет сеанс через CAN CAN.
Для обычного терминала использовать minicom/screen с одинаковой скоростью
и XON/XOFF; перед запуском скрипта освободить канал B.

## Проверка

`make test-uart-app`: реальные BIOS, UniDOS, UART.PGM и UARTTEST.PGM,
оба CPU/модели, 40/80 колонок и старт из графики. Потоковые проверки терминала при
1 МГц выполняются на 9600; отдельный прогон 8 МГц — на 115200. Проверяются экран,
курсор CRTC, управляющие последовательности, цвета, рамки, flow control,
двоичные данные, CRC, повторы, потеря ACK, отмена и освобождение памяти.
`tests/run_uart_app.py --terminal-only --hg` добавляет настоящий резидент HG
и чтение/запись через его host volume. `--stress` добавляет пустой файл, 32771 байт и обмен 115200 при 8 МГц.
`--payload-size 32771` проверяет
переход номеров блоков 255→0 и неполный последний блок; 0 — пустой файл.
Хостовый протокол независимо проверяет `tests/test_uart_xmodem_host.py`.

17 октября 2026 терминал и XMODEM проверены на физической плате при **8 МГц**,
в тексте **40 колонок**, через FTDI B при работающем HG на канале A:

- Ответы DA/DSR, положение курсора, четыре стрелки, текст, Enter и Esc.
- Пользователь подтвердил рамку штатными символами, область прокрутки
  ONE/TWO/THREE, открытие F1 и восстановление экрана после Esc.
- **9600 и 115200**, в каждом случае приём на плату и отправка обратно.
  Исходник 32771 байт, получено 32896 с 125 байтами дополнения 1A;
  сравнение побайтное, включая переход номера блока 255→0.
- На каждой скорости намеренно повреждён CRC первого блока: плата
  отвергла его, приняла повтор и завершила передачу с правильными данными.
- После закрытия результата через Esc и выхода по F10 пользователь
  подтвердил возврат в UniDOS/NC без сообщения об ошибках UART.

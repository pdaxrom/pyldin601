# Память и переключение страниц

Внешняя SRAM — 2 МиБ, физический byte address 000000..1FFFFF.
CPU имеет 16-битное адресное пространство с классическими RAM/ROM overlay.
Графические страницы не отображаются через C000..DFFF: ими управляет
GPU-порт. Музыкальные данные используют отдельный пул RAMMAN.

| Физический диапазон | Размер | Назначение |
|---|---:|---|
| 000000..00FFFF | 64 КиБ | Базовая RAM, включая RAM под виртуальным ROM |
| 010000..01FFFF | 64 КиБ | 8 ROM-страниц 8..F |
| 020000..020FFF | 4 КиБ | BIOS выбранной модели |
| 021000..0217FF | 2 КиБ | Шрифт |
| 021800..021FFF | 2 КиБ | Не входит в публичный пул RAMMAN |
| 022000..0FFFFF | 888 КиБ | 111 RAM-банков по 8 КиБ |
| 100000..1FFFFF | 1 МиБ | 16 GPU-страниц по 64 КиБ |

В runtime чтение F000..FFFF берётся из физического BIOS 20000..20FFF.
Чтение C000..DFFF при странице 8..F выбирает соответствующий 8-КиБ ROM:
`10000+(page-8)*2000+(CPU-C000)`. Запись под этими ROM overlay идёт в
обычную базовую RAM по CPU-адресу. ROM/font физически защищены после lock.
Во время bootstrap D000/F000 читаются из EBR первичного BIOS;
остальная карта и физический boot-порт описаны в [BOOT.md](BOOT.md).

## RAM-окно C000..DFFF

| E6F0 bits3:0 | Значение |
|---|---|
| 0 или 7 | Основная RAM, одно и то же отображение |
| 1..6 | RAM-банк текущей группы E6F1 |
| 8..F | ROM-страница, E6F1 на неё не влияет |

E6F1=0..18; в группе 18 доступны только страницы 1..3. Последние три
несуществующие страницы читаются FF, записи блокируются. Неверный номер
группы не применяется. Для банка n=0..110 из дескриптора RAMMAN:

```text
E6F1 = n / 6
E6F0 = 1 + n % 6
physical = 022000h + n*2000h + (CPU address-C000h)
```

Сначала сохранить оба регистра, выбрать group/page, выполнить операции,
затем восстановить group и page. Код и стек должны оставаться вне окна.
Слова могут пересекать конец окна; библиотека должна переходить к следующему
выделенному банку, а не предполагать непрерывную физическую цепочку.
Reset регистров выбирает page/group=0, сами данные SRAM не стирает.
[Биты и reset-значения регистров](REGISTERS.md#страничное-окно-e6f0e6f3).

## Владение и UniDOS

Новые приложения получают банки через [RAMMAN INT E5](RAM-MANAGER.md).
Дескриптор содержит cookie, количество и физические номера; банки могут
быть разрозненными. Нельзя выбирать заранее придуманный свободный номер:
его может удерживать другой процесс. Данные при выделении не очищаются.
Обычная основная RAM, ROM и GPU не входят в пул E5.

UniDOS размещает резидентную часть в основной RAM по C000 и использует
страницу 7 для своих векторов. E6F0=0/7 поэтому обязаны показывать
основную память. Превращать страницу 7 в дополнительный RAM-банк нельзя.
Приложение само закрывает GAMEBIOS и освобождает банки до INT38, в том
числе при ошибках. Оболочка не вызывает E5/E6 при удалении PCB.
Контекст GAMEBIOS, очереди IRQ, stack и дескрипторы живут в обычной RAM.
Нативный FAT12/FAT16 использует 480 байт вместо второго FAT-буфера E900:
восемь дескрипторов томов по 50 байт, owner общего E700-буфера, четыре байта
старших адресов файловых буферов, probe BPB и поля банковых FAT/файловых кэшей.
Каждый связный handle получает девять байт после прежнего тела: обычные
10 handles добавляют 90 байт heap, HANDLES 32 — 288. Четыре байта хранят
адреса handle, пять образуют отдельную таблицу ключей пользовательских
буферов; общий буфер не зависит от lifetime одного handle. Дополнительного
512-байтового буфера нет. `FAT_RAMMAN=1` занимает один банк и 4 байта
resident-descriptor, экономя 512 байт heap на дополнительный SD-том
(93 вместо 605). [Проверки доступности и возврат к обычным буферам](STORAGE.md).
При успешной проверке файлового переноса два штатных файловых кэша
используют одно окно E000–E1FF; атрибуты E200/E405 остаются раздельными.
E205–E404 содержит пять заголовков с текущими каталогами для C:–G:,
экономя до 465 байт heap. H: и аппаратный fallback используют heap.
Явные пользовательские буферы остаются по прежним адресам.
Дополнительные частные поля ядра занимают E5E6–E5FD; штатные адреса EBxx/E4xx
и 27/48-байтовые публичные структуры сохранены.
Контекст E6 ABI 2 занимает 416 байт; резервная PAL-палитра — один банк E5.
Словарь и таблицы LH5 занимают два временных банка только при загрузке.
Для переноса RAM↔банк, банк↔банк и PAL↔банк существует
[INT E8 в постоянном BIOS](BANKCOPY.md). Он не выделяет память и сохраняет
селекторы; код копирования не приходится размещать в RAM.

## IRQ/NMI/SWI и Y-код

Диспетчеры обоих BIOS сохраняют E6F0 и E6F1 в каждом прерванном вызове.
При входе обработчик видит исходный десятибайтовый кадр: return PC по
offset 0..1 от TSX, E6F0 по 2, CCR/B/A/X/PC по 3..9. Дополнительного
байта E6F1 в этом кадре нет: группа 0..18 закодирована выбором адреса
возврата в ROM. Продолжение восстанавливает группу, страницу и регистры.
Для SWI/IRQ/NMI используются продолжения из `ROMRETURNS.INC` в обоих BIOS.
Старые обработчики INT37, INT38 и монитор сохраняют прежние смещения;
вложенные вызовы не используют общий буфер и не выделяют resident RAM.

Вектор с page=0 означает «не переключать» и наследует group/page вызывающего.
Для ненулевой page BIOS выбирает group=0 и указанную страницу, а при возврате
восстанавливает исходные оба регистра. Вложенные вызовы имеют свои копии.
Ручная смена банков в основном коде всё равно должна восстанавливать их:
автоматическое сохранение обработчиком не закрывает время жизни выделения.

Поставляемый Y-интерпретатор использует ROM-страницы 9/D. Его прямые
переключения E6F0 выполняются из RAM-трамплина BE00..BEFF вне окна;
E6F1 они не меняют. ExitYcode восстанавливает SP по сохранённой глубине
вызова. Старые смещения кадра интерпретатора остаются действительными.
FPGA сохраняет классическую карту регистров даже при HD6303 ISA;
условный вариант исходников YGPascal для отдельного физического Lilith
не выбирается автоматически настройкой CPU.

## Проверки памяти

RAMPAGE — разрушительный тест всех 888 КиБ, запускать без других владельцев.
RAMALLOC проверяет выделенные 64 КиБ и освобождение, сохраняя чужие банки.
Нативные/HDL проверки покрывают группы, невалидные окна, обе модели/ISA,
IRQ/NMI/SWI, Y-код и возврат в UniDOS. Команды — [BUILD.md](BUILD.md).

# Изображения: HAM8, JPEG/PNG и PCX

`tools/ham8conv.c` — C-конвертер JPEG/PNG в HAM8; `HVIEW.PGM` —
HD6303-загрузчик картинок через штатный файловый API UniDOS.
Нужны HD6303 EXTENSION Y и существующая FPGA с графическим интерфейсом v5.
FPGA и ROM для этих программ менять не требуется. При 8 МГц загрузка быстрее.
PCX и его произвольная 256-цветная палитра остаются в отдельном `VIEW.PGM`.

## Конвертация на Linux

Конвертер уже установлен на HG-хосте `sashz-ubuntu`:

```sh
~/Work/FPGA/pyldin601-hg/bin/ham8conv \
  --preview preview.png photo.jpg \
  ~/Work/FPGA/pyldin601-hg/files/PHOTO.IFF
```

PNG принимается той же командой. Файл появляется на HG автоматически,
перезапуск сервера не нужен. Имена файлов для UniDOS — формат 8.3.
На Пълдине:

```text
B:HG
E:HVIEW E:PHOTO.IFF
```

Заменяй E на букву, которую сообщил HG. ESC после показа возвращает UniDOS.
Для проверки уже установлен `E:HVIEW E:LENA.IFF`. Исходная `LENA.PCX`
сохранена. На физической плате пользователь подтвердил цвета Лены и ESC.

По умолчанию картинка вписывается в 320×200 с сохранением пропорций
в логических пикселях, по центру на чёрном фоне. Лена 500×500 преобразована
в 200×200; `--stretch` явно растягивает картинку на весь кадр:

```sh
~/Work/FPGA/pyldin601-hg/bin/ham8conv --stretch photo.jpg \
  ~/Work/FPGA/pyldin601-hg/files/PHOTO.IFF
```

`--uncompressed` отключает ByteRun1. `--preview preview.png` сохраняет
точное RGB-превью декодированных команд нашего контроллера. PAL и дисплей
могут менять воспринимаемый цвет; превью не моделирует аналоговый выход.

## Сборка

Из каталога `pyldin601-fpga`, на Debian/Ubuntu:

```sh
sudo apt install build-essential pkg-config libjpeg-dev libpng-dev
make ham8conv
make gfx-apps UNIAS=/path/to/hd6303-toolchain/unias
build/ham8conv --preview preview.png photo.jpg PHOTO.IFF
```

На macOS библиотеки предоставляет `brew install jpeg-turbo libpng pkg-config`.
HVIEW собирается существующим UniAS, без собственного ассемблера.
PGM имеет 2809 байт кода/данных, 8192 байта BSS для сохранения палитры,
265 relocation, размер файла 3355 байт. В код/данные входят 512-байтный
входной буфер и 320-байтная строка; целая картинка в основной RAM не хранится.

## Формат и кодирование

Используется стандартный [IFF ILBM](https://wiki.amigaos.net/wiki/ILBM_IFF_Interleaved_Bitmap):
`FORM/ILBM`, `BMHD` 320×200, восемь interleaved bitplanes,
`CAMG=$00000800` (HAM), `CMAP` из 64 фиксированных RGB222 цветов и `BODY`.
Все размеры/числа big endian, нечётные chunks имеют байт padding.
Compression 0 — raw; 1 — ByteRun1 с независимыми 40-байтными строками плоскостей.

Это поддерживаемый профиль HAM8 нашего контроллера: произвольная CMAP,
mask plane, другие размеры и дополнительные CAMG-флаги не принимаются.
Изображения от сторонних HAM8-конвертеров могут использовать другой профиль.
RGB6 расширяется репликацией битов; это не обещание побитовой совместимости
24-битного цветового состояния Amiga. [Точные команды и PAL](HAM.md).

JPEG декодируется libjpeg, PNG — libpng. Поддержаны baseline/progressive,
grayscale и CMYK/YCCK JPEG, Exif orientation 1–8, RGBA PNG с композицией
на чёрный фон. ICC-профили не обрабатываются; CMYK использует обычное
арифметическое преобразование, не полиграфическое управление цветом.
Уменьшение — area filter, увеличение — bilinear. Максимум входа —
64 миллиона пикселей и 16384 пикселя на сторону.

Для каждой строки конвертер подбирает команды с beam search из 32 состояний
и взвешенной ошибкой RGB. Проверка greedy-пути исключает ухудшение относительно
однопиксельного выбора. Строка начинается с чёрного, как в FPGA.
Фиксированная палитра RGB222, изменения B/R/G используют шесть бит.
HAM8 хранит 262144 RGB-состояния; соседние пиксели зависят друг от друга,
поэтому резкие границы могут давать характерные HAM-переходы.

Лена из пользовательского PNG: IFF 49290 байт, RGB PSNR 30,40 dB относительно
масштабированного исходника. Это качество кодирования, не измерение PAL DAC.

# PCX и VIEW

VIEW.PGM — перемещаемая программа UniDOS, собранная UniAS из
`firmware/gfx/VIEW.ASM` для HD6303. Она открывает обычный PCX через INT4A,
получает размер INT51, перемещается INT50 и читает INT4C. Файл открывается
только для чтения. SD и HG используют общий файловый API.
Проверка CPU перед первым расширенным opcode совместима с MC6800 и
выводит сообщение, если HD6303 EXTENSION выключено.

```text
B:VIEW B:FRACTAL.PCX
```

Для удалённого диска выполнить B:HG, затем E:VIEW E:FRACTAL.PCX
(E — первый свободный диск при наличии ROM/RAM-дисков). После загрузки
ESC выключает расширенный экран, закрывает файл и возвращает UniDOS.
На 1 МГц распаковка больших изображений занимает заметное время;
короткое нажатие Reset позволяет выбрать 2/4/8 МГц.

## Поддерживаемый формат

Используется [оригинальная спецификация ZSoft PCX, revision 5](https://techheap.packetizer.com/compression/graphics/pcxfmt.html):
128-байтовый заголовок с little-endian словами, version 5, encoding 1,
8 bits/pixel, одна плоскость, RLE и хвост 0Ch + 768 байт RGB-палитры.
Картинка должна быть не больше 320×200. Меньшие изображения центрируются
на фоне самого тёмного цвета палитры (минимум R+G+B). BytesPerLine учитывается отдельно от ширины: допустим
чётный размер от ширины до 512 байт. Padding декодируется, но не рисуется.
RLE-пакет не пересекает строку; нулевые серии, выход за строку, обрезанные
данные, неверный заголовок и отсутствующая палитра дают сообщение об ошибке.
Форматы PCX с несколькими плоскостями и картинки большего размера
отклоняются. Импорт PNG/JPEG и конвертер на хосте не используются.

Все 256 RGB888-цветов PCX загружаются в программируемую PAL-таблицу
графического устройства версии 2; индексы сохраняются без преобразования
в RGB332. Изображение рисуется на соседней странице SRAM,
показывается после VBL flip. Для серий используется аппаратный FILL,
для одиночных пикселей WRITE BYTE. Кадр не хранится в базовой RAM CPU:
там находятся код, 512-байтовый буфер чтения, заголовок, PCX-палитра и
8 КиБ BSS для сохранения прежней PAL-таблицы. UniDOS резервирует BSS
обычным PGM-loader. VIEW занимает 3288 байт кода/данных и 3750 байт в PGM,
223 relocation entries. При ESC и ошибках прежняя палитра восстанавливается.
Старая FPGA без порта палитры выдаёт сообщение о необходимости обновления.

HD6303 рассчитывает 32 отсчёта каждого цвета тремя MUL на фазу, используя
signed Q9-коэффициенты из `PALCOEF.ASM`, проверяемые независимым `tests/pal_reference.py`.
Округление выполняется после суммы. Ошибка коэффициентов во всём RGB888
кубе не превышает 0,630859375 шага DAC, разница округлённых отсчётов — 1.
Все промежуточные значения помещаются в 16 бит. Это точность программного
расчёта, без учёта фазовой дискретизации и аналогового composite PAL.
Файловые позиции и остаток сжатого потока — 32-битные, палитра не может
быть случайно принята за RLE. В UniDOS INT50 method 2 вычитает положительное
смещение из размера файла; это проверено по оригинальному U.ASM.

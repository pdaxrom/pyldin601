# Paint

`PAINT.PGM` — новый нативный графический редактор для Пълдин-601 и 601А.
Прежний `GD.CMD` остаётся отдельной программой для 601.

Рядом с `PAINT.PGM` нужны три файла: `PNTNAT.PGM`, `PNTRGB.PGM`,
`PNTHAM.PGM`. Запуск: `PAINT` или `PAINT имя.PCX` / `PAINT имя.IFF`.
CVM не требуется. RAMMAN используется при наличии свободной страницы;
при его отсутствии или занятости модуль выполняется в обычной ОЗУ.

## Режимы и управление

Поддерживаются 320×200 моно, 640×200 моно на 601А, 320×200 с четырьмя
цветами, 320×200 с 256 цветами и HAM8. Редкие форматы 80×200 и 160×200
не включены в редактор. Начальный холст — 320×200 с 256 цветами;
F6 меняет его формат.

Левая кнопка рисует, правая стирает цветом фона, средняя берёт цвет
пикселя. Есть кисть, линия, прямоугольник, закрашенный прямоугольник
и пипетка. Линия и прямоугольники фиксируются при отпускании кнопки.

| Клавиша | Действие |
| --- | --- |
| F1 | Справка |
| F2 / F3 | Сохранение / открытие |
| F4 | Выбор цвета; для HAM8 ввод RGB666 |
| F5 / F6 | Инструмент / новый рисунок |
| F7, Ctrl+Z / F8, Ctrl+Y | Undo / Redo |
| F9 / F10 | Меню / выход |
| + / − | Размер кисти от 1 до 16 |
| Стрелки, пробел | Перемещение указателя и включение рисования с клавиатуры |
| Z | Масштаб 1× / 2× / 4× / 8× вокруг указателя |
| G, I/J/K/L | Сетка, прокрутка вверх/влево/вниз/вправо |
| S / B | Выделение прямоугольника / кисть |
| Ctrl+A / Ctrl+D | Выделить всё / снять выделение |
| Ctrl+C / Ctrl+X / Ctrl+V | Копировать / вырезать / вставить у указателя |


Окна используют знакогенератор и общие с NC процедуры ввода, рамок,
кнопок и фокуса. Ввод текста принадлежит открытому диалогу. В графике
указатель рисует аппаратный спрайт; его 16×16 форму загружает программа.
Инициализация PS/2 и команды F6/F4/F5 выполняются программно.

В режиме 256 цветов F4 показывает сетку 16×16. Клик по квадрату либо
стрелки и Enter выбирают цвет кисти и возвращают к рисованию; Esc оставляет
прежний цвет. F5 выбирает инструмент. В HAM8 F4 принимает шесть hex-цифр
RRGGBB с компонентами 00..3F: `3F0000` — красный, `003F00` — зелёный,
`00003F` — синий, `3F3F3F` — белый.

Масштаб и рамка выделения выводятся в отдельный кадр графической SRAM.
Исходный документ и обычное изображение для Undo остаются неизменными.
Левая кнопка в инструменте выделения задаёт прямоугольник, правая снимает
его. Cut/Paste — отдельные операции Undo/Redo; вставка обрезается по краям.
Буфер содержит канонические индексы или полные RGB666-тройки HAM8.
Открытие и создание другого рисунка очищают буфер PAINT.

Сетка появляется при ширине увеличенного пикселя от четырёх экранных
отсчётов: 4×/8× для 320 точек, 8× для 640-точечного монохромного холста.
Выделение в 640×200 включает 2×, чтобы можно было выбирать отдельные
пиксели. При возврате к 1× в этом формате рамка снимается.
F9 также предлагает масштабирование, Copy, Paste и снятие выделения.

## Файлы

PCX: чтение однобитных планарных изображений с 1–4 плоскостями,
упакованного двухбитного и восьмибитного индексного изображения.
Принимаются подходящие размеры холста и RLE; учитывается дополнение
строк. Запись — 1 бит для моно, две плоскости для четырёх цветов и
8 бит для 256 цветов. Индексы и шестибитные компоненты палитры
сохраняются точно.

HAM8: IFF ILBM с BMHD, CMAP, CAMG и восемью плоскостями BODY;
чтение без сжатия или с ByteRun1. Допускаются неизвестные блоки,
нечётные размеры с дополнением и разный порядок блоков. Произвольная
64-цветная CMAP преобразуется в канонический RGB666. Запись создаёт
несжатый ILBM с RGB222 базовой палитрой и тем же HAM-кодированием,
которое используется для просмотра. HAM может приближать исходный
RGB-цвет: сохранённый IFF содержит видимый результат этого кодирования.

Открытие читает рисунок в отдельную область графической SRAM, проверяет
файл и готовит изображение для вывода. Текущий документ заменяется
после завершения этой работы. При ошибке или отмене восстанавливаются
его формат, палитра и модуль вывода.

Сохранение сначала создаёт уникальный `PNTxxxx.TMP` в том же каталоге.
После записи и закрытия существующий файл переименовывается в
уникальный `.BAK`, затем публикуется временный файл. Ошибка публикации
вызывает обратное переименование. Если сам носитель не позволяет
выполнить восстановление, исходные данные остаются под именем `.BAK`.
Отмена до публикации не меняет исходный файл.

## Память и модули

Код рисования и файловых операций собирается как два стандартных PGM
с общей BSS. Списки объектов — `PAINT.LNK` и `PNTFIO.LNK`; `.EDO`/`.FIO`
содержат обычный OBJ. Общие процедуры NC, клавиатуры и мыши линкуются
из `PNTCOM.LIB`. `UniLD -z 17000` задаёт одинаковое начало BSS; сборка
проверяет адреса состояния и постоянных обработчиков IRQ/ввода.

Резидентный `PNTBOOT.PGM` из `PNTOVL.ASM` заранее кэширует и проверяет
оба PGM, затем меняет только код, сохраняя BSS, документ и живые выделения
памяти. Смена не обращается к диску. При единичной ошибке переноса
восстанавливается код рисования, после чего он показывает ошибку.
512 байт уже ненужных аргументов/пути префикса служат файловым буфером.
`UniLD -b` объединяет префикс и два PGM в готовый `PAINT.PGM`.
Для установки нужны сам PAINT и прежние три модуля, дополнительных
файлов с кодом на диске не требуется.

Документ, Undo, подготовка открываемого файла, изображение экрана,
снимки нативного экрана и палитра находятся в отдельной графической
SRAM. В обычной ОЗУ остаются строки, палитра, управляющие данные и код.
При запуске из нативной графики используется уже выделенный видеобуфер.
При запуске из текста редактор выделяет свой буфер 8000/16000 байт.
Начало нативного видеобуфера выравнивается на восемь байт: CRTC хранит
адрес в единицах восьмибайтовых знакомест. Младшие три бита адреса кода
и обычных данных могут быть произвольными.

Карта графической SRAM:

| Адрес | Назначение |
| --- | --- |
| 100000 / 110000 | Текущее изображение и Undo для расширенной графики |
| 120000–14EE00 | Канонический документ, до 192000 байт |
| 150000 | Выбор цвета, временный native Undo и первый увеличенный кадр |
| 160000–18EE00 | Канонический Undo; базы документа и Undo меняются местами |
| 190000–1BEE00 | Буфер выделения; при Open — подготовка нового документа |
| 1C0000–1CF9FF | Подготовка при Open и второй увеличенный кадр |
| 1CFA00–1CFCFF | Палитра для отката открытия |
| 1D0000–1D3FFF / 1E0000 | Исходный нативный экран / подложка диалога |
| 1D4000–1DFFFF | Проверенные неизменяемые PGM рисования и файловых операций |
| 1F0000–1F1FFF | Исходная таблица PAL |
| 1F2000 / 1F6100 / 1FA200 | Проверенные PGM модулей NAT / RGB / HAM |

Кэш модуля заполняется при первом обращении. До освобождения работающего
модуля проверяются заголовок, дескриптор и все релокации нового PGM.
Повторная загрузка и откат используют кэш без дискового ввода-вывода.
Исполняемый модуль занимает одну арендованную страницу RAMMAN либо
обычную память. Загрузчики складывают полный 16-битный адрес релокации,
поэтому дополнительное выравнивание модуля и основного кода не нужно.
Код модуля при работе не меняется.

Таблица диапазонов мазка и имена файлов с заголовком используют общие
800 байт: файловое окно сначала завершает рисование, а новый мазок
инициализирует таблицу. Ввод диалога и текст ошибки тоже используют
эту область до начала кодирования файла. Загрузчик модуля и построитель
палитры используют буфер строки,
который во время загрузки ещё не содержит декодируемого изображения.
Окна собираются из общего с NC исходника с выключенными неиспользуемыми
цветными и числовыми процедурами; весь код NC сохраняет полный вариант.

У каждого сменяемого PGM 17000 байт кода; BSS общая. Точные размеры
BSS, резидента, обычного модуля и выравнивания контролирует
`build/paint/PAINT.json`. Видеобуфер 8000/16000 байт и стек учитываются
отдельно; запускаются также проверки наиболее тесного случая NC + HG +
601А и работы без RAMMAN.

Undo/Redo хранит целый мазок и готовое изображение, поэтому не требует
повторного кодирования всего HAM-холста. Счётчики поколений определяют,
совпадает ли документ с последним успешно сохранённым состоянием.

Кисть объединяет перекрывающиеся квадраты в диапазоны строк. HAM8
пересчитывает изменённый диапазон и его продолжение до совпадения
удерживаемого RGB с прежним изображением; предыдущий базовый цвет
служит точкой восстановления состояния. Если модуль не поддерживает
частичную строку, используется полный проход. Закрашенный прямоугольник
индексного холста заполняет документ и экран аппаратным DMA FILL.

Все переносы используют плоский DMA и его BUSY. CPU обслуживает мышь
во время ожидания и длинных преобразований. Обработчик ожидания
не запускает вложенные операции DMA или модулей. Перед освобождением
буфера редактор дожидается завершения аппаратного обращения.

## Сборка и проверка

`make paint-apps` использует UniAS, UniAR и UniLD. Выполняемый код не
создаётся и не исправляется скриптами хоста. JSON и заголовки с адресами
формируются только для контроля ресурсов и тестов.

Проверки: `test-paint-backends`, `test-paint-loader`, `test-paint-canvas`,
`test-paint-ui`, `test-paint-files`, `test-paint-hg` и `test-paint-overlays`. Они выполняют
настоящие PGM в нативном UniDOS
с моделями 601/601А и CPU MC6800/HD6303. Декодеры PCX и ILBM на хосте
независимо проверяют файлы, записанные нативной программой.
Проверки окон читают начало экрана из настоящих регистров CRTC и сравнивают
все восемь строк символов с ROM-шрифтом. `run_paint_dialog_video.py`
прогоняет снимки RAM и CRTC окон F5/Esc через production video RTL,
сверяя каждый пиксель обоих PAL-полей для 601 и 601А.
Проверяется также запуск через настоящий резидент HG с его расходом
обычной ОЗУ, в том числе из NC, а также отказ при нехватке памяти.
`tests/run_native_firmware.py` собирает все объекты,
библиотеку и готовый контейнер нативными UniAS/UniAR/UniLD и сравнивает
их побайтно с кроссовой сборкой.

Проверка сменяемого кода выполняет реальные Save/Open, увеличение и сетку,
рисование по увеличенному экрану, выделение в обоих направлениях,
Copy/Cut/Paste с обрезкой и Undo/Redo. HAM8 сверяется с независимым полным
перебором команд кодировщика. Вводится единичная ошибка DMA при замене
кода, проверяется восстановление документа и возврат к редактированию.
Проверяются оба CPU, обе модели, старт из текста/графики, отсутствие
RAMMAN и банки, занятые другим владельцем.

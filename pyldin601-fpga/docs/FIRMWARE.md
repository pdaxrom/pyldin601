# Исходники и состав ПЗУ

Системные BIOS 601 и 601А находятся в `firmware/bios/BIOS.ASM` и
`BIOS_A.ASM`. UniBIOS 3.02 собирается целиком из `UNIBIOS.ASM`/`FONT.INC`;
UniDOS — из `UNIDOS.ASM`, оболочка страницы F — из `UNISHELL.ASM`.
Исходники передаются UniAS без переписывания генератором.
CHECKSUM вычисляет UniAS; контейнер P601BOOT дополнительно защищён CRC32.

## Страницы рабочего комплекта

| Page | Physical SRAM | Содержимое |
|---|---|---|
| 8 | 10000..11FFF | UniBIOS 3.02, монитор, родной шрифт |
| 9 | 12000..13FFF | Штатная страница YGPascal |
| A | 14000..15FFF | SDPARTS, INT E1, разделы и дисковые драйверы |
| B | 16000..17FFF | FPGABIOS, INT E0/E2, PS/2 переводчик |
| C | 18000..19FFF | Штатная страница UniDOS |
| D | 1A000..1BFFF | Штатная страница YGPascal |
| E | 1C000..1DFFF | RAMMAN INT E5, GAMEBIOS INT E6 |
| F | 1E000..1FFFF | UniShell INT01/E3: вся сжатая оболочка и декомпрессор |
| BIOS | 20000..20FFF | BIOS 601 либо 601А, 4096 байт |
| FONT | 21000..217FF | Загружаемый видеошрифт, 2048 байт |

Page 8..F отображаются в CPU C000..DFFF. Выбор page/group и защита ROM —
[MEMORY.md](MEMORY.md). Векторы страниц устанавливает native BIOS.
Публичные новые службы — [FPGA-BIOS.md](FPGA-BIOS.md),
[RAM-MANAGER.md](RAM-MANAGER.md), [GAMEBIOS.md](GAMEBIOS.md).

Первичный BIOS FPGA — отдельные 8 КиБ EBR, `firmware/boot.asm`/`setup.asm`.
Его нельзя обновить заменой P601.ROM на SD: нужна сборка FPGA.
LOADER.BIN из `firmware/loader.asm` работает по 2000 в RAM.
Замена ROM на SD применяется при полном bootstrap/включении;
warm Reset использует уже загруженный ROM. [BOOT.md](BOOT.md).

## Сборка и исходные данные

```sh
make -f firmware/Makefile all UNIAS=/path/to/hd6303-toolchain/unias
```

C `tools/firmware_data.c` создаёт данные PAL/AY, таблицы клавиатуры,
packed UniShell, PGM-заголовки/manifest и метки из листингов. Он не
кодирует CPU-инструкции. ROM/PGM собирает UniAS; производные данные
имеют сохранённый исходник. Конвертер IFF тоже работает с изображением,
не с исполняемым кодом. Штатные страницы YGPascal/UniDOS берутся из
native-комплектов; новый UNIBIOS.ASM не включает бинарные фрагменты монитора.

BIOS*.ASM, UNIDOS.ASM и MEMORY.INC сохраняют исходную однобайтовую
кодировку. Не перекодировать их литералы в UTF-8. FONT.INC содержит
256 символов по 8 байт; для EBR меняется только порядок адресации.
Документация docs — UTF-8, не кодировка строк прошивки.
Результаты, листинги и логи остаются в build. [Команды и тесты](BUILD.md).

## UniShell в одной ROM-странице

UniAS собирает UNIDOS.ASM в SHELL.CMD, 10001 байт. C `firmware-data shell`
создаёт SHELL.PACKED/SHELLPACK.INC; UniAS включает packed **данные** вместе
с исходным декомпрессором UNISHELL.ASM в страницу F 8192 байта.
Системный BIOS сначала выполняет родной загрузочный сектор выбранного
диска. При отсутствии такого сектора вызывает зарегистрированный INT01:
UniShell восстанавливает оболочку в RAM 1000..3710 и запускает её по 1000.
E3 остаётся отдельным входом распаковщика; BIOS не требует его наличия.
SDPARTS только монтирует разделы. Вся сжатая оболочка и декомпрессор
находятся в странице F. UNIDOS.CMD на диске может быть другой версией;
обновление ROM не заменяет этот файл. [Порядок загрузки](BOOT.md).

Используется внутренний LZ-формат оригинального Uniload из
`native/RAMROMDiskPipnet/str$0a.roz`; gzip .roz — контейнер эмулятора,
не формат выполняемого ROM-декомпрессора.

| Управляющие биты, LSB first | Токен |
|---|---|
| 1 | Один literal байт |
| 00 и два бита | Повтор 2..5, отрицательное 8-битовое смещение |
| 01 | Отрицательное 13-битовое смещение, длина 3..9 |
| 01 с полем длины 0 | Дополнительная длина до 255; 0 завершает поток |

Управляющие слова по 16 бит, окно 8192, перекрывающиеся повторы разрешены.
На границе управляющего слова следующий control читается до данных
текущего токена. Упаковщик выбирает разбиение динамическим программированием
по битовой цене и проверяет побайтную распаковку. Текущая оболочка:
7535 packed + 223 header/decompressor + 1 checksum = 7759 байт,
свободно 433. Размеры проверяет сборка, не ручной патч числового адреса.

Декомпрессор временно использует SP для чтения ROM/back-reference с IRQ
запрещённым. Сохраняет 14 байт 0080..008D на обычном стеке, восстанавливает
их, SP и флаги до возврата. E6F0/E6F1 обслуживает BIOS. Распаковка однократная
при запуске UniDOS, не при каждой команде оболочки.

## Приватные службы и совместимость

Расширения используют системный API BIOS/UniDOS. Обязательная связь между
нашими независимыми расширениями допускается внутри одной пары 16 КиБ:
SDPARTS/DIRECTSD занимают A/B. RAMMAN/GAMEBIOS собраны в одной странице E.
Номера в таблице описывают штатную раскладку, а не адреса вызова служб.

Основные BIOS сами регистрируют E8 и координируют запуск: проверяют
наличие E1 и ядра UniDOS, вызывают E1 A=7 для монтирования, затем пробуют
дисковый сектор A55A по 0150 и зарегистрированный ROM-вход INT01.
При отсутствии/ошибке обязательной службы выводится
BOOT-сообщение; при наличии INT30 открывается монитор, иначе BIOS ожидает
Reset. SDPARTS проверяет наличие E2 до выделения своей рабочей памяти.

GAMEBIOS выполняет COPY/SPRITE непосредственно через MMIO и собственные
переменные контекста. Он не вызывает E0. Клавиатурный IRQ выбирает страницу
по вектору E7; музыкальный IRQ и дисковые драйверы регистрируют фактическую
страницу собственного кода. Оба регистра страниц восстанавливаются BIOS.

UniShell не вызывает E5/E6 при завершении процесса. Приложение само
закрывает GAMEBIOS и освобождает выделения RAMMAN до INT38, включая
ошибочные выходы. Автоматических обработчиков расширений в оболочке нет.
`make test-rom-modules` проверяет отсутствующие ROM, независимость служб
и перестановку половинок A/B и E/F на 601/601А, MC6800/HD6303.

Клавиатурный E7 — приватный указатель на 64-байтовое resident-состояние,
не публичная SWI-функция. RAMMAN использует собственные 240 байт.
GAMEBIOS ABI 2 — контекст приложения 416 байт и один банк PAL через E5.
INT E8 в постоянном BIOS переносит банки/PAL без процедуры в ОЗУ.
Чужие временные переменные
BIOS/UniDOS для этих состояний не заняты.

Оба BIOS сохраняют E6F0/E6F1 при IRQ/NMI/SWI, сохраняя исходное расположение
кадра для старых обработчиков. E6F1 кодируется адресом возврата обработчика
через продолжения из `firmware/memory/ROMRETURNS.INC`; дополнительного байта
между E6F0 и аппаратным кадром нет. Абсолютные публичные входы сохранены.
Старые графические/музыкальные вызовы работают с native-режимами и beeper;
новое приложение выбирает E6 явно. HD6303 ISA не меняет карту на Lilith.

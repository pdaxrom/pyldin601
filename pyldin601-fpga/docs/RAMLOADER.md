# ramloader: системные ROM-модули в RAMMAN

`RAMLOAD.PGM` загружает 8192-байтовые ROM-образы с любого диска UniDOS
в выделенные RAMMAN-банки. Код работает по C000–DFFF через обычные SWI.
FPGA и карта памяти не меняются. Нужен обновлённый ROM RAMMAN с функциями
E5 A=4/5; прежний ABI 1 и функции 0–3 сохранены.

## Запуск

```text
E:RAMLOAD E:CRC16.ROM
E:RAMCHECK
E:RAMLOAD /L
E:RAMLOAD /U CRC16
```

`RAMCHECK` должен вывести `PASS: banked ROM CRC16 = 29B1`.
Имя при выгрузке берётся из восьмибайтового ROM-заголовка, а не имени файла.
`LIST` и `UNLOAD NAME` — синонимы `/L` и `/U NAME`.
`/CVM` автоматически загружает ZVM6800.ROM либо ZVM6303.ROM рядом с
RAMLOAD.PGM по выбранной ISA. Повторная команда использует установленную
VM после проверки шлюза/ABI/CPU. [Small-C и нативные инструменты](CVM.md).
Список показывает имя, физический банк, группу `g` и страницу `p` в hex.
В UniDOS действует 8.3, поэтому имя утилиты ramloader на диске — RAMLOAD.

Первый успешный LOAD создаёт резидентную таблицу: его надо выполнять из
основного приглашения UniDOS до запуска NC и других вложенных программ.
Нативный INT2C устанавливает общую границу постоянной памяти; установка
из дочерней программы закрепила бы также её родителей. Такой первый
запуск отклоняется ($56). После создания таблицы LOAD/LIST/UNLOAD работают
и из вложенных программ; новые постоянные области при этом не выделяются.
Пустой LIST, ошибочные LOAD и просмотр справки ничего не устанавливают.

На проверенном дисковом UniDOS 3.20 постоянный расход — около 1,1 КиБ
обычной ОЗУ, включая накладные расходы штатного аллокатора. Таблица имеет
четыре повторно используемых слота, до восьми SWI-служб на модуль.
Каждый загруженный модуль дополнительно занимает один банк 8 КиБ.
После последней выгрузки маленькая таблица остаётся до Reset. При Reset
BIOS перестраивает векторы и RAMMAN; модули надо загрузить снова.

## Поддерживаемый ROM

Образ имеет штатный заголовок страницы:

| Смещение | Содержимое |
|---|---|
| 0 | A55A или 5AA5, BE16 |
| 2 | Имя, 8 печатных однобайтовых символов; справа пробелы |
| 10 | JMP на инициализатор внутри C000–DFFF |
| 13 | Штатный вход версии |
| 16 | Записи `SWI U8, адрес BE16`, завершённые нулём |

Размер строго 8192, сумма всех байтов по модулю 256 — ноль. Разрешено
1–8 различных экспортов 80–FF, кроме EC, E4 и E7. EC занят обнаружением
ramloader; E4/E7 имеют специальный IRQ ABI. Уже занятые SWI не заменяются.
Адреса инициализации и экспортов должны находиться в C000–DFFF.

Код собирается на C000, не пишет в собственную страницу и не предполагает
фиксированных E6F0/E6F1. Изменяемые данные и стек находятся вне окна.
INIT вызывается через C00A: A=B=0, X указывает на восемь обнулённых байтов
постоянного контекста модуля. Он возвращается RTS, записав результат в
SWI A ($06): ноль — успех. INIT не выделяет внешние ресурсы, не меняет
векторы и не вызывает INT2C; весь необходимый ему постоянный контекст
предоставлен загрузчиком. При неуспехе он сам отменяет внешние действия.
Выгрузка освобождает предоставленный контекст и банк.

Обработчики используют родной SWI ABI: входные A/B/X — в регистрах,
выходные CCR/B/A/X — по $04/$05/$06/$07. Возврат RTS; вложенные SWI
разрешены. Обработчик обязан вернуться обычным RTS, без INT38 и других
нелокальных выходов. Шлюз сохраняет группу и полный байт страницы на обычном стеке,
поэтому вложенные вызовы не делят переменные переключения. BIOS отдельно
сохраняет селекторы при IRQ/NMI/SWI. Счётчик активности запрещает выгрузку
исполняемого модуля. Изменённый другим кодом вектор также блокирует выгрузку.

`CRC16.ROM` — рабочий пример: INT ED A=0 сообщает ABI 1, B=1, X=8;
A=1, X → `sourceBE16, lengthBE16, seedBE16, resultBE16` вычисляет
CRC-16/CCITT-FALSE (полином 1021, обычная ОЗУ 0100–BDFF). Все временные
данные находятся на стеке. `CRCALT.ROM` использует EE; его A=2 вызывает
ED и проверяет вложенное исполнение разных RAM-банков.

Перенос старого ROM требует проверки этого соглашения. Жёсткие номера
ROM-страниц, запись в ОЗУ под ROM и самостоятельная регистрация IRQ
автоматически не преобразуются. В этой версии один файл — одна страница.

## Загрузка и откат

PGM состоит из маленького префикса и вложенного стандартного PGM с CLI.
Префикс читает relocations блоками по 64 байта. CLI использует один обычный
512-байтовый буфер: DOS никогда не читает прямо в банковое окно.
При чтении сохраняются и восстанавливаются оба селектора.
Рабочий код временно устанавливает обработчики BREAK и критических ошибок:
ошибка чтения возвращается в откат, BREAK запрашивает отмену после текущего
блока. Старые обработчики восстанавливаются до освобождения рабочего кода.
До регистрации проверяются длина, checksum, заголовок, имена, экспорты,
отсутствие конфликтов и успешная инициализация. Затем lease закрепляется
E5 A=4 и публикуются шлюзы со страницей 0. CLI освобождается; при первом
успехе освобождается также код и буферы префикса перед резидентным хвостом.

UNLOAD проверяет активность и все векторы, временно отключает IRQ,
восстанавливает прежние пустые векторы и освобождает lease через E5 A=5.
Если освобождение отклонено, шлюзы устанавливаются обратно. Обычная
очистка процесса E5 A=3 не затрагивает закреплённые банки.

| Код hex | Значение |
|---|---|
| 04 | RAMMAN отсутствует |
| 50 | INT EC уже занят другой службой |
| 51 | Неверный размер/checksum/заголовок/экспорты ROM |
| 52 | Запрошенный SWI уже занят |
| 53 | Модуль с этим именем уже загружен |
| 54 | Все четыре слота заняты |
| 55 | Модуль исполняется или его вектор изменён |
| 56 | Первый LOAD запущен из вложенной программы |
| 57 | Старый RAMMAN без PIN; обновить ROM-комплект |
| 58 | Имя модуля не найдено |
| FF | Загрузка отменена через BREAK |

Остальные коды — ошибки DOS, RAMMAN либо инициализатора.

## Сборка и испытания

```sh
make ramloader-apps UNIAS=/path/to/unias
make test-ramloader UNIAS=/path/to/unias
make test-ram-manager UNIAS=/path/to/unias
```

Результаты — `build/ramloader`: RAMLOAD.PGM, CRC16.ROM, CRCALT.ROM,
RAMCHECK.PGM, RAMLOAD.TXT и листинги. Обновлённые ROM-контейнеры для
601/601А — `build/rom.reference` и `build/rom-a.reference`; устанавливаются
как P601.ROM/P601A.ROM на загрузочный раздел и применяются при полном
bootstrap, не при тёплом Reset. Пересборка FPGA не нужна.
Тесты используют частные копии SD, реальный UniAS/BIOS/UniDOS и обе ISA.
Рабочий `images/sd.img` и физическая карта не изменяются.

15 октября 2026 года на реальной плате pyldin601-fpga подтверждены загрузка
`CRC16.ROM` в RAMMAN через `RAMLOAD` и успешное выполнение `RAMCHECK`.
Проверка выполнена после обновления обоих ROM-контейнеров на SD и полного
перезапуска питания.

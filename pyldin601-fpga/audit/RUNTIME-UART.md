## Независимая проверка BIOS

`RAM_DIAGNOSTICS=2` в board top включает запись UART в обычной системе.
Дополнительные 4 EBR содержат независимую копию BIOS. Она инициализируется
из native BIOS и обновляется каждым принятым boot-write диапазона
60000–60FFF, до внешней SRAM. Warm reset её сохраняет.
Каждое завершённое runtime-чтение CPU F000–FFFF сравнивается с этой копией.
Несовпадение замораживает CPU до falling edge, сохраняет адрес/байты и
последние 256 обращений CPU, затем выдаёт их в UART. Проверка не подменяет
данные CPU и не проверяет всё содержимое base RAM/ROM-банков.

## UART второго канала FTDI

TX pin132, RX pin133, Linux `/dev/ttyUSB1`, 115200 8N1.
Раз в секунду выдаётся пакет состояния. Команда H/h замораживает CPU и
выгружает кольцевую трассу; применять её при наблюдаемом зависании.
Reset снимает заморозку. Приём без команд не вмешивается в CPU или SD.

Пакет: ASCII P601, тип S/T, длина payload в big endian (2 байта), payload,
XOR8 всех байтов payload. S имеет 32 байта, magic BUS1. Поля: ticks 24 MHz,
число записей трассы, причина (0 normal, 1 BIOS mismatch, 3 host halt),
адрес и expected/actual, текущий FDC LBA, CPU address/in/out, golden byte,
page, mode, последний прочитанный MSR, boot stage, CPU flags, phase, SD flags.
T: хронологические 32-битные записи, little endian; address16, data8, flags8.
CPU flags: RW, IRQ, hold, reset, memory busy, complete, issued, VMA (7→0).
SD flags: ready, initialized, error, raw owned, raw busy, boot mode, locked,
PLL locked (7→0). Декодер — `tools/capture_runtime_uart.py`.
При утрате PLL/power эти регистры тоже сбрасываются; trace не сохраняется
через такой reset. Пакеты до события сохраняются на Linux.

сохраняются; MSR здесь является последним прочитанным значением, а не текущим

## Исправление переноса адресов видео, прошито 3 октября

Обнаружено отдельное расхождение с оригинальным `mc6845.c`: 16-битное
сложение адресов экрана в RTL переходило через FFFF к базовой RAM с адреса 0.
Оригинальный текстовый renderer после FFFE возвращается к F000; графический
перед ячейкой FFF8 возвращается к 0. Исправлены начало следующей строки,
последовательные SRAM-read адреса и сравнение физического адреса курсора.
Carry сохраняется до применения wrap. Произведение номера строки на stride
регистрируется, чтобы расчёт wrap/курсора укладывался в период 24 MHz.

На прежнем RTL новый эталонный кадр с началом FF00 падает на y=48,x=27.
Текущий RTL совпадает с оригинальным renderer на 384000 пикселях шести кадров:
обычный текст/графика, перенос внутри кадра, начальные FFFF/FFF8 и курсор
после переноса. Все RTL-тесты проходят; журнал
`build/video-wrap-final-regression.log`. Это исправление влияет только на
чтение видео и не установлено как причина прежних CPU reset/повреждения RAM.

## Электронный диск удалён, 3 октября

По запросу пользователя удалены 19-битный адресный счётчик, его обновление
по завершению SRAM-запроса и выбор физического адреса диска перед CPU bus.
E680–E683 возвращают FF; записи не меняют состояние и не запрашивают SRAM.
Область 80000–FFFFF не используется. Новый loader не очищает её; старый
loader на физической карте продолжает работать благодаря немедленному
подтверждению boot-портом без SRAM-запроса. Этап 0A — `ROM DISK DISABLED`.
ROM-банки, BIOS, font, SD/FDD и расписание CPU/video не изменялись.

Проверки: 20 RTL cases; каждый из 524288 байтов legacy clear даёт ноль
SRAM-запросов; два SRAM-audit прогона с разными pad skew проверяют
150000 CPU-циклов, 2342 чтения/2349 записей отсутствующих портов без SRAM
grant, полную сохранность 1 МиБ и 24 фазы warm reset. Новая прошивка
исполняется на C-модели с SDHC/SDSC/фрагментацией/ошибками; прежний
`sd-text.img` тоже загружается без изменения исключённой области.
Оригинальное C-ядро/BIOS с отключёнными портами выполнило 32 DIR и вернулось
к промпту каждый раз. Это проверка эмулятора, не физического VHDL CPU.
Логи: `build/no-edisk-{rtl,firmware,legacy-sd,native-dir}.log`.
Счётчик/мультиплексор диска отсутствуют в текущих RTL и synthesis netlist.

`build/diamond/source-no-edisk.tar.gz`, `.sha256.json`.
FLASH Verify ID и Erase,Program,Verify прошли; JTAGENB высокий до/после.

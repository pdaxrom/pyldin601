# Арбитраж SRAM после рефакторинга, 3 октября 2026

Физическая проверка этой сборки завершилась неудачей: третий DIR завис,
индикатор R/S/R сменился очисткой экрана и перезапуском. Ниже описаны
изменения и проверки сборки ram-arbiter. На следующем этапе использовалась
[UART-диагностика](RUNTIME-UART.md), затем найдены и исправлены
[ошибки CPU](CPU-CONFORMANCE.md). После исправления пользователь подтвердил
DIR без сбоев и работу электронного диска. Текущая версия —
[601/601A](MODELS.md), без аппаратной отладки; расписание SRAM сохранено.

Обычная прошивка использует отдельные адаптер CPU, арбитр и контроллер
физических выводов SRAM. Сравнена рабочая реализация uJ11
`uj11-ebr-audit-20261001/sources/boards/hc7000/uj11_sram.v` и
`video/uj11_video_arbiter.v` на разрешённой Linux-машине.
Из неё перенесена последовательность setup → два access-такта → hold →
release. Протокол Пълдина сохраняет одно принятое обращение и одну выдачу
завершения; его слоты рассчитаны для непрерывной работы MC6800 на 1 МГц.

`classic_cpu_bus.v` принимает цикл CPU на фазе 2: сохраняет физический
адрес, направление, данные и признак доступа к электронному диску.
I/O получает один строб на цикл. Запрос SRAM остаётся до accept;
после accept новый запрос не возникает до done. Результат SRAM хранится
в отдельном `cpu_in`; последующие видеочтения его не меняют. Адаптер
работает от system clock 24 МГц, захват MC6800 происходит на falling edge
зарегистрированного CPU clock, через полпериода system clock после фазы 23.

`memory_arbiter.v` единолично назначает runtime-слоты. Владельца, адрес,
данные и направление принятого запроса он сохраняет до завершения,
даже если клиент снял запрос или сбросился. В boot-режиме используется
round robin между CPU, boot-портом и видео. Runtime boot-порт исключён.
Одновременного done и нового accept нет, позднее завершение не относится
к следующему владельцу.

| Фаза system clock | CPU-слот |
|---|---|
| 2 | Захват цикла CPU / единственный I/O-строб |
| 3 | Accept; адрес, CE, byte lanes и данные, OE/WE пока высокие |
| 4 | OE низкий для чтения либо WE низкий для записи |
| 5 | Первый access-такт |
| 6 | Чтение SRAM в регистр либо подъём WE после двух тактов |
| 7 | Освобождение CE/OE/lanes и выхода DQ после hold |
| 8 | Done контроллера SRAM, возврат контроллера в idle |
| 9 | Завершение арбитра; адаптер сохраняет данные CPU |
| 10–16 | Первое видеочтение по той же последовательности |
| 17–23 | Второе видеочтение |
| Следующий полутакт | Falling CPU clock; CPU получает сохранённый результат |

WE низкий 83.3 ns вместо прежних 41.7 ns. Ограничение выходных задержек
15 ns оставляет не менее 68.3 ns с учётом skew. Чтение выполняется через
два такта после OE; OE снимается только через следующий такт после захвата.
Адрес и данные не меняются во время активной записи. Между владельцами
предусмотрено освобождение шины. Кнопочный reset прекращает новые запросы
и дожидается завершения принятых SRAM-записей; lock/ROM сохраняются.

## Проверки сборки ram-arbiter

- Арбитр: 30000 тактов с одновременными/снимаемыми запросами, переменной
  задержкой backend, сменой адресов/данных после accept и 94 сбросами во
  время обращения. Проверены соответствие каждого done владельцу,
  отсутствие потерь/дубликатов, boot fairness и runtime slots.
- Полная модель CPU/video bus: 148852 доступа CPU, 67078 видеочтений,
  74986 физических записей и 150436 захватов CPU. Каждое чтение сравнивается
  с независимой physical-memory моделью; каждая запись — с принятым адресом,
  byte lane и данными. В конце проверен весь используемый 1 MiB SRAM.
  Проверяются ROM-банки/страницы и BIOS overlay, RAM под ROM, электронный
  диск с заворотом адреса и warm reset на каждой из 24 фаз.
- Та же проверка повторена с противоположным skew: 15 ns address/data/control
  и 3 ns WE, затем 1 ns address/data/control и 15 ns WE. SRAM access 20 ns.
- `tb_sram_stress`: 100000 CPU-циклов, 44800 видеочтений, 1120 строк,
  сохранность base 64 KiB; без hold в момент захвата CPU и без пропуска
  дедлайна видеостроки. Отдельно проверен PAL renderer против эмулятора.
- Настоящее VHDL-ядро с штатным BIOS на вводе времени: 20 натуральных PAL IRQ,
  RTI и переход через 02:00:00, RAM сравнивается с оригинальным эмулятором,
  старый экранный заголовок сохраняется; 172800 видеочтений.
- `make test`: CPU differential, устройства, software SD boot, CRC/FAT,
  warm reset, клавиатура/раскладки и handoff прошли.

Логи: `build/ram-arbitration-audit/final-regression.log`,
`runtime-sram-final.log`. Сквозной тест DIR сохраняет отдельный журнал
`dir.log`; проверка завершилась timeout через 12 виртуальных секунд,
четыре DIR не завершились. Она не включается в результаты PASS выше.
Сохранены короткие snapshot RAM/screen и журнал `dir-short-dump.log`:
23 чтения с загрузкой UNIDOS.CMD, не совпадающие с native baseline.
Диагностическая прошивка подготовлена отдельно, но на плату после
уточнения пользователя устанавливается обычная версия.

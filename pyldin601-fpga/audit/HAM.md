# HAM8 и наложение, 12 октября 2026

Графический интерфейс v6 поддерживает HAM8 и индексные 256 цветов.
HAM6 удалён. Размер кадра остаётся 320×200 байт, доступны 16 страниц SRAM,
прежние COPY/FILL/keyed COPY и VBL FLIP. HAM8 хранит три шестибитных
компонента: 262144 RGB-состояния. Два бита команды меняют один канал,
сохраняя остальные; произвольный независимый цвет может требовать трёх команд.
Для прозрачных спрайтов поверх произвольной HAM8-картинки предусмотрено
наложение v6. [Программирование и порядок подготовки](../docs/PROGRAMMING.md#ham8-и-наложение-без-полос).

Это байтовый формат с фиксированной RGB222 палитрой и шестибитным composite
PAL DAC. Число RGB-состояний не означает 18-битный физический DAC и
не устраняет ограничение полосы PAL.

## Интерфейс

| E650 | Режим |
|---|---|
| 0 | Штатное видео 601/601A |
| 1 | 256 программируемых индексов |
| 7 | HAM8 |
| 15 | Полный HAM8-фон с RGB222 передним планом, FPGA v6 |

HAM8 выбирается только при bits 2:1=3. Остальные значения FORMAT аппаратно
дают индексный режим; INT E0 принимает только 0, 1 и 7. Чтение E650
возвращает режим и BUSY/UNDERRUN/ERROR; bit 3 обозначает наложение.
E65F возвращает версию 6. Обычный HAM8 v5, HVIEW и indexed остаются
совместимыми. INT E0 и GAMEBIOS ABI1 принимают прежние режимы 0, 1 и 7;
Xonix готовит HAM-таблицу через MODE 7, затем сохраняет **логический
MODE 1** GAMEBIOS для текста и примитивов. Аппаратные E654/E650 задают
наложение напрямую; MODE 15 в INT E0/E6 не добавлен.

| Bits 7:6 пикселя | Bits 5:0 |
|---|---|
| 00 | Абсолютный RGB222: R=bits 5:4, G=bits 3:2, B=bits 1:0 |
| 01 | Новый B6 |
| 10 | Новый R6 |
| 11 | Новый G6 |

RGB222 переводится в компоненты 0/21/42/63. Каждая физическая строка
начинается с чёрного. Масштабированные повторения одной команды сохраняют
цвет; повторные PAL-строки независимо декодируют тот же поток.

## HAM8-фон и передний план

На FPGA v6 перед E650=15 записать E654 с номером страницы полного
исходного HAM8-фона. Номер фиксируется при записи режима; последующие
E654 для COPY/READ не меняют фон. Повторная запись E650=15 фиксирует
новый источник. Показ и FLIP по-прежнему выбирают страницу переднего
плана. В ней байты 00–3F рисуют собственный RGB222 цвет, 40–FF показывают
декодированный исходный фон в тех же координатах. Значение компонента
байта переднего плана в этом случае не используется. Поэтому можно
копировать неизменённый HAM8 участок фона и перекрывать его полем,
текстом или спрайтом из 64 RGB222 цветов. Для произвольного открываемого
пикселя подходит также любой код 40–FF, например 40h. Абсолютный код
00–3F из исходника при копировании отображается как тот же RGB222 цвет.

MODE 7 рассчитывает компонентную таблицу в PAL-индексах 0–191. После
перехода GAMEBIOS в MODE 1 таблица сохраняется; индексные цвета меню
можно размещать в 240–245. Оверлей использует непосредственно RGB222
коды 00–3F, а не эти меню-индексы. Менять индексы 0–191 через PALETTE
перед показом HAM8 нельзя. Для возврата из слоя в меню достаточно MODE 1;
для следующего раунда повторный расчёт MODE 7 не требуется.

Полный исходный поток читается слева направо, включая скрытые пиксели.
Начальный цвет сбрасывается только в начале строки. Маска/спрайт не
влияет на накопленный цвет фона. Два чтения по 16 бит на пару пикселей
заменяют одно; двухстрочный кэш содержит RGB666 и занимает два EBR
вместо одного. PAL принимает готовый RGB666 через прежнюю компонентную
таблицу. E650=0/1/7 и Reset выключают наложение; формат существующих
изображений, команды блиттера и восстановление палитры не меняются.

Этот режим убирает полосы старой восьмипиксельной перекодировки Xonix.
Картинка в SRAM побайтно соответствует исходному IFF. Проверки и
сборка: `make test-ham-layers`, [отчёт](HAM-LAYERS.json).

## Таблица и конвейер

Приложение сохраняет и заменяет часть существующей PAL-таблицы вкладами
каналов: `channel*2048 + component*32 + phase`, R/G/B=0/1/2,
component=0..63, phase=0..31. Всего 6144 шестибитных отсчёта в прежних
шести EBR. CPU-порт E652/E65D/E65E/E65F работает на 24 МГц, вывод — на
имеющихся 96 МГц; дополнительный PLL или EBR для HAM не используется.

RGB6 расширяется в RGB888 как `(n<<2)|(n>>4)`. HD6303 вычисляет вклад
одним MUL на отсчёт по signed Q9 коэффициентам PALCOEF.ASM. Сумма трёх
вкладов даёт DAC-код. Перед возвратом или при ошибке восстанавливаются все
8192 прежних отсчёта. Штатный PAL использует отдельную ROM.

Четыре 96-МГц слота читают R/G/B и регистрируют сумму; полутактовый буфер
передаёт результат на 24 МГц. Native, indexed, HAM, sync и burst проходят
одинаковые три ступени выхода. DDS непрерывен; геометрия, 50-Гц IRQ и
фиксированные SRAM-слоты без HOLD сохраняются.

## Демо и проверки

`B:HAM` либо `E:HAM` через HG требует HD6303 и graphics v5+. Демо сохраняет
палитру в 8192 байтах PGM BSS, рассчитывает таблицы и строит страницу 0
аппаратным FILL. 886 байт кода/данных, 84 relocation, PGM 1070 байт.
ESC восстанавливает палитру и UniDOS. Подготовка быстрее при 8 МГц.
Сетка содержит 4096 RGB-сочетаний из 262144 возможных состояний HAM8.

```sh
make test-ham UNIAS=/path/to/hd6303-toolchain/unias
```

PAL проверяется независимо для всех 262144 RGB-состояний, 32 фаз и обоих
знаков V; максимальная ошибка матрицы 1,809914 DAC-кода, переполнения нет.
HDL-проверки также покрывают модификацию начального чёрного, базовые цвета,
масштабирование, Reset, все 6144 записи/readback и пять фаз fast clock.
Нативный тест загружает настоящий PGM/BSS через BIOS и UniDOS обеих моделей,
проверяет весь кадр, повторный запуск, ESC, произвольную исходную палитру,
MC6800/старую FPGA, ошибку FILL и последующий DIR.

`HVIEW.PGM` загружает стандартный HAM8 IFF ILBM через UniDOS.
JPEG/PNG преобразует C-конвертер `ham8conv`;
[использование и точный профиль формата](HAM-VIEWER.md).
Пользователь подтвердил цвета Лены и выход HVIEW по ESC на v5;
после установки v6 отдельно подтвердил HVIEW и отсутствие полос Xonix.
Ресурсы и текущий протокол — [DIAMOND.md](DIAMOND.md).

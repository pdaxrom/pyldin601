# UniShell в одной странице ПЗУ

UniAS собирает `firmware/bios/UNIDOS.ASM` в 10001-байтовый SHELL.CMD.
C-инструмент `firmware-data shell` сжимает его в SHELL.PACKED и создаёт
SHELLPACK.INC. UniAS собирает `firmware/bios/UNISHELL.ASM`, который
содержит весь декомпрессор, заголовок и сжатые данные страницы F.
Выполняемые инструкции не создаются и не исправляются упаковщиком.
Checksum всей 8192-байтовой страницы рассчитывает директива UniAS.

Использован формат из оригинального `native/RAMROMDiskPipnet/str$0a.roz`.
Gzip этой .roz — внешний контейнер для эмулятора. В самом ПЗУ находится
LZ-поток с 16 управляющими битами, которые читаются от младшего к старшему:

| Управляющие биты | Данные |
|---|---|
| 1 | Один буквальный байт |
| 00 + два бита | Повтор 2–5 байт, отрицательное 8-битовое смещение |
| 01 | Отрицательное 13-битовое смещение и длина 3–9 байт |
| 01, поле длины 0 | Дополнительный байт длины, до 255; ноль завершает поток |

Окно — 8192 байта; перекрывающиеся повторы поддерживаются. На границе
16-го управляющего бита следующее слово загружается до данных текущего
токена. C-упаковщик выбирает разбиение динамическим программированием
по битовой стоимости токенов и проверяет весь результат распаковкой.
Переполнение страницы, испорченные ссылки и усечённые потоки отвергаются.

Текущая оболочка: 10001 → 7540 байт. Заголовок/декомпрессор занимают
214 байт, checksum — один: использовано 7755, свободно 437 байт.
На одинаковом оригинальном SHELL.CMD из Uniload старый поток занимает
7894 байта, новый — 7541: экономия 353 байта, 4,47%.

Сохраняются заголовок UniShell и INT E3. Сервис восстанавливает всю
оболочку в RAM 1000–3710 и возвращается в загрузчик страницы A. Загрузчик
запускает её по 1000. 2001-байтовый SHELLTAIL и цикл его копирования
удалены; вместе освобождено 2049 байт. В странице A теперь свободно
3283 байта; она остаётся для служб SD-разделов.

Как в оригинальном декомпрессоре, SP читает ROM и обратные ссылки при
запрещённом IRQ. Все 14 временно используемых байт 0080–008D сохраняются
на обычном стеке и восстанавливаются вместе со SP и исходными флагами.
После TAP ожидающий IRQ может выполниться до RTS: обычный стек к этому
моменту уже восстановлен. E6F0/E6F1 обслуживаются штатным BIOS.
Распаковка выполняется разово при загрузке: около 0,94 с на 1 МГц,
0,12 с на 8 МГц по счётчику тактов эмулятора.

```sh
make test-shell UNIAS=/path/to/unias
```

Тест кодека выполняет 131 поток настоящим ASM-декомпрессором на MC6800/HD6303
с обеими начальными масками IRQ. Проверяются границы управляющих слов,
перекрытия, смещение 8192, длина 255, все флаги, разное содержимое
нулевой страницы, стек и границы результата: 524 прогона. Нативный тест загружает оба
ROM через BIOS, сравнивает весь результат INT E3 с SHELL.CMD, затем
проверяет DIR, warm Reset и работу таймерного IRQ на 601/601А с обеими ISA.

Все проверки прошли, включая усечённые/испорченные потоки, переполнение
страницы, bootstrap, выбор раздела и raw SD. Чистая сборка одних исходников
UniAS/Make/C без Python побайтно воспроизвела 11 ROM/потоков/отчётов.

Для установки требуется обновление обоих ROM на первом разделе SD.
FPGA для этой правки менять не требуется. 12 октября 2026 оба ROM записаны
на физическую SD и проверены O_DIRECT. Настройки, остальные загрузочные
файлы, 14 разделов данных и 13 таблиц MBR/EBR сохранены. Полная копия
карты — `/Storage2/pyldin601-backups/20261012-unishell/card-before.img`.
Пользователь подтвердил на плате обе модели 601/601А: загрузка UniDOS,
DIR A:/B:/C: и тёплый Reset работают без мусора и зависаний.
Ответ: «да, работают».

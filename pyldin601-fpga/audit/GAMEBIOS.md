# GAMEBIOS, SDK и Арканоид

11 октября 2026: реализованы ROM INT E6, ABI 1, библиотека тайлов/прокрутки
HD6303 и ARKANOID.PGM. Это программное расширение для **Пълдина** 601/601А.
Для удержания игровых клавиш FPGA предоставляет независимый raw FIFO
PS/2 set 2 с захватом клавиатуры. Размер контекста и GAMEBIOS ABI 1 сохранены;
Арканоид использует raw через SDK и блокирует нативные IRQ/автоповтор/клики.

## Совместимость и память

GAMEBIOS собран настоящим UniAS в странице E вместе с RAMMAN, INT E5.
Новые страницы ROM и LUT не требуются. Проверяются размер 8192 байта
и checksum; оригинальные UniBIOS, UniDOS, YGPascal и font сохраняются.
Старые INT12 (режимы 0–4), INT15/22/23, INT60–67 и INT6E/6F не
перенаправляются. Они сохраняют штатные параметры, видео и бипер.
Для новых видео, текста и AY приложение явно открывает INT E6.

При обычной загрузке GAMEBIOS не выделяет дополнительную основную RAM.
Остаются прежние 240 байт менеджера INT E5. Состояние GAMEBIOS находится
в контексте приложения, размер **8608 байт**:

| Смещение | Содержимое |
|---|---|
| 0–1 | Размер 8608, big endian |
| 2 | ABI 1 |
| 3 | Флаги: bit0 video, bit1 audio; хотя бы один |
| 4–31 | Зарезервировано |
| 32–8223 | Полная резервная копия PAL-палитры |
| 8224–8607 | Частное состояние, очередь AY и временные переменные |

Контекст живёт в обычной RAM $0100–$BDFF до CLOSE/INT38. Его нельзя
размещать в страничном окне или освобождать, пока он открыт. Активный
вектор E6 указывает на JMP в хвосте контекста; после закрытия снова
указывает на ROM. Системные переменные графики/музыки UniBIOS не заняты.
Один владелец PCB одновременно; чужое приложение и вложенный вызов
получают ошибку. UniDOS close_PCB закрывает контекст до освобождения PCB.
Ошибки открытия возвращают вектор в ROM. Неактивный CLOSE ничего не меняет.

CLOSE восстанавливает палитру, страницу показа, native video, регистры AY,
делитель, период музыкального таймера и прежний INT E4. Активный музыкальный
таймер или графическое расширение другого приложения запрещают OPEN.
Кадры framebuffer принадлежат приложению; их прежнее содержимое не
сохраняется. После завершения владельца сохранённая native-консоль видна
с прежними настройками. Расширенная RAM INT E5 и чужие банки не затрагиваются.

## ABI

Сначала INT2E проверяет присутствие E6, затем E6 A=0 возвращает
A=1, B=63 (video, text, audio, clipping, HAM8, BATCH), X=8608. INFO допустим
на MC6800. Все остальные функции требуют HD6303 ISA.
Публичные константы: `firmware/game/GAMEBIOS.INC`.

A выбирает функцию; результат A=0 при успехе. B/X сохраняются,
кроме INFO, READPIX (B=пиксель) и STATUS (B=очередь, X=счётчик тиков).
Слова в структурах big endian, координаты signed 16-bit. BIOS сохраняет
регистры страниц и CCR. Параметры/строки должны быть в обычной RAM.

| A | Функция и параметры |
|---:|---|
| 0 | INFO: версия, features, размер контекста |
| 1 | OPEN: X=контекст |
| 2 | CLOSE: восстановить устройства и освободить владение |
| 3 | MODE B=0 native, 1 indexed 256, 7 HAM8; HAM8 загружает таблицы компонентов |
| 4 | TARGET B=страница рисования 0..15 |
| 5 | FLIP B=страница показа 0..15; ожидание VBL |
| 6 | PALETTE X=index,R,G,B (RGB888) |
| 7 | PIXEL X=xBE,yBE,value; координаты вне экрана пропускаются |
| 8 | READPIX X=xBE,yBE; B=индекс, вне экрана ошибка |
| 9 | RECT X=xBE,yBE,widthBE,height,value; width 1..320, height 1..200; clipping |
| 10 | LINE X=x0BE,y0BE,x1BE,y1BE,value; Bresenham с clipping |
| 11 | COPY X=11-байтовый дескриптор E0 blit |
| 12 | SPRITE X=12-байтовый дескриптор E0 signed sprite |
| 13 | PUTC B=код символа |
| 14 | PUTS X=строка с NUL |
| 15 | CURSOR X=column,row, нумерация с нуля |
| 16 | ATTR X=foreground,background |
| 17 | WINDOW X=left,top,width,height в символах |
| 18 | SCROLL B=1..height строк вверх |
| 19 | CLEAR: очистить текстовое окно цветом background |
| 20 | NOTE X=channel,note,ticksBE,volume |
| 21 | FRAME X=14 регистров AY; R13=FF удерживает envelope |
| 22 | RATE X=BE32 период таймера, 240000..24000000 тактов 24 МГц |
| 23 | PLAY B=0 пауза, 1 воспроизведение |
| 24 | STOP: очистить очередь/эффекты и выключить звук |
| 25 | AYREG X=register,value; register 0..13, без потока кадров |
| 26 | RESERVE B=маска каналов 0..7 |
| 27 | STATUS B=число кадров в очереди, X=16-битный счётчик IRQ |
| 28 | CLOCK B=0:2МГц, 1:1МГц, 2:1773400Гц, 3:1789773Гц |
| 29 | RAWPIX X=xBE,yBE,value; допускает encoded HAM8 |
| 30 | BATCH B=0..32, X=список четырёхбайтовых команд |

Коды ошибок: 1 аргумент, 2 оборудование/таймаут, 3 требуется HD6303,
4 нет открытого контекста, 5 занято, 6 чужой владелец, 7 очередь заполнена,
8 операция не поддержана в этом режиме/контексте.

COPY: command(2 opaque/6 keyed), key, srcpage, dstpage, srcBE, dstBE,
widthBE, height. SPRITE: xBE,yBE,srcBE,widthBE,height,srcpage,dstpage,key.
Адреса — byte offset внутри страницы, stride=320. Проверки и обрезка
используют существующие E0-службы. LINE допускает конечные точки
x=-320..639, y=-200..399. Текст — штатный font 8×8, поле 40×25;
CR/LF, Backspace, перенос и прокрутка окна работают в indexed.
PIXEL/READPIX/RECT/LINE/текст не выполняются в HAM8, где байт является
командой изменения цвета; RAWPIX/COPY/SPRITE используют encoded данные.

### Пакеты графических операций и текст

GB_BATCH принимает до 32 записей `operation,B,pointerBE`. Разрешены TARGET,
PIXEL, RECT, LINE, COPY, SPRITE, PUTC, PUTS, CURSOR, ATTR, WINDOW, SCROLL,
CLEAR и RAWPIX. Список целиком проверяется на размещение в обычной RAM;
каждая операция сама проверяет свои параметры. При первой ошибке пакет
останавливается, ранее выполненные команды сохраняют результат. Нулевой
пакет ничего не делает. Пакеты нельзя вкладывать; INFO, OPEN/CLOSE, смена
режима, FLIP, палитра, чтение пикселя и аудио в них запрещены.

Один вход через SWI обслуживает весь пакет. B/X/CCR и страницы сохраняются
при успехе и ошибке, музыкальные IRQ продолжают работать. Контекст остаётся
8608 байт. Состояние пакета использует временные байты палитры, которая
запрещена внутри пакета; оно не пересекается с состоянием музыкального IRQ.
У новых ROM feature bit5=1; прежние ABI1 возвращают B=31 и не знают BATCH.
Арканоид проверяет этот бит и на прежних ROM вызывает обычные COPY.

Текст сохраняет родной шрифт, фон, переносы, окно и прокрутку. Вместо PIXEL
для каждого установленного бита рисуются горизонтальные полосы заливкой.
Проверены все 224 печатных символа, включая кириллицу. На модели 601 вывод
этого набора сократился с 2047827 до 1391673 тактов эмулятора (32%), число
графических команд — с 3484 до 2295. Это сравнение CPU/MMIO-модели,
не замер времени физического монитора. Цвета и пиксели совпадают с native ROM.

## Музыка и эффекты

NOTE: канал 0..2, нота 1=C1 ..72=B6, volume 0..15. ticks=0 удерживает
ноту; положительное значение задаёт длительность в музыкальных IRQ.
note=0,ticks=0 отпускает канал, note=0 с длительностью даёт паузу.
NOTE временно резервирует свой канал и смешивается с музыкой;
после истечения длительности канал возвращается музыкальному кадру.
RESERVE удерживает выбранные каналы; без NOTE они молчат.
Шум/envelope доступны через AYREG либо кадры. Генератор envelope общий
для трёх каналов AY; эффекты NOTE используют фиксированную громкость.

FRAME копирует готовые 14 байт в очередь на 16 кадров. Музыкальный IRQ
снимает кадр, накладывает эффекты и передаёт регистры, без SD/HG,
распаковки или переключения RAM. Пустая очередь удерживает последний
кадр без повторного запуска envelope. Пауза отключает таймер и звук,
сохраняя очередь и длительности. По умолчанию 50 Гц, clock 2 МГц.
CLOCK и RATE меняются только на паузе; CLOCK выбирается перед NOTE,
уже рассчитанный период активной ноты автоматически не пересчитывается.
Частоты AY и музыкального IRQ не зависят от CPU 1/2/4/8 МГц.
Декодеры YM/PSG/VTX/LH5 остаются в библиотеке приложения, а не в ROM.

## Тайлы и игра

`GAMESDK.ASM` и `GAMESDTA.INC` — библиотека HD6303 приложения:
sdk_open B=флаги, sdk_close, sdk_input_reset, sdk_input, sdk_tile, sdk_map, sdk_scroll.
Все возвращают A=код. Атлас — сетка 8×8 тайлов по 8×8 пикселей,
ID 0..63 в framebuffer-странице. sdk_tile X: srcpage,dstpage,ID,column,row.
Тайлы копирует аппаратный блиттер.

sdk_map X=12 байт: mapBE,mapWidth,mapHeight,cameraX,cameraY,viewWidth,
viewHeight,left,top,atlasPage,destPage. Карта содержит byte ID в обычной
RAM. Размеры/координаты в тайлах. Максимальное окно 40×25; можно задать
малое окно для перерисовки изменившейся области. sdk_scroll принимает
тот же X, B=0 left/1 right/2 up/3 down, изменяет camera, сдвигает
изображение COPY на 8 пикселей и рисует только открывшийся ряд/колонку.
На границе карты возвращается успех без изменения экрана.

`B:ARKANOID` использует страницы 0/1 для двойного буфера, 2 для атласа,
3 для статического фона. 40 кирпичей, счёт, три жизни, прозрачный мяч,
грязные прямоугольники, короткая оригинальная мелодия и эффекты AY.
LEFT/RIGHT или A/D двигают ракетку; SPACE запускает мяч, затем управляет
паузой; ESC возвращает UniDOS. После конца игры можно выйти и запустить
заново. Для игры рекомендуются 4/8 МГц; производительность полноценной
игры на физической плате при 1 МГц пока не измерена.
PGM занимает 6184 байта, код 4870, BSS 9829, RAM всего 14699 байт.
SDKTEST — 1943 байта, код 1513, BSS 8668, RAM всего 10181 байт.
Статические подписи счёта рисуются один раз; изменившиеся цифры
копируются из атласа. Очередь музыки пополняется по одному снимку STATUS.
[Замеры production HDL на 1/2/4/8 МГц](GAME-PERFORMANCE.md) показывают
сокращение кадра при попадании на 1 МГц с 301 до 42 мс.
`B:SDKTEST` автоматически проверяет карту и прокрутку: ожидается PASS.

sdk_input_reset требует status bit6 и включает эксклюзивный захват raw.
PS/2 receiver и модификаторы продолжают работать; нативная очередь,
keyboard IRQ и автоповтор очищаются/подавляются. sdk_close освобождает
захват. Запись native mode в $E650 и Reset также освобождают его;
поэтому автоматическая очистка владельца через INT38 работает с прежним ROM.
Музыкальные и PAL IRQ остаются активными. Старые программы при capture=0
получают обычную клавиатуру. FIFO без capture явно отвергается новым SDK.

При ошибке игра сохраняет и печатает OP/STATUS/RAW/GFX/AY до закрытия
контекста. OP FE означает sdk_input (STATUS=02: переполнение raw), FC —
sdk_map; остальные номера соответствуют таблице INT E6. sdk_input при
overflow уже очистил FIFO, поэтому RAW в этом случае обычно равен 40h.
Эти поля различают raw overflow, отказ аппаратной графики и другие ошибки
API. Ошибка COPY при потере мяча и оставшийся флаг, мешавший следующему
MODE, разобраны ниже; обе причины покрыты регрессионными тестами.

## Сборка и проверки

```sh
make game-apps test-gamebios test-gamebios-rtl UNIAS=/path/to/unias
python3 tools/install_game.py --image card-before.img --output card-game.img
```

UniAS формирует команды, релокации и ROM checksum. Python генерирует
только таблицы нот/данные и переносит нулевой BSS в заголовок PGM.
Инсталлятор работает с обычной резервной копией; обновляет два ROM и
указанные файлы B:, сохраняет настройки, остальные файлы, MBR/EBR и
все остальные разделы. Для raw ввода игры требуется новая FPGA;
Для BATCH и ускоренного текста обновляются оба ROM; FPGA прежняя.
Новый Арканоид также работает со старым GAMEBIOS без пакетного COPY.

Нативные проверки исполняют настоящий ROM/PGM через UniDOS на
601/601А × MC6800/HD6303: обнаружение, отказ ISA, контекст/владение,
ошибки оборудования, палитра, линии/clipping/текст/скроллинг/HAM8,
ноты/очередь/пауза/эффекты/IRQ, CLOSE и автоматическая очистка INT38.
Игра проверяется независимым сравнением каждого полного framebuffer,
включая восстановление фона, столкновения, счёт/жизни, повторный запуск.
SDK проверяет четыре направления прокрутки, границу и неверные параметры.

Производственный VHDL CPU исполняет ABI на обеих моделях: отказ MC6800,
HD6303 при 1/2/4/8 МГц, одновременный IRQ и графические вызовы,
восстановление страниц/регистров/устройств. MMIO-модель здесь проверяет
протокол, не электрический PAL. Совместимость: менеджер RAM, HVIEW,
GFXMUSIC/YPLAY и сравнение native GD с прежним ROM. GD на 601А не считается
поддерживаемым приложением; это только сравнение состояния эмулятора.
11 октября оба ROM и десять файлов игры/SDK установлены на физическую
SD: обновлены только разделы 1 и 3 (B:). Выполнено прямое чтение O_DIRECT
после записи; остальные 13 томов и 13 таблиц MBR/EBR совпадают с резервной
копией. Настройки и прежние файлы B: сохранены. Полная резервная копия:
`/Storage2/pyldin601-backups/20261011-gamebios/card-before.img`, SHA-256
`72c8612a45edf057d2fd213a410ebcb9fe150bdf65b945c2ba7a016824afa606`.
Протокол: `build/gamebios/card-installed.json`. FPGA не перепрошивалась.
Пользователь подтвердил SDKTEST PASS, игру, звук, управление, ESC,
повторный запуск и DIR на обеих моделях. Обнаруженное движение ракетки
по событиям/автоповтору заменено на raw make/break и шаг каждый кадр.
Пользователь подтвердил raw версию на плате: плавное движение,
остановку по отпусканию, SPACE и ESC.

Версия с raw PS/2 прошита в FPGA 11 октября: Verify прошёл, HG
восстановлен. Через HG установлены новая игра и SDK (10 файлов),
84 других файла сохранены. Готовый SD-образ обновлён; ROM/A/C/MBR
и остальные файлы B: побайтно сохранены. На этом этапе на физической SD
ещё оставалась первая версия игры; позднее B: обновлён через кардридер.
Карта raw регистров и протокол проверки: [KEYBOARD.md](KEYBOARD.md#raw-ps2-set-2-для-игр).

### Угол отскока мяча

Скорости теперь signed Q8.8, координаты — целые пиксели с отдельным
накопителем дробной части. Прежние семь зон и сложение с большой входящей
скоростью часто насыщали VX до одного и того же ±3; эта схема заменена.

Расстояние между центрами мяча и площадки задаёт основной VX: каждый
пиксель меняет его на 24/256 пикселя за кадр. Учитываются 1/8 входящего VX
и 48/256 действительного перемещения площадки. Встречное движение может
сделать отскок круче или изменить сторону, попутное — положе. Удержание
клавиши у границы не даёт ложную подкрутку. VX ограничен ±2,75 пикселя/кадр,
минимальная горизонтальная составляющая 0,25 исключает вертикальную петлю.
VY берётся из таблицы длиной 45 слов для скорости около 3 пикселей/кадр;
он всегда направлен вверх. Расчёт — сдвиги, сложения и таблица, без деления
или вычисления корня во время игры. Начальный вектор (1,5; −665/256).

Стена и потолок отражают свою компоненту. Боковой вход в кирпич отражает X,
вход сверху/снизу — Y; координата возвращается за грань кирпича. Площадка
ловит только пересечение сверху вниз, мяч ниже неё больше не отскакивает.

После потери жизни мяч возвращается на площадку до отрисовки и записи
истории двойного буфера. При скорости 3 пикселя за кадр он мог оказаться
на y=194; старый код сохранял эту позицию и через два кадра выполнял
COPY 8×8 за пределы 64000 байт. Контроллер отклонял запрос с GFX=11,
а игра завершалась с OP=0B/STATUS=02. Добавлены проверки быстрого и
дробного падения через нижнюю границу, обеих страниц и последней жизни.

Нативный тест настоящего PGM на обеих моделях проверяет 45 соседних точек
удара (более 40 разных углов), зеркальность, встречное/попутное движение,
скорость, накопление дробной части, границы и разные стороны кирпича.
Каждый framebuffer и счёт/жизни сверяются с независимым образцом; проверены
музыка, raw input, SPACE/ESC, повторный запуск и DIR A/B/C. Та же игра
прошла эти проверки с прежней страницей GAMEBIOS без BATCH.

Исправление потери мяча прошло нативные тесты обеих моделей с новым и
установленным прежним GAMEBIOS. Пользователь подтвердил на плате потери
мяча до конца игры, ESC и повторный запуск без Reset: вылет не повторяется.
Проверена игра из HG с прежним ROM. После установки новых ROM с BATCH

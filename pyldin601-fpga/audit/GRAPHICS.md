# Графическое расширение 320×200, 9 октября 2026

Реализован framebuffer 320×200 с 256 программируемыми цветами,
переключением страниц на границе PAL-поля и аппаратной заливкой/копированием
прямоугольников. Расширение работает с 601 и 601A, MC6800 и выбранным
расширением HD6303; частоты CPU 1/2/4/8 МГц остаются прежними.

Вывод масштабируется аппаратно в PAL-окно 48 мкс × 264 строки поля,
с сохранением framebuffer 320×200. Следующая строка загружается в другой
банк; повторяемая строка не запускает DMA. [Геометрия и проверки](VIDEO-VIEWPORT.md).
После Reset расширение выключено и виден штатный экран соответствующей модели.
Переписывать оригинальные BIOS и программы для этого не требуется.

## Демо

`GFX.PGM` — перемещаемая программа UniDOS, собранная UniAS, только с
инструкциями MC6800. Она выводит все 256 цветов, аппаратно копирует кадр,
рисует белый прямоугольник и копирует внутрь него часть первой страницы.
SPACE переключает две страницы, ESC возвращает штатное видео и UniDOS.
Демо перезаписывает только графические страницы 0/1; базовая RAM используется
обычным PGM-loader и стеком. ROM и электронный диск сохраняются.

В готовом `images/sd.img` программа, исходник и инструкция находятся на B:

```text
B:GFX
```

`B:SPRITES` — нативное HD6303-демо трёх спрайтов 32×32 с прозрачным
индексом 0. Оно использует страницы 0/1 для кадров, 2 для атласа и 3 для
неизменяемого фона. В скрытой странице сначала восстанавливаются все
прежние прямоугольники спрайтов, затем рисуются все новые позиции. Это
сохраняет правильное наложение без следов. CPU задаёт координаты и команды;
FLIP ждёт VBL. Полные копии кадра выполняются только при инициализации.
ESC возвращает UniDOS; штатная видеопамять и PAL-палитра не меняются.
Нужны HD6303 EXTENSION Y и графический интерфейс v3. Через HG: `E:SPRITES`.
[Исходник](../firmware/gfx/SPRITES.ASM), [инструкция](../firmware/gfx/SPRHOWTO.TXT).

На существующей физической SD эти файлы пока отсутствуют. Через HG их
можно предоставить в каталоге хоста, подключить диск командой `B:HG`
и запустить `E:GFX` (или с буквы, напечатанной драйвером).

## Память и цвет

Физический диапазон SRAM `100000–1FFFFF` отведён графике: 16 страниц по
64 КиБ. Страница `n` начинается с `100000+n*10000`; пиксель `(x,y)` имеет
смещение `y*320+x`. Полезный кадр занимает 64000 байт; последние 1536 байт
страницы не используются командами. Два кадра занимают 128 КиБ; оставшиеся
14 страниц можно использовать для изображений и спрайтов, копируя их блиттером.
Каждая страница может быть выбрана для показа или назначения команды.
Свободный диапазон вне графики — `061800–07FFFF`, 122 КиБ.

Байт пикселя — индекс палитры. При конфигурации FPGA таблица загружается
цветами RGB332: `RRRGGGBB`, 0 — чёрный, FF — белый. Программы могут заменить
любые из 256 цветов. PAL-кодировщик сохраняет штатные sync/burst/DDS.
256 кодов различны в цифровом тракте; видимые оттенки и горизонтальная
чёткость зависят от полосы composite PAL и телевизора. Цвет задаётся 32
шестибитными отсчётами PAL-сигнала; это сохраняет существующий DAC и его
ограничения. Версия 5 поддерживает HAM8 на той же памяти; HAM6 удалён;
[байтовые команды, таблицы и ограничения](HAM.md).

## Регистры E650–E65F

Окно проверено по native BIOS/UniDOS; E645–E647 оставлены штатному ACIA.
Все обращения байтовые. Двухбайтовые параметры передаются младшим байтом
по меньшему адресу, независимо от порядка байтов регистров CPU.

| Адрес | Назначение |
|---|---|
| E650 | Запись bit 0 ENABLE, bits 2:1 FORMAT: 3 HAM8, остальные значения indexed; чтение выбранного формата в bits 2:0 плюс bit 7 BUSY, bit 5 UNDERRUN, bit 4 ERROR |
| E651 | Команда: 1 FILL, 2 COPY, 3 FLIP, 4 WRITE BYTE, 5 READ BYTE, 6 TRANSPARENT COPY; чтение последней команды |
| E652 | Чтение: текущая страница показа; запись: младшие 8 бит адреса палитры |
| E653 | Цвет заливки / байт для WRITE BYTE / прозрачный индекс для команды 6 |
| E654 | Страница источника, 0–15 |
| E655 | Страница назначения / следующая страница для FLIP, 0–15 |
| E656/E657 | Смещение источника, low/high |
| E658/E659 | Смещение назначения, low/high |
| E65A/E65B | Ширина: low / bit 0 high, 1–320 |
| E65C | Высота, 1–200 |
| E65D | Чтение: результат READ BYTE; запись: старшие 5 бит адреса палитры |
| E65E | Чтение: 47h (`G`), либо отсчёт палитры в режиме readback; запись: 6-битный отсчёт, затем адрес +1 |
| E65F | Чтение: версия 05h; запись: bit 0 включает readback E65E, bit 1 увеличивает адрес на 1 |

Перед командой нужно дождаться BUSY=0, записать параметры, затем E651.
После завершения проверяется ERROR. Пока BUSY=1, параметры и новая команда
игнорируются; E650 можно менять всегда. ERROR относится к последней команде;
UNDERRUN сохраняется до выключения расширения или Reset.

Порт палитры работает независимо от BUSY блиттера, на 24 МГц. Адрес
`index*32+phase` занимает 13 бит, увеличивается по модулю 8192. Его запись
не меняет front page. Чтение EBR синхронное; перед чтением E65E после
изменения адреса требуется один такт 24 МГц, что укладывается в обычное
байтовое обращение CPU даже на 8 МГц. Для readback записать E65F=1;
после каждого чтения записать E65F=3. E65F=0 возвращает идентификатор `G`.
Перед заменой таблицы выключить E650, чтобы избежать видимой частичной
палитры. Нулевая запись E650 не сбрасывает цвета. CPU Reset выключает
расширение и сбрасывает адрес/readback, но сохраняет таблицу; штатный
экран, чёрные поля, sync и burst от неё не зависят.

VIEW использует исходные RGB888 PCX и вычисляет отсчёты на HD6303:
три MUL на фазу, signed Q9 и один 16-битный аккумулятор. Прежняя таблица
сохраняется в 8 КиБ BSS и восстанавливается при ESC либо ошибке, поэтому
следующий GFX снова получает прежнюю палитру. FPGA-умножители и новые
EBR не добавлены: прежние шесть ROM стали двухпортовой RAM.

FILL/COPY/TRANSPARENT COPY используют шаг строки 320 байт и проверяют, что последний
затронутый байт меньше 64000. Координаты задаются линейным смещением;
условие `x+width<=320` проверяет вызывающая программа. COPY допускает
перекрывающиеся области одной страницы и выбирает безопасное направление.
TRANSPARENT COPY использует те же параметры и направление: исходный
индекс, равный E653, пропускается без чтения или записи назначения.
Сравнение ключа регистрируется отдельно от счётчиков и продвижения
указателей, чтобы сохранить 96 МГц. Цветовой ключ может быть любым 00–FF;
команда 2 копирует все индексы независимо от E653. Версия 2 содержит порт
палитры, версия 3 добавляет команду 6; текущий VIEW принимает все версии начиная с 2.
WRITE/READ BYTE используют только смещение и страницу назначения/источника,
игнорируют ширину/высоту. FLIP завершается на следующей границе PAL-поля;
менять отображаемую страницу посреди поля он не позволяет.
Команды асинхронны: CPU может выполнять полезную работу вместо ожидания.

## Доступ к SRAM

Контроллер сохраняет прежние шеститактовые слоты на 96 МГц и приоритет CPU.
Графика занимает свободные слоты после boot-порта и штатного видео;
HOLD не используется. Внутри графики загрузка видеостроки имеет приоритет
над блиттером. Строка читается 160 словами по 16 бит в двухбанковый EBR-кэш;
на выводе SRAM адрес/направление/данные регистрируются до принятия запроса.
Принятое физическое обращение завершается и при Reset.
Заливка пишет байты, копирование читает/пишет байты; фон CPU и электронный
диск обслуживаются прежними путями.

Для размещения расширения сокращена логика без изменения внешних интерфейсов:
таблицы PS/2 перенесены в две EBR, умножение stride видеостроки и CHS capacity
заменено последовательным сложением, ROM-bank адреса — таблицей конкатенаций.
Boot-заголовок проверяется при приёме байтов, сохраняя только нужные поля.

## Сборка и проверки

```sh
make gfx-apps UNIAS=/Users/sash/Work/FPGA/hd6303-toolchain/unias
make test-gfx
make test-gfx-app UNIAS=/Users/sash/Work/FPGA/hd6303-toolchain/unias
make test-view UNIAS=/Users/sash/Work/FPGA/hd6303-toolchain/unias
make test-ham UNIAS=/Users/sash/Work/FPGA/hd6303-toolchain/unias
make test-sprites UNIAS=/Users/sash/Work/FPGA/hd6303-toolchain/unias
make test-rtl test-python test-turbo test-memory-bus test-keyboard-bios
```

`tb_gfx` проверяет 512000 пикселей обоих PAL-полей на четырёх частотах,
одновременные чтения/записи CPU, заливку целого кадра и видео, byte lanes,
перекрывающиеся COPY, границы, VBL flip и завершение SRAM при warm reset.
Прозрачный COPY проверяется по снимку исходной/целевой страницы: ключи
00/FF и промежуточные индексы, odd/even lanes, оба направления перекрытия,
сдвиг на строку, одинаковые смещения, полностью прозрачный кадр, точное
число физических записей, границы и одновременные CPU/video/DMA.
`test_sprites_unidos.c` запускает реальный PGM через оригинальные BIOS и
UniDOS для обеих моделей: два запуска по 400 полных кадров, независимый
эталон наложения/фона/движения, четыре границы, ESC, повторный запуск,
MC6800/старый FPGA, ошибка команды и последующий DIR.
`run_sprites_app.py` исполняет тот же PGM на производственном VHDL HD6303,
контроллере SRAM с задержками и графическом RTL. Проверяются все пиксели
восьми кадров, обе истории страниц, пересечение, скрытая страница и ESC.
Все восемь сочетаний 601/601A × 1/2/4/8 МГц прошли SPRITES: по 313
команд, 512000 пикселей и восемь VBL-переключений. Финальный RTL-прогон
проверил 32 keyed COPY и 281840 пикселей плюс 512000 пикселей растра.
Прежний GFX.PGM на MC6800 проверен отдельно для обеих моделей на 8 МГц.
VIEW прошёл native UniDOS обеих моделей с версиями устройства 2/3,
прежними проверками PCX/палитры/ошибок. Сводка: `build/sprites/validation.json`.
`tb_pal_rgb332` сравнивает все 256 цветов при обеих полярностях V с независимой
непрерывной YUV-моделью: 131493 отсчёта, максимальная ошибка 2,434 DAC-кода
в пределах округления и квантования фазы.
При сборке Diamond `check_pal_ebr.py` дополнительно сверяет настоящие
INITVAL синтезированных EBR. На Лене обнаружено обращение адресного порядка
RGB332-ROM в Synplify; исправлены направление массива и явный диапазон
readmemh. Проверены все 8192 отсчёта через модели Lattice SP8KC/DP8KC.
Для программируемой версии также проверены адреса/данные обоих портов
настоящего EDIF и запись/readback всех 8192 адресов в моделях Lattice.
`tb_pal_palette` проверяет полный порт CPU, маски, wrap, сохранение при
Reset и 65918 отсчётов DAC всех индексов при обоих знаках V.
[Причина, исправление и проверка цвета](PCX-VIEWER.md).
`tb_boot_header` проверяет 5817 заголовков, включая все легальные CHS-геометрии,
ошибочные фиксированные байты, CRC, границы MBR и переполнение.
Тест PGM исполняет настоящий перемещённый бинарник на HDL MC6800 с
производственным SRAM/GFX; минимальный SWI-обработчик подаёт SPACE/ESC.
Это проверка CPU/PGM/регистров, а не полная загрузка UniDOS в mixed HDL.
Все восемь сочетаний 601/601A и 1/2/4/8 МГц прошли тест PGM:
263 команды, проверка 64000 пикселей на каждой из двух страниц,
три переключения по VBL и возврат по ESC.
Штатные пиксельные регрессии 601/601A и быстрый ввод через оригинальный BIOS
проходят; runtime CPU и его набор команд не менялись.

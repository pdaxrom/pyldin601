# Пълдин-601/601A для Z-pdaXrom-TV / hardware-lcd

Проект классического Пълдина с выбором MC6800/HD6303 ISA: внешняя SRAM 2 МиБ, цветной
PAL TV, PS/2 и SD. Электронный диск 512 КиБ восстановлен после исправления
CPU. Рабочая директория — этот проект.
Старый прототип сохранён в `audit/previous-prototype` только для аудита.

Для записи карты без сборки используй [`images/sd.img`](images/sd.img):
текущие ROM 601/601A, загрузчик, UniDOS на A и тесты HD6303, HG/HGTIME и GFX.PGM на B.
[Контрольная сумма и инструкция записи](images/README.md).

Добавлено независимое графическое расширение **320×200, 256 цветов RGB332**:
две страницы кадра, переключение по PAL VBL, аппаратная заливка и копирование
прямоугольников. Демо `B:GFX`: SPACE переключает страницы, ESC возвращает
UniDOS. Расширение выключено после Reset; штатные режимы 601/601A сохраняются.
CPU работает на прежних 1/2/4/8 МГц без HOLD.
[Память, регистры, сборка и проверки](audit/GRAPHICS.md).

При включении первичный BIOS работает на HD6303 ISA на 4 МГц, независимо
от выбранного рабочего CPU. Он читает P601.SET с первого раздела SD и
показывает модель, HD6303 EXTENSION и частоту с обратным отсчётом 10 секунд.
DEL открывает BIOS Setup; без ввода запускается сохранённая конфигурация.
Перед первым CMD0 BIOS ждёт не менее 300 мс и повторяет команды при
временном отсутствии ответа; инициализация SD ограничена таймаутами.
Без файла или при неверной конфигурации меню открывается сразу с настройками
601, HD6303 EXTENSION N, 1 МГц. Стрелки выбирают/меняют значения, Enter
подтверждает. SAVE AND BOOT сохраняет и проверяет настройки, BOOT WITHOUT
SAVE применяет их на текущий запуск, EXIT AND BOOT отменяет изменения.
Модель и рабочая ISA применяются до загрузки ROM; после lock CPU получает
выбранный набор команд. BIOS занимает 8 КиБ EBR в F000–FFFF и D000–DFFF;
окно D000 действует только до lock. [Меню, формат и запись](audit/BIOS-SETUP.md).
[Команды HD6303 и границы реализации](audit/HD6303.md).
Этот BIOS через SPI E660–E664 инициализирует SDHC/SDSC, читает MBR и FAT16
первого раздела, загружает LOADER.BIN в RAM с 2000h. Загрузчик тем же CPU
читает P601.ROM или P601A.ROM согласно модели, проверяет CRC32 заголовка и содержимого, размещает ROM в
SRAM и очищает базовую RAM. Передача управления идёт через
повторную проверку CRC32 чтением ПЗУ обратно из SRAM, затем через
RAM-трамплин E000: commit закрывает запись ROM, затем CPU читает штатный
reset vector и запускает соответствующий оригинальный BIOS. Аппаратного FAT-загрузчика нет.
Удержание Reset около двух секунд сохраняет ROM/lock и электронный диск,
без чтения ПЗУ с SD, возвращая частоту, выбранную в BIOS для этого запуска.
Удержание 10 секунд запускает первичный BIOS заново после завершения
принятых SRAM/SPI обращений; питание переключать не нужно. После отпускания
кнопки снова читаются настройки и загружаются ROM, электронный диск очищается.
Короткое нажатие при отпускании переключает CPU 1 → 2 → 4 → 8 → 1 МГц.
Индикатор показывает 01/02/04/08, при bootstrap — 04.
[Тайминги SRAM, ресурсы и проверки](audit/TURBO-SRAM.md).

До первого обращения к SD первичный BIOS включает текстовый экран 601
40×24 через регистры MC6845. После применения настроек он включает
экран выбранной модели: 40×24 для 601 или 40×12 с атрибутами для 601A.
Существующий font EBR при конфигурации FPGA уже
содержит штатный шрифт `native/Bios/video.roz` из `rtl/font_boot.mem`;
дополнительной памяти для него нет. Затем загрузчик заменяет его шрифтом
из выбранного комплекта через те же SRAM/font writes, что использовались раньше.
На экране выводятся этапы SD, MBR/FAT16, LOADER.BIN, P601.ROM, проверки
заголовка/CRC, загрузки ROM/BIOS/font, очистки RAM и handoff.
При загрузке банков виден счётчик блоков; при ошибке
сохраняется название этапа, выводится его код и подсказка о reset.
Экран занимает обычную RAM 0400–07BF и очищается перед запуском BIOS.
Название этапа 0A на экране — `INITIALIZING ROM DISK`. Электронный диск
512 КиБ занимает SRAM 80000–FFFFF. E680–E682 задают адрес, E683 читает
или записывает байт и увеличивает адрес один раз на CPU I/O-цикле; запрос SRAM уже сохраняет прежний адрес.
При cold boot loader очищает эту область; кнопочный reset сохраняет данные.
LOADER.BIN на физической SD содержит эту инициализацию и выбор комплекта ROM.
Этап 0C — `VERIFYING SRAM CRC32`; при повреждении сохранённого ПЗУ
запуск классического BIOS запрещается. Выбор 601A требует обновлённого loader и отдельного P601A.ROM.

Ранее наблюдались повреждение текста после простоя и сбои DIR. Проверка
MC6800 выявила ошибки CLR/CCR и выбора вектора IRQ/SWI: IRQ мог перенаправить
уже выполняющийся SWI на свой обработчик. Исправлены фиксация причины
прерывания, маскирование и reset/WAI. Production CPU совпал с эмулятором
на 500000 последовательных инструкций native BIOS и итоговой RAM;
пройдены 24 проверки входа прерываний. Подробности и ограничения эталона —
в [audit/CPU-CONFORMANCE.md](audit/CPU-CONFORMANCE.md).

На плате пользователь подтвердил целый баннер, повторные DIR без сбоев,
а после восстановления электронного диска — его нормальную работу.
Аппаратная отладка удалена из RTL и проекта Diamond: UART-трасса,
контрольная EBR-копия BIOS, команды остановки CPU и диагностические
регистры. TX второго канала FTDI удерживается в idle; RX не управляет CPU.
Исходники прежней отладки и журналы сохранены в build только как история.
Экранный статус загрузки и CRC32 ПЗУ остаются частью штатного bootstrap.

После старта и кнопочного reset включена латиница. Обе клавиши Windows
передают штатный код FB (Кир/Лат); переключением управляет UniBIOS.
Caps Lock передаёт штатный код FC. RGB показывает состояния BIOS:
красный — Caps Lock включён, зелёный — кириллица, синий выключен.
Исходник таблицы PS/2 — [firmware/ps2_set2.csv](firmware/ps2_set2.csv):
байт Set 2, индекс PC Set 1 и название клавиши. `tools/make_ps2.py`
генерирует `rtl/ps2_set2.mem` при `make firmware`; неперечисленные байты
получают FF. E0/F0/E1, модификаторы и обе Windows-клавиши обрабатывает RTL;
Scroll Lock не выдаёт код Кир/Лат.
Быстрые нажатия сохраняются в очереди и выдаются с учётом штатной
защиты BIOS от дребезга и повторного нажатия одной клавиши. Интервал
считается по подтверждённым 50-Гц тикам, независимо от частоты CPU;
в первичном BIOS задержка отключена. [Протокол и проверка](audit/KEYBOARD.md).
Чтение E629 возвращает сохранённый регистр режима, поэтому изменение
видеорежима сохраняет раскладку. Курсор приведён к оригинальному эмулятору:
в 601 текстовая позиция R14:R15−2, графическая R14:R15−1. В 601A
используется прямой адрес символа, включая нечётный байт цветной пары.
Проверки и источники — в [audit/IO-FIXES.md](audit/IO-FIXES.md).

Звук управляется битом 3 регистра E62B. Один и тот же однобитный сигнал
подаётся на оба аудиоканала: audio[0] — правый, вывод FPGA 21;
audio[1] — левый, вывод 22. Пользователь подтвердил звук на плате;
без внешнего усилителя он тихий. Для нормальной громкости используются
усилитель или активные колонки. [Аппаратная проверка](audit/HARDWARE.md).

Цветная графика классической 601: 80×200 в 16 цветах IRGB и 160×200
в четырёх цветах, все четыре палитры E629. Текст и 320×200 остаются
монохромными. PAL-кодировщик на 24 МГц использует один дополнительный EBR;
частоты PAL и периферии остаются 24 МГц. Совместимость сверена со
штатными BIOS/XBIOS; пользователь подтвердил работу цвета на плате.
Подробности — в [audit/COLOUR.md](audit/COLOUR.md).

601A дополнительно поддерживает текст 80 колонок, цветной текст 40 колонок
с атрибутами/миганием и графику 160×200×16, 320×200×4, 640×200×2.
Для этой модели используется оригинальный `../native-src/BIOS_A.ROM`.
На плате подтверждены запуск 601A, нормальный текст и работа DIR.
Выбор модели, формат ROM, EBR и проверки — в [audit/MODELS.md](audit/MODELS.md).

SRAM обслуживает один контроллер на 96 МГц, используя фиксированные
слоты по 62,5 нс: обращение CPU, затем свободные слоты для boot-порта,
штатного видео и графического расширения. Даже на 8 МГц между CPU-циклами помещается видеочтение; HOLD
не используется, включая bootstrap. Адрес, данные и byte lane сохраняются
до завершения обращения, результат CPU удерживается отдельно от видео.
Переключение частоты выполняется после falling edge CPU и завершения SRAM;
PAL, таймер, клавиатура и SD сохраняют частоту 24 МГц.
Видео загружает строку в EBR-кэш: 601 во время гашения, 601A — в другой банк
во время предыдущей строки. Обе модели проверены на 1/2/4/8 МГц с непрерывными
чтениями/записями CPU: 17920/35840 видеочтений и 448 готовых строк на частоту.
Архитектура и бюджет для установленной SRAM-10 описаны в
[audit/TURBO-SRAM.md](audit/TURBO-SRAM.md).
Аппаратный i8272 обращается к SD через секторный буфер 512 байт в EBR.
DMA SD→основная SRAM нет: BIOS читает E6D1 и сам записывает байты в RAM.
Первичный BIOS и рабочая копия шрифта также используют EBR; основная RAM,
все ROM-страницы и классический BIOS находятся в SRAM.

| Физический диапазон SRAM | Назначение |
|---|---|
| 00000–0FFFF | Базовая RAM 64 КиБ |
| 10000–5FFFF | Пять ROM-банков по 64 КиБ |
| 60000–60FFF | Выбранный BIOS 601/601A, 4 КиБ |
| 61000–617FF | Текстовый шрифт 2 КиБ |
| 61800–7FFFF | Свободно, 122 КиБ |
| 80000–FFFFF | Электронный диск 512 КиБ, E680–E683 |
| 100000–1FFFFF | Графика: 16 страниц по 64 КиБ, E650–E65F |

ROM-комплектация берётся из `../native/Bios` и `../native/RAMROMDiskPipnet`.
Банки меньшего размера зеркалируются до 64 КиБ. Файлы ROM на SD собраны
в P601.ROM и P601A.ROM; P601.CFG — информационный JSON, CPU его не читает.
P601.SET хранит модель, расширение ISA и частоту для первичного BIOS.
Подробные адреса — в [SD-registers.md](SD-registers.md).

SD образ: раздел 1 FAT16 16 МиБ (LOADER.BIN, P601.ROM, P601A.ROM, P601.CFG, P601.SET), разделы
2/3 содержат сырые FAT12-образы дисков A/B. Поддерживаемая первая версия
использует интерфейс i8272, 512-байтовые секторы, 80 дорожек, две стороны,
до 18 секторов на дорожке (1,44 МиБ). `--boot B` меняет местами физические
образы для логических A/B: штатный BIOS по-прежнему загружает логический A.
LBA-контроллер и работа ОС с 12 МиБ отложены. `--allow-large` у генератора
проверяет лишь формат образа, такой образ не поддерживается этим RTL.
Первичный раздел сейчас только FAT16; это зафиксированный загрузочный профиль.
Разметка, подготовка нового образа, обновление загрузчика и пояснение,
почему Linux `blkid` может не показывать диск A, — в [SD-card.md](SD-card.md).

HG.PGM подключает FAT12-диск хоста через канал A FT2232 по протоколу
uJ11 HG, без DMA и запросов к общей SRAM. По умолчанию — 32736 секторов,
8 секторов в кластере, 4084 кластера FAT12; первая свободная буква обычно E:.
Драйвер синхронизирует дату/время с хостом, HGTIME.PGM обновляет их отдельно.
Программы находятся на B готового образа и работают с MC6800/HD6303 ISA.
[Запуск демона, FTDI/JTAG и формат FAT12](host/hg/README.md).

## Сборка и проверки

Нужны Python 3, C-компилятор, Icarus Verilog и NVC 1.23 или новее с mixed HDL.
Из этой директории:

```
make test
make test-setup
make test-setup-hdl
make test-handoff-fast
make test-stage1
make test-stage1-a
make test-stage1-hd
python3 tests/run_boot_modes.py
make test-system
make test-sram-diagnostic
make test-native-stability
make test-runtime-irq STABILITY_IMAGE=build/sd-text.img
make test-memory-bus
make test-turbo
make test-runtime-turbo
make image
```

`make test` проверяет генератор/ассемблер, Verilog-устройства, настоящее
VHDL-ядро CPU против MC6800/HD6303 режимов C-эмулятора и исполняемые прошивки на
байтовой SPI-модели карты (SDHC, SDSC, фрагментация, повреждения, warm reset).
Отдельно выполняются штатный BIOS с оригинальной моделью клавиатуры и
сравнение 768000 пикселей PAL в обоих полях с оригинальным MC6845 renderer,
включая перенос адреса экранной памяти и курсор после переноса. Дополнительно
проверяются все символы шрифта и подчёркивание в обоих полях, навигация
во всех сочетаниях кир/лат, Shift/Ctrl, Windows и отсутствие события Scroll Lock.
Для 601A сравниваются все пять видеорежимов, четыре палитры, текстовые
атрибуты и мигание с исполнением оригинальных BIOS_A/XBIOS. Проверка
`make test-stage1-a` выбирает 601A через реальные PS/2-фреймы и загружает
LOADER.BIN на настоящем HDL CPU. Короткий mixed HDL тест дополнительно
проверяет CPU commit/handoff/warm reset
с заранее заполненной SRAM; он не заменяет полный ROM-boot тест.
`make test-runtime-irq` восстанавливает настоящую DOS на вводе времени
и сравнивает двадцать штатных PAL IRQ VHDL-ядра/BIOS с эмулятором, включая
переход через 02:00:00 и сохранность старого заголовка. SD/FDD в этом
коротком тесте не участвуют.
`make test-turbo` проверяет задержки SRAM, смену частоты, Reset и сроки
видеочтений обеих моделей на 1/2/4/8 МГц. `make test-runtime-turbo`
повторяет сверку настоящего CPU/BIOS с эталоном на каждой из этих частот.
PLL синтаксически проверяется с заглушками примитивов, их тайминги не моделируются.
`make test-system` — существенно более долгая смешанная симуляция CPU,
SRAM, SPI и всей системы; PLL заменён входной границей системного clock.
`make image` создаёт `build/sd.img` с `../native/Floppy/system.imz` на A
и пустым B. Генератор отказывается перезаписывать существующий образ.
Это создаёт файл образа, запись физической SD-карты не выполняется.
При создании нового образа используются текущий LOADER.BIN и оба комплекта
ROM, если доступен `../native-src/BIOS_A.ROM`. Старые файлы в `build`, включая
`sd-text.img` и ранее созданный `sd.img`, не обновляются автоматически.
Для обновления существующей карты с сохранением A/B см. [SD-card.md](SD-card.md).

Для Diamond добавлены LDF/LPF и VHDL board top `pyldin601_classic`.
Используется LCMXO2-7000HC-4TG144I по схеме hardware-lcd,
кварц 12 МГц → system 24 МГц и SRAM 96 МГц; CPU 4 МГц при загрузке,
выбранные 1/2/4/8 МГц после commit.
На Linux-машине выполнена сборка Diamond 3.14: synthesis, MAP, PAR, TRACE,
Jedecgen. Текущая сборка с HG и RGB332 занимает 6529/6864 LUT,
3274/3432 slices, 2367/7209 registers, 25/26 EBR и 1/2 PLL.
Свободны 335 LUT, 158 slices, 4842 registers и 1 EBR.
Распределение EBR: bootstrap 8, шрифт 2, SD/FDD 2, PAL waveform 1,
штатный кэш строк 1, HG RX/TX FIFO 2, RGB332 waveform 6,
графический кэш строк 1, таблицы клавиатуры 2.
Setup/hold проходят, unconstrained paths = 0; полный отчёт и проверки
зафиксированы в [audit/GRAPHICS.md](audit/GRAPHICS.md). LPF ограничивает
внешние SRAM/SD пути и отдельно проверяет SRAM→CPU за 27 нс.
Результаты и допущения STA — в [audit/DIAMOND.md](audit/DIAMOND.md).
Графическая сборка от 9 октября прошла Diamond и симуляции, записана
во FLASH с Verify и подтверждена пользователем на плате.
GFX.PGM также предоставлен на диске HG.
История записи и физические подтверждения — в [audit/RELEASE.md](audit/RELEASE.md).
Проверка быстрого ввода на 601/601A при 1/2/4/8 МГц — PASS;
8 октября 2026 года пользователь подтвердил быстрый набор на плате
без пропусков. [Протокол](audit/KEYBOARD.md).
Новый PAL tick имеет приоритет над очисткой E62B: совпавшее чтение
не стирает событие. Проверка — `tb_timer_tick`, включая полный Reset.
Пользователь подтвердил полный Reset и загрузку на плате 4 октября 2026 года.
Первоначальное обновление SD boot-раздела с сохранением MBR и текущих A/B
зафиксировано в `build/hardware-bios-setup`.
Предыдущая записанная сборка 601/601A с цветным PAL, выбором CPU и частотами 1/2/4/8 МГц:
`build/diamond/turbo-final/impl1/pyldin601_classic_impl1.jed`.
Она записана во FLASH с успешным Verify и JTAGENB high до/после;
журналы — `build/hardware-turbo`. Новые частоты физически ещё не проверены
пользователем.
Восстановление электронного диска и его проверки — в
[audit/ELECTRONIC-DISK.md](audit/ELECTRONIC-DISK.md).
Перед программированием нужно сверить маркировку установленной FPGA и кварца.
Предыдущий JED hd-tests с выбором CPU и меню по 10 секунд записан во FLASH FPGA через FTDI с Verify;
JTAGENB подтверждён высоким до и после записи. Физическая проверка выбора
CPU пользователем ещё не выполнена. При предыдущем обновлении models-ebr

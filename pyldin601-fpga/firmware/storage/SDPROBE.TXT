SDPROBE - read-only SD SPI initialization diagnostic

1. Boot with the working SD card, in plain UniDOS (outside NC).
2. Start HG, then run E:\SDPROBE (use HG's actual drive letter).
3. At "Replace SD with test card; press ENTER", remove the working
   card from the FPGA slot and insert the test card. Press Enter.
4. Photograph the completed results. POWER OFF afterwards.

All program code is already in conventional RAM when the prompt appears.
No file, sector, write or erase commands are issued after Enter.
The program halts instead of returning to DOS with stale mounted volumes.

Profiles: 400k, 200k, 100k, 100k+.
The first three wait 16 PAL ticks and supply 80 initial clocks.
100k+ waits 64 PAL ticks and supplies 1280 initial clocks.
Each CMD0/CMD8/ACMD41 stage has a 101-tick retry deadline.

PH: 01 CMD0, 02 CMD8, 03 CMD55/ACMD41, 04 CMD58.
C0/C8/C55/C41/C58: R1 responses; FF = no reply or not reached.
R7 and OCR: raw four-byte replies, printed as eight hex digits.
E: 00 no local error, 01 SPI READY timeout, 02 PAL tick timeout,
   03 invalid CMD8 pattern/voltage, 04 unexpected response/OCR.
IO: last SPI control/status byte. Final CS is high.

A normal SDHC/SDXC result: PH=04 C0=01 C8=01, C41=00 C58=00,
R7=000001AA, OCR with its high bit set (usually C0FF8000).
SDSC may return C8=05; it is then initialized without HCS.

This checks initialization only, not filesystem or sector contents.

PYLDIN COMMANDER

Keep NC.PGM, NCMAIN.PGM and NCEDIT.PGM in the same directory.
Replace all three together when updating. Start NC, for example:
    B:NC

NC uses the current native BIOS video mode. Supported: 40/80-column text,
601 monochrome graphics (40 columns), 601A four-colour graphics (40), and
601A monochrome graphics (80). Narrow 10/20-column modes are rejected.
40-column colour text and four-colour graphics use an NC-style blue/cyan
palette; monochrome modes use a visible cursor marker. The original mode
and palette are restored around external commands and on final exit.
Frames use the native ROM box-drawing glyphs, including CF and D3 (the
Pyldin Cyrillic encoding differs from PC character sets).
Each panel has column headings and two selected-file information lines:
name with RHSA attributes (read-only, hidden, system, archive; '-' is clear),
then modification date, time and size. In 40 columns: DD.MM HH:MM and exact
bytes when they fit; large values use truncated KiB/MiB with K/M suffixes.
In 80 columns: DD.MM.YYYY HH:MM and the exact unsigned 32-bit byte count.
UniDOS does not maintain a separate creation timestamp for its own files.
Free space remains in the bottom frame. The 80-column file list also has
size/date columns. Text uses 26 NC rows, immediately followed by the BIOS
clock; graphics retains 25 rows and displays 16 file rows instead of 17.
The command prompt and function keys sit directly below the panels.
The input caret stays in the command prompt, or moves into a modal input
field while that dialog has focus. Long commands scroll horizontally to
keep the end visible. Menus, buttons, progress windows and the viewer hide
the input caret. Text uses the native hardware cursor; graphics draws its
caret in the active field. The original cursor shape is restored on exit.

With the FPGA PS/2 mouse port, click a row to select it, double-click to
open/run, or click the other panel, a drive heading, menu, dialog control
or function-key label. A graphics pointer is uploaded by NC; text uses the
existing CRTC cursor, and keyboard input restores the input-field caret.
The mouse is initialized by software and does not add a resident IRQ hook.

TOP MENUS AND WINDOWS
The top bar contains Left, File, Command, Options and Right. In a menu use
Left/Right to change groups, Up/Down or Tab to select, Enter to execute,
or the displayed item number. Esc/Ctrl+C closes the menu. Left/Right menus
choose a drive or reread the corresponding panel. Options opens Settings.

The drive window lists registered UniDOS drives and highlights the panel's
current drive. Up/Down, Left/Right or Tab moves selection; Home/End selects
the first/last drive. A drive letter highlights that entry. Enter confirms;
Esc/Ctrl+C cancels without changing either panel or the active panel.
Selecting the current drive preserves its directory and cursor. A different
drive opens its root and activates the requested panel. Listing drives does
not probe removable media; a media error on selection returns to the list.

Settings has four sort radio buttons (n/e/s/d: name/extension/size/date)
and a hidden-file checkbox (h). Work directory (w) chooses the editor's
scratch directory; empty uses the document's directory. The chosen directory
must already exist and leave room for a 12-byte work filename in a 63-byte
DOS path. Up/Down/Tab moves focus; Space selects or toggles. Enter on Work
opens its input window. Apply/Enter on other controls commits staged changes;
Cancel/Esc discards them. Settings survive external programs, F4, and EXIT
from the nested shell for the current NC session.

Input dialogs support insertion, Left/Right, Home/End, Backspace, Delete
and horizontal scrolling. Tab moves between input, OK and Cancel. Enter
accepts input or activates the focused button; Esc/Ctrl+C cancels.
Confirmation windows start on No: Y/N answers directly, Left/Right/Tab
changes the selected button, Enter activates it. Help/errors use an OK
window, closed with Enter/Esc/Ctrl+C.

F5/F6 ask for a destination directory or filename. Default: other panel.
Directories are copied/deleted recursively. Copy uses a temporary in the destination
directory and retains the previous destination under a backup name until
the completed file has been published. The progress window shows source,
destination and actual bytes written / file size with a 32-bit progress
bar. Directory traversal and deletion show activity and completed objects,
without an estimated total. Esc/Ctrl+C aborts before the next 512-byte block.
Same-volume file moves use UniDOS RENAME; cross-volume moves copy first.

TEXT EDITOR
For PCX/IFF/LBM, F3 and Enter start PAINT /V (read-only); F4 starts PAINT
for editing. Keep PAINT.PGM, PNTNAT.PGM, PNTRGB.PGM and PNTHAM.PGM beside
NC.PGM. Both CPU types work. The selected panel directory becomes the
application's CWD, and the image basename is passed as its argument.
Paint's Esc/F10 returns to the same directory and selected filename.
The image viewer supports F3 Open, Z zoom, G grid, I/J/K/L pan, F9 Menu.
It disables drawing, Save, New, Cut/Paste and Undo/Redo. Other file types
retain the built-in text viewer/editor and ordinary executable launch.

F4 on a text file unloads the panels and loads NCEDIT. Esc/F10 returns to the same panel
and selected file, even if saving changes its position in the sorted list.
The editor keeps the current video mode, native font and colour scheme.
Its header shows the filename, '*' for unsaved changes, INS/OVR and the
one-based visual column. The caret stays in the document or active dialog.

Click text to position the caret; drag with the left button to select a
byte range, including tabs and line breaks. Ctrl+C/X/V uses that selection.
Right-click cancels a long scan; a progress window also accepts a click on
its Cancel row. The mouse is released before another program or shell runs.

    F7                  Search forward; wraps once at the document end

Long lines scroll horizontally without inserting line breaks. Offsets,
sizes and columns are 32-bit. Text uses native 8-bit Pyldin characters;
UTF-8 conversion and syntax highlighting are not included.
Search matches bytes and case. Existing tabs, CRLF/LF/CR, NUL and 1A bytes
are preserved; new lines use the first detected convention (CRLF if empty).
Control bytes are displayed as dots. Delete/Backspace treats CRLF as a pair.

F8 asks for the search and replacement text. Shift+F8 starts at the document
beginning and asks for confirmation. Inserted bytes are skipped, so replacing
"a" with "aa" terminates. An empty replacement deletes matches. Each match
is one Undo record. Esc cancels a long search/replacement; matches already
changed remain undoable. Patterns/replacements are literal native text,
up to 79 bytes; regular expressions and UTF-8 conversion are not included.

F3 starts marking at the caret; ordinary navigation extends the range, and
F3 again freezes it. On the FPGA PS/2 keyboard, Shift+arrows/Home/End/pages
also selects text; Ctrl+Shift+Home/End reaches document boundaries. Ordinary
navigation clears a frozen/Shift selection. Typing, Enter, Tab, Delete and
Backspace replace the selected range as one Undo action. Colour and graphics
modes highlight selected cells. Native monochrome text has no cell colours,
so brackets mark the range endpoints; '*' marks a single selected cell.
These display markers do not change file data.

The clipboard is a unique NCE000hh.CLP disk file in Work (or the document's
parent). It survives closing F4, so Copy in one file and Paste in another
works throughout the current NC session. NC deletes its clipboard on final
F10 exit. A failed/cancelled Copy keeps the previous clipboard. Paste stages
all incoming bytes before changing the document. Large Copy/Paste/replacement
operations show byte progress and accept Esc. Cut, Paste and replacement
are each one Undo record, regardless of block size. Native tabs, line endings
and control bytes are copied exactly.

Opening only reads the original; it creates no work files. The first edit
creates unique NCE000hh.IDX, .ADD and .UND files in the work directory.
The original remains read-only while edits update disk-backed pieces and
Undo/Redo records. RAM use does not grow with document length or edit count.
The dead loader supplies a 512-byte disk cache and one 80-byte display row.
The remaining display cache uses 6K of private GPU SRAM through flat DMA.
One RAMMAN 8K bank adds sixteen disk-cache blocks when available. Without
RAMMAN, its unused BIOS bounce buffer supplies a second ordinary block.
Another ordinary block is allocated when conventional memory permits.
Continuous local typing uses the cache. Cold jumps and searches scan from
a known position; large files and saving remain limited by native DOS I/O.
Esc cancels long scans and saving before publication.

Save writes a unique .NEW beside the target, closes it, then renames the
old target to a unique .BAK and publishes the completed new file. The
progress window shows actual bytes written and total bytes. A failed write
keeps the original and the editing state; retry F2 or use Save As. Undo/Redo
remains available after Save. The latest previous version is kept as .BAK;
normal exit deletes the editor's IDX/ADD/UND work files. Keep the work disk
mounted while editing.

RECOVERY
F9 streams a checkpoint to the work directory (or document directory).
After a minute without changes, the idle loop starts the same operation.
The original is untouched. Up to four NCR0hhhh.RC0/.RC1/.RC2/.RC3 files
rotate; the newest completed copy and the open backing are protected.
The final trailer verifies the full pathname, size, cursor and two CRC16s.
Unknown files are preserved. Esc cancels before completing the checkpoint.
Disk-full/I/O errors preserve edits and stop automatic retries; a successful
manual F9 enables them again. A checkpoint needs room for the whole document.

After a reset, reopen the same file with F4. NCEDIT validates the latest
copy and asks Restore; a damaged last copy falls back to an earlier one.
No/Esc opens the original and retains the copies. Yes restores the text
and cursor as unsaved changes with a new Undo history. F2 publishes it.
Only edits in the last complete checkpoint can be restored. Save/Discard
and normal exit clean up owned copies; crashed IDX/ADD/UND files can be
removed after successful recovery. Damaged FAT/storage is not repaired.

For read-only sources, set Work in Settings to a writable directory before
F4, then use Save As to a writable target. With the default work directory,
read-only files can be viewed but the first edit reports a disk error.
Save As can copy an unmodified document to a writable disk as well.

MEMORY AND LIMITS
Only the small NC.PGM supervisor remains during EXEC or the nested shell.
For F4, NCMAIN releases its memory and the supervisor loads NCEDIT instead.
The editor and its small streamed-relocation loader use about 26K of ordinary
RAM, plus the optional 8K leased cache; the supervisor uses about 1.2K.
NCMAIN terminates, closes its handles and releases its optional RAM bank.
Return reloads NCMAIN from its original absolute pathname, rereads both
directories, and restores paths, catalogue windows, cursors and active panel.

RAMMAN is optional. NC checks the vector and allocation result. One leased
8K bank holds two directly accessed catalogues of up to 159 files each.
Without RAMMAN or free banks, the same functions use a shared ordinary-RAM
cache and reread the
other catalogue when needed. No physical bank number is assumed free.

Within a cached window, cursor movement and marking perform no disk reads,
catalogue scans or RAMMAN cache transfers. Selection updates the markers,
colours/pixels and two information lines. Graphics scrolling shifts existing
panel pixels and draws the newly exposed row.
Text scrolling rebuilds just the active panel: native text VRAM lies under
the BIOS ROM read overlay. RAMMAN panel switches need no catalogue copies.

The ordinary-RAM fallback holds 45 files; the RAMMAN cache holds 159 per
panel. Larger directories use overlapping sorted windows. At a boundary,
arrows still select the adjacent file and scroll exactly one row, preserving
the visible neighbours. The '..' parent appears only at the directory start.
Catalogue insertion uses binary search. Refills still enumerate the directory
through UniDOS; their delay depends on directory size and storage speed.
Unmark the current window before crossing a catalogue boundary.
Marked groups are local to that window and
are cleared after operations, sorting, reread, or an external command.
Paths are limited to 63 bytes by the DOS interface; recursion to 24 levels.
The viewer streams files using 32-bit offsets, retaining 64 previous screen
positions. Home always returns to the start, even after a longer file.
F2 in the panels does not yet load a configurable user-menu file.

BUILD AND TEST (from pyldin601-fpga)
    make nc-apps UNIAS=/path/to/unias
    make test-nc UNIAS=/path/to/unias
    make test-nc-editor UNIAS=/path/to/unias

NCMAIN and NCEDIT are linked from separate OBJ modules. Shared display
and dialog routines are in NCUI.LIB, built by UniAR. NCMAIN.LNK and
NCEDIT.LNK list the input modules; NCBUILD.TXT contains every command
for the same build on a host or native UniDOS. No enlarged host symbol
pool or PGM BSS trimming is needed. Use HANDLES 16 before RAMLOAD /CVM.
NCEDIT's two standard PGM streams are joined with UniLD -b.
    make test-native-firmware CVM_TOOLCHAIN=/path/to/hd6303-toolchain
compares native objects, library, PGMs and maps with the cross build.

Outputs: build/nc/NC.PGM, NCMAIN.PGM, NCEDIT.PGM, NCHOW.TXT, listings
and manifests. NCEDIT.PGM includes its loader; NCEDIT.core.PGM is a build
artifact used by tests, not an additional file to install.
test-nc also builds build/nc/sd-nc.img with NC installed on B: while
preserving the other files and partitions of images/sd.img. Boot this
image and enter B:NC. The original images/sd.img is not modified.
Tests use disposable SD images and actual BIOS/UniDOS/relocatable PGM files
in the project's CPU reference harness. They do not write a physical card.
Framebuffer PNGs include the panels, menus, dialogs, confirmations,
settings, editor and in-progress copying/saving. These are digital references, not
composite PAL simulations.
Navigation tests count CPU cycles and disk/cache accesses, and compare
incremental screen output with a complete render byte-for-byte.
Editor tests include all supported model/video/CPU combinations, missing
or occupied RAMMAN, a document over 2 MiB, a line over 64 KiB, fragmented
edits, exact byte comparisons, Undo/Redo, tab columns, native Cyrillic,
read-only and full disks, injected read/write faults, cancellation,
selection across lines/tabs, a disk clipboard over 2 MiB across F4, failed
editor loading, panel return, and released heap/stack/bank leases.
